## Context

dafung-web 当前地图(30 城主环 + 5 捷径)硬编码在 `src/core/boards-data.ts`(RAW 数组 + `buildShortcuts`),渲染与规则通过 `createBoard(tiles, shortcuts)` 消费。主路相邻 = tiles 数组顺序(闭合环),捷径 = `branchNode→rejoinNode` 跳跃边。路线视觉:`edgeWaypoints`(主路,固定法向量偏移,**不避城**)+ `sideArc`(捷径,选离其他城更远的弧线,**避城**)。改任何地图内容都要改 TS 并重建;玩家无法自定义。

## Goals / Non-Goals

**Goals:**
- 地图数据 100% JSON 驱动(内置三国地图 + 玩家自定义同 schema)
- 加载强校验,坏 JSON 不崩、给可读错误
- 主路/捷径路线统一自动避城,可选手配 `waypoints` 精修
- 应用内可视化编辑器:城池位置/属性、主路顺序、捷径、路线控制点可编辑
- 导入/导出 JSON 用于分享;自定义地图持久化到 localStorage
- 分阶段交付,**阶段 0(数据层)独立可用、独立验证**

**Non-Goals:**
- 任意图拓扑(Catan 式任意分叉/交叉)——保持环+捷径模型
- 力导向 / 应力最小化等全局自动布局——避城算法 + 可选手配已足够
- Chance / Fate / 股票等事件格的编辑——这些游戏行为 v2.0 未实现,编辑器暂只支持 Property 格
- 撤销重做、在线地图市场、多人协作编辑——留待更后续

## Decisions

1. **JSON 为 single source of truth**:游戏运行时与编辑器读写同一份 JSON;编辑器本质是「可视化 JSON 编辑器」。复用数据类型 + SVG 渲染 + 校验,避免两套代码。
2. **环+捷径模型不变**:主路 = tiles 数组顺序闭合环;捷径 = branch→rejoin 弦。契合大富翁玩法,玩家路径决策清晰。不引入任意图。
3. **混合路线美化(核心决策)**:所有边默认跑「避城算法」(把 `sideArc` 的「两方向偏移取离其他城更远者」统一到主路 `edgeWaypoints`);边在 JSON 可带可选 `waypoints`,**有则用手配、无则自动**。不使用全局力导向(复杂、不可控、对本场景过重)。
4. **编辑器复用渲染层**:编辑器 = 带交互的棋盘 SVG(拖拽城池/控制点)+ 侧栏属性面板,复用 `createBoardSvg` 绘制逻辑,叠加编辑态事件。
5. **持久化分层**:内置 = 仓库 JSON 文件;玩家自定义 = localStorage;分享 = 导出/导入 JSON 文件。三者同一 schema。
6. **强校验早失败**:loader 校验 version / 环闭合 / 坐标重叠 / 数值合法性 / shortcut 端点有效;任一不过抛可读错误,UI 横幅提示,不进入对局。
7. **分阶段实现**(详见 tasks.md):阶段 0 数据层(独立价值)→ 阶段 1 编辑器 MVP → 阶段 2 路线/捷径精修 → 阶段 3 事件/撤销(可选)。

## Risks / Trade-offs

- [坏 JSON 让游戏崩] → loader 强校验 + try/catch,失败回退内置地图并提示
- [编辑器开发量大、易膨胀] → 严格分阶段;阶段 0 独立交付;MVP 只做城池位置/属性/主路,路线精修延后
- [手配 waypoints 增加玩家负担] → 默认全自动,手配是可选兜底;编辑器「双击边加控制点」便捷交互
- [JSON 版本不兼容] → 顶层 `version` + loader 版本检查 + 明确报错
- [现有 e2e/单测依赖硬编码地图] → 内置三国地图 JSON 内容与当前一致;loader 对 JSON 跑同一套校验,测试不动

## Migration Plan

- 阶段 0:抽 JSON + loader + 避城统一(对玩家行为不变,纯内部重构);e2e/单测保持绿
- 阶段 1+:编辑器/导入导出为纯增量,不影响现有对局
- 回滚:阶段 0 若出问题,`boards-data.ts` 在 git 历史可回退
