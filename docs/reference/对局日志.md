# 对局日志与诊断

对局日志按局记录局头、玩法、命令和终局。对局诊断把所选一局的日志、客户端现场和已采集的帧诊保存成一个 JSON 文件。

设计决议见 [`docs/adr/0014-game-log-system.md`](../adr/0014-game-log-system.md)。术语:**对局日志**(不用「战报」)、**局头**。

## 1. 行格式

每行一个 JSON 对象(`LogEvent`,定义在 `src/core/model.ts`):

| 字段             | 含义                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| `ts`             | 时间(epoch ms,引擎侧 `Date.now()`)                                           |
| `round` / `turn` | 轮(`engine.round`,所有人各行动一次)/ 回合(`engine.turnNumber`)               |
| `player`         | 玩家国号(无主行为为 `null`)                                                  |
| `brief`          | 中文自然语言(人类可读层)                                                     |
| `detail`         | 机读审计行(英文键值;`cmd`/`room`/`header`/`final` 四类为完整 JSON)           |
| `category`       | 分类(见下表)                                                                 |
| `amount`         | 仅现金收付(+收入 / -支出),可选;非现金资产(如得宝)估价走 `detail` 的 `value=` |

### category 分类表

| 类别     | category                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 写入点                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 局头     | `header`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 引擎构造时首行(gameId/mapId/seed/座位表/现金/目标/startedAt)                                     |
| 玩法事件 | `roll` 掷骰(点数/步数/加成)· `buy` 购地 · `upgrade` 扩军/成交升级 · `trade` 珍宝交涉(**买卖双向各记一行**:`treasureBuy` 买家付款 -实付 / `treasureFair`·`treasurePremium` 卖家成交 +实收,直付实付=成交价、破产为余现金扫账)+ escrow 交割/退回(资产交割,不挂 amount)· `supply` 补给 · `halt` 驻跸必停 · `setup` 开局流程(定序/**三候选生成**/选都/招贤)· `skill` 时机技能击发(37 时机)与名将主动技发动(`heroSkill`/`heroRelief`/`heroWarDrum`)· `system` 其余玩法杂项(商市城行情/跳过回合/破产清算/警告;#826 起旧 `tax` 类目随税关退役删除)· `victory` 胜负 | `src/core/authority.ts` 各结算点                                                                 |
| 终局行   | `final`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | 胜负判定 + GameOver 时机后:round/turnNumber/winner/玩家面板(cash/netWorth/position),归档终态锚点 |
| 命令类   | `cmd`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `submitCommand` 统一入口 + 人类 `pickCapital`(detail = 完整命令 JSON)                            |
| 房间类   | `room`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | 联机:`scripts/room.ts`(开局/托管/离线/解散);单机托管:`local.ts`(detail 机读 JSON)                |

## 2. 命令流(审计口径)

命令流记录**人类操作全量**,供对账与复盘:

- **人类命令**全走 `submitCommand` 统一入口 → 每条记一行 `cmd`(detail = 命令 JSON);选都不是 `GameCommand`,人类落子走公共 `pickCapital` → 同样记 `cmd` 行(detail `{type:"pickCapital",seat,tileIndex}`)。
- **bot 路径不产生 cmd 行**:`botAct` / `aiSetupStepFor` 直调引擎方法,不经 submitCommand——bot 行为不进命令流,日志只审计人类操作。单机托管(apLoop)/联机托管代驾同样直调 `botAct`,也不产生 cmd 行。
- **托管座位(#591/ADR-0028)**:room 行(detail `{type:"autopilot",seat,on,by}`)记录驱动权变化(与 `room.seatControlled` 同源)。托管是唯一代打状态域——**重放不再读 takeover 行(已随状态域删除),autopilot 行即驱动集依据**;`by` 分辨触发源(`self`=玩家自助/`watchdog`=停摆或保留窗到期代开),重放与审计可考,行为无分叉。
- **局头座位表记构造时原始规格**(bot 国号可空 = `doDraftRoll` 分配),如实归档开局规格。

## 3. 双轨落盘

| 轨道             | 时机                                                                                                                                | 位置                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| **联机(服务器)** | `RoomRegistry.persist`(每手快照)后经 `logSink` 钩子增量追加;房间行写入后即时追加;恢复房间的基线 = 恢复快照的 log 长度(重启不重不漏) | `data/logs/<gameId>.jsonl`(`LOGS_DIR`,默认 `./data/logs`) |
| **单机(客户端)** | 房间编排经 `logSink` 将权威日志交给 `archiveEngineLog`                                                                              | IndexedDB `dafung-logs`，按 `gameId` 存储                 |
| **联机(客户端)** | 首次水合、校准或重连时收到完整日志，其余通过已入座的连接接收新增日志                                                                | 与单机共用本机归档，保留已收到的权威日志                  |

- **gameId**:引擎构造时生成(毫秒时间戳 + 随机后缀,`newGameId()`),随快照序列化/恢复——联机各端、服务器重启后保持同一 id。
- **终局行**:引擎在胜负判定时写入 `engine.log`，各轨道随末次更新归档。

### 单局诊断文件

- 在局中打开「设置」里的「对局诊断」，默认选中当前局。回到主页、再战或重启后，从主页打开「对局诊断」，默认选中最近游玩且已记录的一局。两处都可选择历史局。
- 点「保存文件」，选择保存位置。文件包含所选局的完整已记录日志和同局已采集的帧诊，附版本、局 ID、回合、等待操作、交互与连接状态以及近期报错。文件开头可见局的身份与采集时间，后面是日志。
- 联机断线时仍可从本机取出已收到的座位视角日志。`logCapturedAt` 以本机收到最后一段已归档日志的时刻为准。联机增量日志需要配套的服务端版本。
- 当前运行期间，归档失败的原因显示在面板上，已有记录仍可保存。再战时若写入失败，可查看原因后选择继续。
- `appVersion` 是采集客户端现场所用的版本。旧对局里未记录的版本、现场或帧诊显示为缺失。文件区分采集时间与导出时间。术语见 [GLOSSARY](../../GLOSSARY.md)。

### 诊断摘要与复制（后续处理）

保存单局文件先落地。复制仍沿用已确认的设计，日常反馈可复制所选一局的诊断摘要，需要完整附件时保存文件。摘要优先保留关键现场、错误和性能摘要，再附最近最多 50 条日志，总长不超过 8000 字符，明确标注节选、截断与缺失。落地时以实现中的声明常量为数值单源。

用户反馈卓易通内运行 APK 时点击复制疑似缺权限，实际失败提示与卓易通内／外粘贴结果尚待确认，不能直接判定为系统权限问题。

现有 APK 复制仅走 WebView 的 `navigator.clipboard.writeText` 或 `execCommand`（`diagExport.ts` `copyDiagText`），未接入原生剪贴板。实施建议为 APK 接入 [Tauri 官方原生纯文本写入](https://v2.tauri.app/plugin/clipboard/)，显式声明写入能力；失败须显示具体错误，保存单局文件仍可使用。原生调用完成不代表卓易通外的目标应用一定能粘贴，跨环境结果须实测。

## 4. 30 天保底清理(无定时器)

- **服务器**:启动时扫 `data/logs/` 删 mtime 超过 `LOG_TTL_DAYS`(默认 30)天的 `.jsonl`。
- **本机**：新局首次归档时按 `gameLogArchive.ts` 的留存窗口清理旧局及其诊断材料。

## 5. 怎么看(归档用法)

- 用编辑器打开诊断文件，先读局 ID、关联版本和客户端现场，按 `round`、`turn` 对照日志。`brief` 是中文简报，`detail` 是机读记录。`header`、`cmd` 和 `final` 分别记录开局规格、操作和终局面板。
- 服务器需要核对原始权威记录时，按局 ID 读取 `data/logs/<gameId>.jsonl`。日志是归档材料，重放校验器已由 [ADR-0021](../adr/0021-drop-replay-and-hash-instruments.md) 退役。
- **边界**(ADR-0021):日志只是归档——规则随版本演进后,旧日志与新代码对不上属预期;排查 bug 靠描述 + 截图 + 现场重跑,不再有重放校验通路。
