# 回合与行军

> 规则手册第 3 页:棋盘、回合状态机、掷骰行军、必停都城、落格结算与轮次。

## 棋盘一图看懂

地图数据驱动(`board-loader.ts` `loadMap`;`public/maps/index.json` 首项为默认地图,现「关中图」guanzhong.json(#938)——4×7 满格螺旋环共 28 格:先沿外环环游一周再盘旋入腹地,28 为偶数、全环纯正交一格邻接,蛇尾洛阳与蛇头长安相邻、闭环边可见闭合;另一张内置图「中原争霸」zhongyuan.json 为速战小环,选图面板可切换;地图系统收敛口径见 [ADR-0048](../../adr/0048-map-system-slimming.md))。区域单源(#828):区域 = 分组字母 `group` + `theme.ts` `groupNames` 八区名单,城池格 `group` 必配、装载校验;唯一 UI 出口是城池详情卷轴的地域行(`DecisionScrollLayer.tsx` 按 group 查 `groupNames`)。棋盘由 `board.ts` `createBoard` 装配:

- **主路**:单环;**都城**是玩家开局所选的城,取代传统「起点」,经过必停(见下)。
- **全城池制**。棋盘每格都是城池。缺省 `event` 的格为普通城，带固定落地事件的是[特殊城池](../../adr/0037-special-city-event-field.md)。地图字段由 `board.ts` 的 `TILE_EVENTS` 与 `board-loader.ts` 的 `loadMap` 校验。
- **特殊城池**保有普通城的购买、扩军与交易权，地图上以两字方印标识（`Tile.tsx` 的 `TILE_EVENT_BADGES`）。三个种类为珍宝城（`treasure`，「珍宝」）、招贤城（`hero`，「名将」）和商市城（`market`，「商市」）。

## 回合状态机

每个实际回合先进入**摸牌阶段**，自动摸一张锦囊，再依次进入出牌阶段（有可用项时）、掷骰行军、落格结算及回合收尾。锦囊、主动技与技能书在出牌阶段共用手牌区。休整或罚跳跳过的座位没有摸牌阶段。引擎以 `authority.ts` 的 `TurnPhase` 管理决策相位，玩家操作经 `submitCommand` 提交。其他抉择相位按落格情况插入，见[抉择相位一览](#抉择相位一览)。

**反应窗**。他人行军进入途中城池时可由城主用「半路杀出」拦检，锦囊宣布后可由持牌者用「识破诡计」拆招。权威端在相应的结算点进入 `AwaitingReaction`，待应答完毕再继续，超时按「不出」结算。见 [ADR-0017](../../adr/0017-non-blocking-reaction-windows.md) 和[锦囊](./06-锦囊.md)。

**掷骰自动触发(#188 行军自动化)**:`Roll` 相位没有可抉择的内容,轮到谁都不用点——先钤一方「签」印起签(~0.8s),随后自动起摇掷骰行军(约 1s 静默拍后起摇,节奏单源 `src/core/timings.ts` `AUTO_ROLL_DELAY_MS`,单机进程内房间与联机服务器同读同值、经同一条命令路径代发)。各相位的**抉择**照旧等人作答,不自动化。

**托管代打节拍(#580)**:托管座位的决策由服务器 bot 逐步代打,**单节拍 2s/步**(`src/core/timings.ts` `AUTOPILOT_STEP_MS`,单机/联机同表同值)——托管是替人玩,节奏要像人;代打行为与 bot 座位同一套策略(行为单源,见 [锦囊](./06-锦囊.md)「bot 与看门狗」)。托管是唯一代打状态域(#591/[ADR-0028](../../adr/0028-takeover-is-autopilot.md)):自助开启与看门狗代开(停摆/掉线保留窗到期)拨的是同一个开关,节拍与打法无分叉。步进经注入时钟异步自续(步间让出宏任务):收回/重开托管命令得以在步间落地,链在下一步的座位归属复查处即停——收回托管**切回即停**(对局停在你的真人决策门),重开再续跑。(#529 快/慢双档叙事随 #580 归一退役。)

**bot 步进配速(#730/[ADR-0061](../../adr/0061-bot-step-pacing-lag-recalibration.md))**:bot 座位的连锁同样逐拍下行——**3s/步**(`src/core/timings.ts` `BOT_STEP_MS`,单机/联机同值),每步动作(掷骰/行军/结算)按实速演出播完再落下一步,轮到你时棋盘已追平、看得清每一步发生了什么。产出配速与播放侧的追帧/吸附治理([ADR-0029](../../adr/0029-presentation-self-consistency-invariants.md))分工:配速让普通对局**够不着**校准线,校准只留给掉线追平、全 bot 观战级的持续发散。无浏览器定向测试可显式关闭配速。

## 掷骰行军

- **单骰 1–6**,掷几步走几步(`movement-flow.ts` `rollAndMove`);持名将技**英姿**者**七面**(第七面 = 7,面数唯一单源 `skills.ts` `heroDieFaces`,从麾下槽位已授技推导、不入快照)——英姿适用该玩家**全部掷骰**(行军/拼点/探宝拼点,见[名将与技能](./08-名将与技能.md));开局点将定序摇骰发生在招募前,恒为六面(`setup-flow.ts` `doDraftRoll`)。掷骰结果以汉字「一~七」钤于顶中回合胶囊侧旁的**掷骰签**(`constants.ts` `SIGN_FACES`;骰子实现 `dice.ts` `createDice`;形制见 [ADR-0043](../../adr/0043-dice-roll-sign-presentation.md):不占屏幕中央、不压暗幕,人类/bot 同节拍),点数同时驻留手牌区左端**签面**。
- **移动加成**:名将技能可在 `BeforeMarch` 时机追加步数(如疾行 +1)——见[名将与技能](./08-名将与技能.md)与[时机框架](../../explanation/时机框架.md)。
- **行军表现口径([ADR-0029](../../adr/0029-presentation-self-consistency-invariants.md) 演出自洽三不变量)**:行军动画路径在事件提取拍一次算死(提取即定格,播放期零读对局状态),棋子怎么走、落在哪早已定死;每枚棋子的视觉位置同一时刻只有一个写入者(per-id 行军会话:新批顶替在途旧动画、切换点一帧直切,不滑移)。演出落后于对局进度时治理演出、不锁人——浅积压整场加速播放(追帧),持续落后才作废过时演出、棋子直切终态(吸附),全程无提示;轮到你操作只等**自己的棋子落定**,他人棋子照飞、不挡决策。

## 途经他人城池:拦检(半路杀出,#281)

行军进入其他在场诸侯所有的中途城池时，可触发拦检。实际离开该城时派发 `MarchPassedCity`。

- 城主持有「半路杀出」则开拦检窗,行军挂起(`movement-flow.ts` `marchTraverse`);无人拦则途经无感,照常走。
- 城主打出**拦检**:城主 vs 行人**拼点**(公共结算 `reaction-window.ts` `resolveDuel`,与连环计共用;双方各掷单骰,面数各随各人——持英姿者七面)。**城主胜=行人止步拦检城**、照常落格结算(可能被交涉);平局或落败=牌白耗,行人自拦检城后续走余下途经格——途中遇到的**下一座城**仍会开新询问点。拼点演出=全屏**拼点签面**(`duelResolved` 事件直译:每方一枚签面并排,并行起摇、依座位序错拍落定;点数只在签面一处,平/负宣告浮字不带点数括注,[ADR-0030](../../adr/0030-duel-sign-face-presentation.md))。
- 拦检结算内不再开新反应窗(拦检是终端结算,反识破链只挂锦囊宣布窗,ADR-0060);拦停成功时的行军动画止于拦检城(表现经 ADR-0010 事件管线)。

## 己城摸牌

- **经过**发生在棋子进入一座城后继续前进、实际离开该城时。**到达**发生在行军结束停在一座城时。同一次进入一座城只算一种。
- 每经过或到达一座当时归自己所有的城，各摸一张锦囊。行军起点、尚未走到的格以及本次到达后才购入的城都不发牌。购入的城从下一次符合条件的经过或到达开始补给。
- 拦停止步、掷骰正落和都城必停都按实际停下的格结算到达。拦检未止步时，要等到实际离开该城才算经过。摸出的牌按自身时机使用，本次行军途中不会重开出牌阶段。
- `movement-flow.ts` 的 `settlePassedCity` 与 `drawOwnCityArrivalSupply` 按权威行军进度结算。开局、回合和己城补给共用[一副锦囊牌库](./06-锦囊.md#摸牌)。

## 必停都城（驻跸）

- 继续走会经过自己的都城时，行军截断于都城，按到达摸牌，然后领[都城补给](./04-地产经济.md#都城补给)并结束回合。
- 掷骰正好落在自己的都城时，按到达摸牌，领补给并开启招贤机会。选择招将、求书或跳过后结束回合。自己的都城优先按都城规则处理。

## 落格结算总表

事件浮字在落点上方短暂停留，战报可回查结果。落格由 `movement-flow.ts` 的 `resolveLanding` 结算。特殊城池先处理固定事件，再进入购城、扩军、按兵不动或珍宝交涉。招贤选择结束后通过 `pendingCityEvent` 续接交易链。商市行情导致清算或破产时中断本次落格。

| 落点         | 处理                                     | 详见                                                           |
| ------------ | ---------------------------------------- | -------------------------------------------------------------- |
| 自己都城     | 补给后招贤。都城必停时补给后直接结束回合 | [地产经济](./04-地产经济.md)、[名将与技能](./08-名将与技能.md) |
| 招贤城       | 招将、求书或跳过，随后继续城池交易链     | [名将与技能](./08-名将与技能.md)                               |
| 珍宝城       | 先探宝，再继续城池交易链                 | [珍宝](./05-珍宝.md)                                           |
| 商市城       | 先结算随机行情，随后按结果续接           | [破产清算](./09-破产清算.md)                                   |
| 无主普通城   | 可购买（`AwaitingDecision`）             | [地产经济](./04-地产经济.md)                                   |
| 自己的普通城 | 可免费扩军（`AwaitingDecision`）         | [地产经济](./04-地产经济.md)                                   |
| 他人普通城   | 城主有珍宝时可交涉                       | [珍宝](./05-珍宝.md)                                           |

## 抉择相位一览

选项集集中注册于 `choices.ts` `PHASE_CHOICES`;除默认行为外可用选项 ≤1 时引擎自动执行、不弹卷轴(见 [ADR-0013](../../adr/0013-choice-set-and-auto-execute.md)),唯一例外是破产清算(`choices.ts` `EXCLUDED_FROM_AUTO`)。

抉择卷轴右上的减号和弹窗外的空白遮罩都可以最小化当前弹窗。玩家可在棋盘查阅城池和诸侯，从左上返回并继续原来的选择。回合及联机的时限照常推进，当前抉择一旦结束便收回返回入口。参见[交互设计](../../design/DESIGN.md)。

| 相位(`TurnPhase`)          | 谁决策             | 一句话                                                       |
| -------------------------- | ------------------ | ------------------------------------------------------------ |
| `AwaitingJinnang`          | 当前回合玩家       | 回合开始掷骰前:出牌阶段(用锦囊 / 出主动技 / 研读 / 「不出」) |
| `AwaitingReaction`         | 被询问座位(多属主) | 反应窗(#281):识破诡计/半路杀出的非阻塞应答点                 |
| `AwaitingDecision`         | 落格玩家           | 购地进驻或免费扩军,或按兵不动                                |
| `AwaitingTreasureOwner`    | 城主               | 珍宝交涉:公道买卖/坐地起价/不交易                            |
| `AwaitingSkillChoice`      | 技能属主           | 处理「你可」技能的待决应答                                   |
| `AwaitingHeroPick`         | 招贤诸侯           | 招将、求书或跳过                                             |
| `AwaitingBankruptcySettle` | 欠款玩家           | 变卖资产自救或宣告破产                                       |

体力归零后按[体力与休整](./07-体力与休整.md)依次结算，触发的技能待决使用 `AwaitingSkillChoice`。

## 回合结束与轮次

回合收尾由 `authority.ts` 的 `endTurn` 驱动。先结完 `TurnEnd` 的前、时、后三阶段及其选择和派生效果，再按地图顺序处理到期的燃烧。一座城的结果结清后才处理下一座。正逢全桌轮末时，再结算 `RoundEnd` 和持城收益。全部结清后判胜一次，对局继续才开启下一回合。详见[城池燃烧](../../adr/0070-city-levels-and-defense-scale.md#城池受伤与燃烧)与[胜利条件](./01-总览与胜利.md#胜利条件)。

轮次供名将技能冷却使用。燃烧按实际完成的个人回合计时，跳过座位和空轮次均不计时。已经开始的回合，即使因当前诸侯主动破产而结束，也照常计时。跳过时消费 `skipTurns`，休整标记在跳过计数耗尽时清除，体力回满。休整中的城主仍领轮末持城收益。详见[体力与休整](./07-体力与休整.md)。
