# 08 · 名将与技能

名将(英雄)是挂在玩家名下的技能载体:**被动技**(时机框架自动触发)+ **主动技**(出牌阶段内手动发动,#188 档 3)并存。核心设计是**技能即数据**:加名将只改数据文件、不动引擎;一武可多技。技能与名将解耦为「**技能池 + 授技**」(ADR-0036):技能独立成表(单源 [`../../src/core/skills.ts`](../../../src/core/skills.ts) `SKILLS`,被动+主动同表、技 id 全局唯一用技名拼音),名将只声明池 `HeroDef.skillPool`(按池声明序引用技 id,一技可入多将的池);招募落定时从池中**掷得授技子集**——下表是各将的池全貌,麾下实有技以授技为准(池内全技在**技能全览**弹层对照,未授者灰置)。

## 名将获取

- 起手 0 位,上限 3 位(`constants.ts` `HERO_CAPACITY`)。
- **招贤纳士**:落**自己都城**(驻跸补给之后)或**卧龙岗**时触发(落格分流在 `movement-flow.ts` `resolveLanding`,招贤本体 `tryRecruitHero`):从剩余名将池随机抽 3 位,**候选生成时逐候选预掷授技、卡面亮预掷结果再选将**(#787 预掷明牌,`AwaitingHeroPick` 卷轴),三选一(`resolveHeroPick`);麾下已满或池已空则无事发生,直接结束回合。
- **唯一性**:已被招揽的名将不再进候选池(`recruitedHeroIds`),全场同名将唯一。
- 其他来投渠道与招贤同池同上限:机遇「义士来投」「以宝换贤」(见 [`./07-声望与机遇.md`](./07-声望与机遇.md))、锦囊「求贤令」(见 [`./06-锦囊.md`](./06-锦囊.md))——两路无候选呈现,维持**盲盒**(将身份落定一刻同掷授技,落袋才见)。
- **破产释放**:玩家破产时麾下名将全部释放回招贤池(`finalizeBankruptcy`),他人可再招;见 [`./09-破产清算.md`](./09-破产清算.md)。

## 授技(#787,ADR-0036)

招募落定时该将从池中实际获得的技能子集,公式单源 `roster.ts` `rollGrantedSkills`:

1. **掷基数**:k = 1 + ⌊rng × 池大小⌋,1..池大小均匀(`rng` = 引擎骰 `g.dice.nextFloat`,联机各端一致);
2. **池内取子集**:对池 Fisher-Yates 洗牌(`dice.ts` `shuffle`)取前 k 定「谁入麾下」。

- **至少一技**天然成立(k 下界 1),**零保底**:主动技与被动技同池同 roll,「麾下有将无主动技」是这套设计的戏剧性,真频发再谈保底。
- **池序存**:子集按池声明序存(`HeroSlot.skillIds`),卡面序/派发序同源;洗牌只定成员、池序定存储序。
- **三路同一公式单点**:招贤路沿用候选行预掷结果入槽(候选卡亮的=实际入麾下的,不重掷);机遇/锦囊盲盒路在 `grantHeroSlot` 调用一刻现掷。入槽唯一口 `roster.ts` `grantHeroSlot`。
- **终身不改**:授技后无补技通道;遣散/破产释放不保留,该将回池后再被人招 = **重新掷**。
- **同名技 = 独立实例**:跨玩家、同玩家跨将的同名技互为独立实例,冷却各自记账(见下「冷却与派发」)。

## 技能系统:时机框架

技能是纯数据声明,单源 [`../../src/core/skills.ts`](../../../src/core/skills.ts) `SKILLS` 技表(名将经 `HeroDef.skillPool` 按池序引用,麾下实授技经槽位 `skillIds` 生效),由派发器 `authority.ts` `dispatchMoment` 按池序消费。三要素:

| 要素   | 载体                                                       | 语义                          |
| ------ | ---------------------------------------------------------- | ----------------------------- |
| when   | `timing.ts` `GameMoment`(39 时机七类,集中注册于 `MOMENTS`) | 什么时机触发                  |
| effect | `effects.ts` `EFFECTS` 注册表(EffectId → 效果函数)         | 做什么;查不到直接抛错(零兜底) |
| params | 纯数据参数(可序列化)                                       | 效果参数;缺必填项抛错         |

深度设计说明与扩展指南(加效果一步 / 加技能两步 / 加时机三步)见 [`../../explanation/时机框架.md`](../../explanation/时机框架.md)。

### 主动技与出牌阶段

- **出牌阶段**(窗口正名;#256 起呈现为手牌架**出牌阶段态**,不弹窗):每回合掷骰开始前、有可用锦囊或就绪主动技时的统一决策窗 = 可用锦囊 + 冷却就绪的主动技 + 「不出」——出牌/出技即结算,选「不出」(引擎 label「今不用」)则直接掷骰(选项集单源 `choices.ts` `jinnangChoices`,动作条呈现「不出」);零可用则静默跳过不进窗态(ADR-0013 ≤1 自动执行口径,`hasUsableJinnang`)。窗态里主动技与锦囊同为牌面形制:技卡 = **名将卡面**(HeroCardFace,#360:满幅立绘+竖排名+称号签+朱砂「将」章+●/◆ 技名 chips),与锦囊的朱底标签章牌面一眼可辨。
- **独立冷却**:主动技发动记麾下槽位的 `lastFired`(键 = 技 id,与被动技同机制、各槽各账;`choices.ts` `skillCooldownLeft` 算剩余轮数),与锦囊的「每回合每标签一张」名额互不相干。发动过技后重算选项集,同回合仍有可用锦囊/其他就绪技则窗口停留(`settleJinnangExit`)。
- **出技是公开事件**:浮字 + `category:"skill"` 战报(detail 锚 `heroSkill owner/skill/kind/target`),与出牌同口径。命令 `useHeroSkill`(`authority.ts`):指向域的技选定后进**目标段**(载荷 `jinnang-execution.ts` `PendingHeroSkill`,与锦囊目标段互斥;可「作罢」,不记冷却)。any 域(赈济)候选含自己——自选目标回归席位格单点:候选面随席位格候选装配,自机格的点击层即候选钮(旧「你」印候选钮随仪表条退役,#700),与对手席候选同口径(金圈呼吸/点选实金停持/再点取消/不可用灰置印原因)。合法性(相位/持有/冷却/费用/目标)由引擎校验(`jinnang-execution.ts` `resolveHeroSkill`),UI 永不裁决。
- **结算纪律**:复用既有结算路径(火攻 = `demolishOnVictim`,不新造 effect kind);技能结算内**不派发时机**(与 `grantSkillCash` 的防连锁同口径——出技不触发他人的 CashLost/CashGained 被动技);主动技**不可被识破**(不经宣布通道,`fireHeroSkill` 直结算,#229/#281 口径)。
- **快照/重放**:冷却(麾下槽位 `lastFired` 随槽位全量进快照,#785)、招贤候选预掷授技(`offeredHeroes` 行携 `skillIds` 随决策窗校准快照下行,#787)、目标段载荷 `pendingSkill`、擂鼓加成 `heroDiceBonus` 全量进快照(序列化单点清单 `snapshot.ts`);得将宣告事件 `heroRecruited` 事件体携本次授技 `skillIds`(权威态随事件下行,客户端折叠不重掷)。技能命令是普通 cmd 行,重放天然复现。技能选项不含他人私隐(名将/冷却/城防/现金均公开),ADR-0016 投影无新增泄漏面。
- **bot/托管(含看门狗代开)**:bot 出技按净值贪心(`bot.ts` `heroSkillIntent`:火攻挑城最多者、赈济体力 <70 自疗、征辟可用即用补偿给最穷者、擂鼓恒用);托管中的人类座位代驾(自助或看门狗代开,#591/[ADR-0028](../../adr/0028-takeover-is-autopilot.md))与 bot **同款出技**(#580 代打行为单源,原「代驾永不主动出技」口径退役)。

### scope 与触发留痕

- **scope**(技能属主与时机主体的关系,缺省 `self`;判定 `authority.ts` `scopePasses`):`self` = 属主是主体;`others` = 主体非属主;`any` = 主体不限;`actor` = 主体恰为当前行动玩家(多数现役挂点主体即行动者;回合外主体的时机已有 `PlayerBankrupt` 的破产者/`AssetsSeized` 的债主/`TurnSkipImposed` 的被跳者等,此时 `actor` 与 `any` 分化)。
- **触发留痕**:击发记 `category:"skill"` 战报,detail 含 `skillFire owner/hero/skill/moment/subject`——每次触发可审计、可重放(日志格式见 [`../对局日志.md`](../对局日志.md))。

### 冷却与派发

- **冷却实例化**:技能可带 `cooldown`(单位 = 轮;键 = `skill.id`,记于麾下槽位 `lastFired`);同名技跨玩家、跨将均为独立实例,**各槽各账**(两玩家同技、同玩家两将同技合法共存、互不相干;`skillReady` 判「距上次触发 ≥ N 轮」)。被动技现役仅华佗带 3 轮冷却;主动技四人全带(3~5 轮,见上表),同用此机制。
- **确定性派发**:`dispatchMoment` 按「座位序 × 麾下槽位序 × 槽内已授技序(=池声明序)」遍历,同种子下联机各端派发次序完全一致。
- **三条纪律**:破产玩家的技能不参与派发;效果函数返回 false = 条件不满足,静默跳过(不记战报/冷却);效果内禁止同步再派发时机(派发深度 >2 直接抛错防递归),效果层收益(如技能给银 `grantSkillCash`)不再触发 `CashGained`——技能链不会自我放大。
