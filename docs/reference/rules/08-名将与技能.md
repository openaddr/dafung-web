# 08 · 名将与技能

名将(英雄)是挂在玩家名下的技能载体:**被动技**(时机框架自动触发)+ **主动技**(出牌阶段内手动发动,#188 档 3)+ **静态被动**(持有即恒常改一条推导值,#1390 英姿首例)三形并存。核心设计是**技能即数据**:加名将只改数据文件、不动引擎;一武可多技。技能与名将解耦为「**技能池 + 授技**」(ADR-0036):技能独立成表(单源 [`../../src/core/skills.ts`](../../../packages/core/src/engine/skills.ts) `SKILLS`,被动+主动+静态被动同表、技 id 全局唯一用技名拼音),名将只声明池 `HeroDef.skillPool`(按池声明序引用技 id,一技可入多将的池);招募落定时从池中**掷得授技子集**——下表是各将的池全貌,麾下实有技以授技为准(池内全技在**技能全览**弹层对照,未授者灰置)。

## 查看麾下名将

右下「名将」或「诸侯详情」中的名将入口打开人物卷：点画像签切换人物，在大幅画像旁阅读该将当前实授技能全文；长文在正文内滚，读取的不是技能池全貌。自己与他人使用同一布局，查看他人时只读。

自己的遣散操作固定在文稿下方，沿现行权限与两次确认流程；不可遣散时显示原因，切将、关闭重开或名册变化会解除旧确认。出牌阶段在手牌区研读技能书，确认后人物卷随实授技能更新。槽位与学技判定以 `roster.ts` 的 `HeroSlot`、`skillBookLearners`、`learnSkillInSlot` 为准。

## 招贤与名将获取

- 起手无名将，麾下最多三位（`constants.ts` 的 `HERO_CAPACITY`）。
- 掷骰正好落在自己的都城（补给之后）或落在招贤城（`event:"hero"`）时，开启一次招贤。可选招将、求书或跳过。招贤城结清后继续交易链，己都城结清后结束回合。
- **招将**从尚未被招揽的名将中随机展示至多三名候选。候选生成时已掷出实际授技，卡面会亮出结果。点候选可查全技能池，确认「收为麾下」后沿用已亮出的授技。同一名将在全场唯一。
- **求书**立即随机得到一册技能书，占用同一次招贤机会。麾下满编或名将池已空时，仍可求书或跳过。
- 锦囊「求贤令」共用名将池，随机招揽一名并公布授技。满编时按该次授技印书，池空时折现，见[锦囊目录](./06-锦囊.md#锦囊目录)。
- 破产或遣散会使该将回到招贤池。招贤与续接见 `recruitment.ts` 的 `tryRecruitHero`／`resolveHeroPick`。

## 结算声

招将成功时，甲扣和短弦贴「来投」宣告。求书、满编印书与遣散用书册入案，遣散时同次折出的多册合响一次。研读实际习得技能时，翻页收弦贴「习得」宣告。名将池已尽触发折现时，铜钱贴归账抵达。窃取、交割技能书沿用对应的珍宝结算声，被动技随得银、行军等实际效果发声。见[音效设计](../../design/音效设计.md)。

## 授技(#787,ADR-0036;分布 ADR-0046)

招募落定时该将从池中实际获得的技能子集,公式单源 `roster.ts` `rollGrantedSkills`:

1. **掷基数**:k 服从**几何衰减**(P(k) ∝ (1/5)^(k-1),#969/ADR-0046)——大概率一技、小概率两技、极小概率满池:三技将 1 技 25/31(80.6%)、2 技 5/31(16.1%)、3 技 1/31(3.2%);华佗池 2 为 5/6(83.3%)、1/6(16.7%)。整数权重 5^(池大小−k) 求和,单掷反变换落档定 k(`rng` = 引擎骰 `g.dice.nextFloat`,联机各端一致);
2. **池内取子集**:对池 Fisher-Yates 洗牌(`dice.ts` `shuffle`)取前 k 定「谁入麾下」。

- **至少一技**天然成立(k 下界 1),**零保底**:主动技与被动技同池同 roll,「麾下有将无主动技」是这套设计的戏剧性,真频发再谈保底。
- **池序存**:子集按池声明序存(`HeroSlot.skillIds`),卡面序/派发序同源;洗牌只定成员、池序定存储序。
- **两路共用公式**。招贤路沿用候选行预掷结果入槽(候选卡亮的=实际入麾下的,不重掷);「求贤令」路在 `grantHeroSlot` 调用一刻现掷。入槽唯一口 `roster.ts` `grantHeroSlot`。
- **招募结果固定**:招募时的授技结果不重掷，后续可用技能书补入池内未习技能；遣散/破产释放不保留，该将回池后再被人招 = **重新掷**。
- **同名技 = 独立实例**:跨玩家、同玩家跨将的同名技互为独立实例,冷却各自记账(见下「冷却与派发」)。

## 技能书

- **求书**遍历技能表，能被至少一位麾下名将研读的书进入可学池，其余书进入其他池。每种技能只计一册。可学池有候选时，两个池各有 50% 概率，选池后再用引擎骰源随机取一册。可学池为空时直接从其他池抽取。见 `recruitment.ts` 的 `seekSkillBook`。
- **研读**在出牌阶段从手牌区点书，选择麾下名将，确认「确认研读」后才消耗一册。资格要求该技属于该将的技能池且尚未习得，取消保留书册。命令是 `useBookSkill`，资格和授技分别由 `roster.ts` 的 `skillBookLearners` 与 `learnSkillInSlot` 管理。
- **技能书是可交易珍宝**，也能被夺取或变卖。暂时无人可学的书保留在珍宝中，待有合资格名将时进入手牌区。出牌阶段的展示与锦囊张数、牌库和弃牌堆分开计算。同种技能书可同时持有多册。

## 遣散(#1147)

麾下名册弹层(藏品弹层·名将)的「遣散」操作:**自己回合可点、免费**(无银两代价,他座决策窗如珍宝交涉及破产清算期间除外);**二段式确认**——首点武装「确认遣散」,再点同将才发命令。命令 `dismissHero`(`authority.ts` 薄委托),校验与结算单点 `hero-dismiss.ts` `dismissHero`:自己回合、目标在麾下且不在破产清算,违规由引擎拒绝。清算不能通过遣散折书筹款,名将不参与变现;主动遣散本身没有银两过手。

- **回池**:遣散即 `recruitedHeroIds` 划名(与破产释放 `finalizeBankruptcy` 同口径)——谁都能再招;**再招 = 全新实例**:授技重新预掷(`roster.ts` `rollGrantedSkills` 现掷)、槽内冷却账不遗留(整槽弃,#785)。
- **折书**:已学技**逐册折成技能书**按普通珍宝入位(印书单源 `treasures.ts` `makeSkillBook`;每册 push 珍宝 + 战报一行 + `TreasureGained` 时机派发,`recruitment.ts` `printSkillBooks` 同构**零特判**——`TreasureGained` 监听技白得照走珍宝通路)。同技多册 = 同 id 多册(`skillbook-<skillId>`);当前无人可学的书仍可交易、变卖或被窃玉偷香夺取。
- **宣告**:`heroDismissed` 事件(seat=遣散者,携 heroId/skillIds=折书明细)显式产出(**非触发时机**——不进 MOMENTS、无 scope/冷却语义);表现=遣散浮字,折书入位演出由同批 `treasureGained` 逐册承担。
- **bot/托管**:v1 不主动遣散(bot 零改动;位满自动改发书已兜住腾位压力)。

## 技能系统:时机框架

技能是纯数据声明，单源为 [`skills.ts`](../../../packages/core/src/engine/skills.ts) 的 `SKILLS`。名将所授技能以麾下槽位 `skillIds` 为准。技表含时机驱动被动技、出牌阶段主动技，以及持有时持续生效的静态被动技。时机驱动被动技用以下字段编排。

| 要素   | 载体                                               | 语义                          |
| ------ | -------------------------------------------------- | ----------------------------- |
| when   | `timing.ts` `GameMoment`(集中注册于 `MOMENTS`)     | 什么时机触发                  |
| stage  | `timing.ts` 的 `MomentStage`                       | 同一时机内的前、时或后阶段    |
| effect | `effects.ts` `EFFECTS` 注册表(EffectId → 效果函数) | 做什么;查不到直接抛错(零兜底) |
| params | 纯数据参数(可序列化)                               | 效果参数;缺必填项抛错         |

深度设计说明与扩展指南(加效果一步 / 加技能两步 / 加时机三步)见 [`../../explanation/时机框架.md`](../../explanation/时机框架.md)。

### 「你可」选择闸(#1377/#1378,被动技可选发动形制)

「你可」表示技属主有权选择发动或放弃。技能命中时在该时机的当前阶段等待应答（`AwaitingSkillChoice`，命令 `respondSkillChoice`）。放逐需要选择目标，行殇的目标是进入休整的诸侯。应答及派生效果结清后继续当前结算。三段时机与文案约定见 [ADR-0068](../../adr/0068-moment-stages.md)。

- **发动落账**:目标 `skipTurns` +1(与缓兵之计同形制叠加)+ 追加一笔「被强加跳回合」(reason=xingshang,韬光养晦按笔计酬属设计联动);`fireResetsMarks` 技(放逐)另把本槽标记归零,超出阈值的部分随归零舍弃。体力耗竭重置时未放掉的标记保留,跨休整周期继续积累;遣散/换技随技能槽清零。
- **超时语义**:单机决策不限时(无窗级 deadline);联机停摆超时由看门狗代发「暂不发」(标记保留;`scripts/watchdogs.ts` #118 真修,#1378),托管 ON 的座位仍按 bot 策略代答。
- **bot/托管**:决策单源 `bot.ts` `botSkillChoiceDecision`(纯函数,与玩家同规则不同决策者)——行殇恒发动(零成本);放逐攒满即发动,目标=身价领跑者(与缓兵之计同一排序公式,并列取座位序小者)。
- **快照/联机**:待决队列 `pendingSkillChoices` 与技能标记 `HeroSlot.marks` 全量随快照走(非空才产键,空=规范缺省);联机经校准快照同步,重连后待决与标记仍在(ADR-0020 快照锚)。

### 主动技与出牌阶段

- **出牌阶段**(窗口正名;#256 起呈现为手牌架**出牌阶段态**,不弹窗):每回合掷骰开始前,有可用锦囊、可用主动技或可学技能书时进入统一决策窗。锦囊、主动技和可学技能书均从手牌区选择;选「不出」(引擎 label「今不用」)则直接掷骰(牌与技的选项集单源 `choices.ts` `jinnangChoices`);三者均不可用则跳过窗态(`hasUsableJinnang`)。锦囊与**技能卡**混排(组件单源 `SkillCardFace`):一张技能卡代表某将的一条主动技,立绘占牌面主体，底签左下是将名，右下是技名，卡面不列技能说明和冷却周期。不可用的卡显示原因,冷却中剩余轮数由 `choices.ts` `skillCooldownLeft` 推导。同将多条主动技或不同将持同名技均各自独立一卡,不合并(#817 每实例一选项,id=`skill:<heroId>:<skillId>`,拼接单源 `skillOptionId`)。点卡体选中,点技名打开**技能全览**查看技效和冷却周期(技表单源 [`../../../src/core/skills.ts`](../../../packages/core/src/engine/skills.ts));不可用时仍可查看全览,但不能选中或发动。
- **独立冷却**:主动技发动记麾下槽位的 `lastFired`(键 = 技 id,与被动技同机制、各槽各账;`choices.ts` `skillCooldownLeft` 算剩余轮数)。发动过技后重算选项集,同回合仍有可用锦囊/其他可用主动技/可学技能书则窗口停留(`settleJinnangExit`)。
- **出技是公开事件**:浮字 + `category:"skill"` 战报(detail 锚 `heroSkill owner/skill/kind/target`;城目标域另锚 `prop/tile`),与出牌同口径。命令 `useHeroSkill`(`authority.ts`):指向域/城目标域的技选定后进**目标段**(载荷 `jinnang-execution.ts` `PendingHeroSkill`,与锦囊目标段互斥;可「作罢」,不记冷却)。any 域(赈济)候选含自己——自选目标回归席位格单点:候选面随席位格候选装配,自机格的点击层即候选钮(旧「你」印候选钮随仪表条退役,#700),与对手席使用相同的亮边、金勾和灰置状态，不可用原因在动作条显示。城目标域(#1388 火攻)候选=**合法城清单**(谓词单源 `choices.ts` `heroSkillCityTargets`:距离 ≤ `skills.ts` `huogong.params.range`、城主为他人),逐城携城名/城主/距离供点选,提交通道=目标城 tileIndex(选城呈现形制归 UI 交付票)。合法性(相位/持有/冷却/费用/目标)由引擎校验(`jinnang-execution.ts` `resolveHeroSkill`),UI 永不裁决。
- **火攻结算**。火攻与火烧连营共用 `defense.ts` 的 `applyDirectFireDamage`。直接火焰、燃烧与外敌乘虚共用城池伤害结算。每座城逐笔结清银两和「得银」时机，再派发城损时机。实际降级派发一次「城池受损」，攻陷造成易主或回到无主派发一次「失城」，均以原城主为主体。纯扣防和都城打空只处理扣防及合格的银两。每座城依次结清各时机的「前」「时」「后」阶段及其中的技能应答和派生效果，再继续当前行动或处理同批下一座城。火攻由 `fireHeroSkill` 直结算，识破针对锦囊声明。伤害、攻陷归属和奖励见[地产经济](./04-地产经济.md#城池攻陷与奖励)。
- **快照/重放**:冷却(麾下槽位 `lastFired` 随槽位全量进快照,#785)、招贤候选预掷授技(`offeredHeroes` 行携 `skillIds` 随决策窗校准快照下行,#787)、目标段载荷 `pendingSkill`、擂鼓加成 `heroDiceBonus` 全量进快照(序列化单点清单 `snapshot.ts`);得将宣告事件 `heroRecruited` 事件体携本次授技 `skillIds`(权威态随事件下行,客户端折叠不重掷)。技能命令是普通 cmd 行,重放天然复现。技能选项不含他人私隐(名将/冷却/防御值/现金均公开),ADR-0016 投影无新增泄漏面。
- **bot/托管(含看门狗代开)**:bot 出技按净值贪心(`bot.ts` `heroSkillIntent`:火攻=合法城里定向择优——等级最高→购价(`purchasePrice`)最高→`tileIndex` 小,与人类同参数不按身份分档,#1388 统一原则;赈济体力 <70 自疗、擂鼓恒用);托管中的人类座位代驾(自助或看门狗代开,#591/[ADR-0028](../../adr/0028-takeover-is-autopilot.md))与 bot **同款出技**(#580 代打行为单源,原「代驾永不主动出技」口径退役)。

### scope 与触发留痕

- **scope**(技能属主与时机主体的关系,缺省 `self`;判定 `authority.ts` `scopePasses`):`self` = 属主是主体;`others` = 主体非属主;`any` = 主体不限;`actor` = 主体恰为当前行动玩家(多数现役挂点主体即行动者;回合外主体的时机已有 `PlayerBankrupt` 的破产者/`AssetsSeized` 的债主/`TurnSkipImposed` 的被跳者等,此时 `actor` 与 `any` 分化)。
- **触发留痕**:击发记 `category:"skill"` 战报,detail 含 `skillFire owner/hero/skill/moment/subject`——每次触发可审计、可重放(日志格式见 [`../对局日志.md`](../对局日志.md))。

### 冷却与派发

- **冷却实例化**:技能可带 `cooldown`(单位 = 轮;键 = `skill.id`,记于麾下槽位 `lastFired`);同名技跨玩家、跨将均为独立实例,**各槽各账**(两玩家同技、同玩家两将同技合法共存、互不相干;`skillReady` 判「距上次触发 ≥ N 轮」)。被动技现役仅华佗带 3 轮冷却;主动技全带冷却(3~5 轮,见上表),同用此机制。
- **确定性派发**:`dispatchMoment` 按「座位序 × 麾下槽位序 × 槽内已授技序(=池声明序)」遍历,同种子下联机各端派发次序完全一致。
- **三条纪律**:破产玩家的技能不参与派发;效果函数返回 false = 条件不满足,静默跳过(不记战报/冷却);效果内禁止同步再派发时机(派发深度 >2 直接抛错防递归),效果层收益(如技能给银 `grantSkillCash`)不再触发 `CashGained`——技能链不会自我放大。
