# 08 · 名将与技能

名将(英雄)是挂在玩家名下的技能载体:**被动技**(时机框架自动触发)+ **主动技**(出牌阶段内手动发动,#188 档 3)+ **静态被动**(持有即恒常改一条推导值,#1390 英姿首例)三形并存。核心设计是**技能即数据**:加名将只改数据文件、不动引擎;一武可多技。技能与名将解耦为「**技能池 + 授技**」(ADR-0036):技能独立成表(单源 [`../../src/core/skills.ts`](../../../src/core/skills.ts) `SKILLS`,被动+主动+静态被动同表、技 id 全局唯一用技名拼音),名将只声明池 `HeroDef.skillPool`(按池声明序引用技 id,一技可入多将的池);招募落定时从池中**掷得授技子集**——下表是各将的池全貌,麾下实有技以授技为准(池内全技在**技能全览**弹层对照,未授者灰置)。

## 查看麾下名将

右下「名将」或「诸侯详情」中的名将入口打开人物卷：点画像签切换人物，在大幅画像旁阅读该将当前实授技能全文；长文在正文内滚，读取的不是技能池全貌。自己与他人使用同一布局，查看他人时只读。

自己的遣散操作固定在文稿下方，沿现行权限与两次确认流程；切将、关闭重开或名册变化会解除旧确认。学习仍从珍宝中的技能书进入，一人可学直接学习、多名可学先选人；完成后人物卷随当前实授技能更新。槽位与学技判定以 `roster.ts` 的 `HeroSlot`、`skillBookLearners`、`learnSkillInSlot` 为准。

## 名将获取

- 起手 0 位,上限 3 位(`constants.ts` `HERO_CAPACITY`)。
- **招贤纳士**:落**自己都城**(驻跸补给之后)或**招贤城**(`event:"hero"` 特殊城池)时触发(落格分流在 `movement-flow.ts` `resolveLanding`,招贤本体 `tryRecruitHero`):从剩余名将池随机抽 3 位,**候选生成时逐候选预掷授技、卡面亮预掷结果再选将**(#787 预掷明牌,`AwaitingHeroPick` 卷轴),三选一(`resolveHeroPick`)。**先看后选**:点候选卡或技名都开**技能全览**详情弹框(池全貌对照),弹框内「收为麾下」拍板方定将(2026-11-01 拍板,点卡不再直选;浏览语境弹框保持只读);麾下已满或池已空则事件沉默,照常续进交易链。
- **唯一性**:已被招揽的名将不再进候选池(`recruitedHeroIds`),全场同名将唯一。
- 其他来投渠道与招贤同池同上限:机遇「义士来投」「以宝换贤」(见 [`./07-声望与机遇.md`](./07-声望与机遇.md))、锦囊「求贤令」(见 [`./06-锦囊.md`](./06-锦囊.md))——两路无候选呈现,维持**盲盒**(将身份落定一刻同掷授技,落袋才见)。
- **破产释放**:玩家破产时麾下名将全部释放回招贤池(`finalizeBankruptcy`),他人可再招;见 [`./09-破产清算.md`](./09-破产清算.md)。

## 授技(#787,ADR-0036;分布 ADR-0046)

招募落定时该将从池中实际获得的技能子集,公式单源 `roster.ts` `rollGrantedSkills`:

1. **掷基数**:k 服从**几何衰减**(P(k) ∝ (1/5)^(k-1),#969/ADR-0046)——大概率一技、小概率两技、极小概率满池:三技将 1 技 25/31(80.6%)、2 技 5/31(16.1%)、3 技 1/31(3.2%);华佗池 2 为 5/6(83.3%)、1/6(16.7%)。整数权重 5^(池大小−k) 求和,单掷反变换落档定 k(`rng` = 引擎骰 `g.dice.nextFloat`,联机各端一致);
2. **池内取子集**:对池 Fisher-Yates 洗牌(`dice.ts` `shuffle`)取前 k 定「谁入麾下」。

- **至少一技**天然成立(k 下界 1),**零保底**:主动技与被动技同池同 roll,「麾下有将无主动技」是这套设计的戏剧性,真频发再谈保底。
- **池序存**:子集按池声明序存(`HeroSlot.skillIds`),卡面序/派发序同源;洗牌只定成员、池序定存储序。
- **三路同一公式单点**:招贤路沿用候选行预掷结果入槽(候选卡亮的=实际入麾下的,不重掷);机遇/锦囊盲盒路在 `grantHeroSlot` 调用一刻现掷。入槽唯一口 `roster.ts` `grantHeroSlot`。
- **招募结果固定**:招募时的授技结果不重掷，后续可用技能书补入池内未习技能；遣散/破产释放不保留，该将回池后再被人招 = **重新掷**。
- **同名技 = 独立实例**:跨玩家、同玩家跨将的同名技互为独立实例,冷却各自记账(见下「冷却与派发」)。

## 技能书(#1146)

**位满改发书**:麾下三位已满后再遇招贤机会(招贤城/机遇「义士来投」「以宝换贤」/锦囊「求贤令」,四路同一分叉单喉 `recruitment.ts` `grantHeroOrBooks`)——不再得将,改为**该次预掷授技各印一册技能书**按普通珍宝入位:该次预掷照掷(选将 1 掷 + 授技 1 掷,零新随机),掷得几技印几册;不占招贤池、零折现(「名将已尽」的折现语义不变,与位满分叉互斥)。书名 = 「技能书·技名」由技表现组(印书单源 `treasures.ts` `makeSkillBook`,禁逐技静态造表);战报逐册一行,入位宣告走 `TreasureGained` 时机(珍宝现通路)。

**书 = 「此技习得器」**(技能二元有无,无等级语义;`level` 只承载珍宝位价值):

- **可点窗口**:己方出牌阶段(珍宝弹层书格真钮;1 名可学直学、多名开选人弹窗、0 名可学=不可用态)。
- **研读**:消耗决策者珍宝位一册书,令麾下一名「池含此技且未习得」名将习得该技(可学者判定单源 `roster.ts` `skillBookLearners`,bot 贪心取槽位序首、零新随机);**池序入槽**、`lastFired` 不落键(照新授技同款,无冷却负债);用后书消耗;命令 `useBookSkill`(`authority.ts`,校验 `jinnang-execution.ts` `resolveBookSkill`,UI 永不裁决)。
- **池绑定不变量**:槽内技能恒为池的按序子集,招贤所得与书学所得不可分辨——学得的技与招贤所得技同槽同账,时机派发/冷却/事件链零第二套(学得主动技即刻就绪,出牌窗照常出)。
- **全套珍宝白得**:书是普通珍宝实例——escrow 交易/破产变卖(按 `SKILL_BOOK_LEVEL` 档指导价)/来访求购/窃玉偷香零特判零豁免;快照随 `TreasureRow` 新增 `kind`/`skillId` 字段往返保真(存量字段零删改)。
- **宣告**:`skillLearned` 事件(seat=习得者,携 heroId/skillId/treasureId)随批下行,折叠面入槽+书出册,表现=习得浮字;战报 `category:"skill"`。
- **bot/托管**:出牌阶段扫描珍宝位,可用书即用(可用即用零权衡);不卖书权衡——变卖路无书特判。

## 遣散(#1147)

麾下名册弹层(藏品弹层·名将)每将领卡下一枚「遣散」钮:**自己回合随时可点、免费**(无声望/银两代价,他座决策窗如珍宝交涉除外);**二段式确认**——首点武装「确认遣散」,再点同将才发命令(遣散不可逆的误触防线,交涉成交钮同惯例)。命令 `dismissHero`(`authority.ts` 薄委托),校验与结算单点 `hero-dismiss.ts` `dismissHero`:自己回合 + 目标在麾下,违规引擎 `warn` 硬拒绝(UI 永不裁决)。与破产清算的「遣散换银」(`bankruptcy.ts` `cashHeroBankruptcy`,200 两)分流:主动遣散零银两过手。

- **回池**:遣散即 `recruitedHeroIds` 划名(与破产释放 `finalizeBankruptcy` 同口径)——谁都能再招;**再招 = 全新实例**:授技重新预掷(`roster.ts` `rollGrantedSkills` 现掷)、槽内冷却账不遗留(整槽弃,#785)。
- **折书**:已学技**逐册折成技能书**按普通珍宝入位(印书单源 `treasures.ts` `makeSkillBook`;每册 push 珍宝 + 战报一行 + `TreasureGained` 时机派发,`recruitment.ts` `printSkillBooks` 同构**零特判**——`TreasureGained` 监听技白得照走珍宝通路)。同技多册 = 同 id 多册(`skillbook-<skillId>`);独门技的书 = **纯交易物**(无人可学,交易/变卖/窃玉全套珍宝现通路自洽)。
- **宣告**:`heroDismissed` 事件(seat=遣散者,携 heroId/skillIds=折书明细)显式产出(**非触发时机**——不进 MOMENTS、无 scope/冷却语义);表现=遣散浮字,折书入位演出由同批 `treasureGained` 逐册承担。
- **bot/托管**:v1 不主动遣散(bot 零改动;位满自动改发书已兜住腾位压力)。

## 技能系统:时机框架

技能是纯数据声明,单源 [`../../src/core/skills.ts`](../../../src/core/skills.ts) `SKILLS` 技表(名将经 `HeroDef.skillPool` 按池序引用,麾下实授技经槽位 `skillIds` 生效),由派发器 `authority.ts` `dispatchMoment` 按池序消费。技表三形:**时机驱动被动**(`TriggerSkill`,when×effect×params 三要素)/ **主动**(`ActiveSkillDef`,出牌手动)/ **静态被动**(`StaticSkillDef`,#1390 英姿首例——无时机、无结算、无冷却,持有即恒常改一条推导值,不经派发、不入快照)。时机驱动被动三要素:

| 要素   | 载体                                                       | 语义                          |
| ------ | ---------------------------------------------------------- | ----------------------------- |
| when   | `timing.ts` `GameMoment`(37 时机七类,集中注册于 `MOMENTS`) | 什么时机触发                  |
| effect | `effects.ts` `EFFECTS` 注册表(EffectId → 效果函数)         | 做什么;查不到直接抛错(零兜底) |
| params | 纯数据参数(可序列化)                                       | 效果参数;缺必填项抛错         |

深度设计说明与扩展指南(加效果一步 / 加技能两步 / 加时机三步)见 [`../../explanation/时机框架.md`](../../explanation/时机框架.md)。

### 「你可」选择闸(#1377/#1378,被动技可选发动形制)

「你可」措辞的被动技(现役=放逐/行殇)命中时机且条件满足时**不自动结算**,而是挂起待决(`choices.ts` `PendingSkillChoice` 队列),回合收口 `endTurn` 入口逐条开窗(`choices.ts` `enterSkillChoiceWindowIfOwed`,相位 `AwaitingSkillChoice`):决策者=技属主(`authority.ts` `decisionOwner`),命令面=`respondSkillChoice(seat, use, targetSeat?)`(发动=放逐自选目标/行殇目标既定;暂不发=标记保留,再攒再问)。窗呈现=触发卡(SkillChoiceBanner,架缘横幅,反应窗同形)+ 放逐进度上席位格底缘金色进度轨(状态表达 DESIGN §4.6,数值在 aria-label)。

- **发动落账**:目标 `skipTurns` +1(与缓兵之计同形制叠加)+ 追加一笔「被强加跳回合」(reason=xingshang,韬光养晦按笔计酬属设计联动);`fireResetsMarks` 技(放逐)另把本槽标记归零,超出阈值的部分随归零舍弃。体力耗竭重置时未放掉的标记保留,跨休整周期继续积累;遣散/换技随技能槽清零。
- **超时语义**:单机决策不限时(无窗级 deadline);联机停摆超时由看门狗代发「暂不发」(标记保留;`scripts/watchdogs.ts` #118 真修,#1378),托管 ON 的座位仍按 bot 策略代答。
- **bot/托管**:决策单源 `bot.ts` `botSkillChoiceDecision`(纯函数,与玩家同规则不同决策者)——行殇恒发动(零成本);放逐攒满即发动,目标=身价领跑者(与缓兵之计同一排序公式,并列取座位序小者)。
- **快照/联机**:待决队列 `pendingSkillChoices` 与技能标记 `HeroSlot.marks` 全量随快照走(非空才产键,空=规范缺省);联机经校准快照同步,重连后待决与标记仍在(ADR-0020 快照锚)。

### 主动技与出牌阶段

- **出牌阶段**(窗口正名;#256 起呈现为手牌架**出牌阶段态**,不弹窗):每回合掷骰开始前、有可用锦囊或就绪主动技时的统一决策窗 = 可用锦囊 + 冷却就绪的主动技 + 「不出」——出牌/出技即结算,选「不出」(引擎 label「今不用」)则直接掷骰(选项集单源 `choices.ts` `jinnangChoices`,动作条呈现「不出」);零可用则静默跳过不进窗态(ADR-0013 ≤1 自动执行口径,`hasUsableJinnang`)。窗态 = 可用锦囊牌面与**技能卡**混排(组件单源 `SkillCardFace`,#818 双方案比选定案):技能卡 = 「某将的某条主动技」一张卡,**技能为维度、名将为载体**——卡面 = 名将立绘与将名(载体,沿用名将卡面家族制式:金框画心立绘+竖排名带+朱砂「将」章)+ **主技名大字竖章**(叠画心左缘,与将名带「左技右将」对读,一眼定本卡身份)+ 该技一句话描述 + 冷却注(冷却周期读技表单源 [`../../../src/core/skills.ts`](../../../src/core/skills.ts);实例解冻剩余不另记第二遍——冷却中卡灰置,印条经选项 reason 单源携带 `choices.ts` `skillCooldownLeft` 的剩余轮数)。同将多条主动技就绪 = 多卡各显各技,不同将持同名技 = 各自独立一卡、**不合并**(#817 每实例一选项,id=`skill:<heroId>:<skillId>`,拼接单源 `skillOptionId`)。点卡体 = 选中出牌(选中放大/目标段流转与锦囊同款),点主技名 = 开**技能全览**(池+已授对照,#605;每张卡只显本卡代表的技,全技对照在弹框)。主技名竖章使技能卡与锦囊的朱底标签章牌面一眼可辨。
- **独立冷却**:主动技发动记麾下槽位的 `lastFired`(键 = 技 id,与被动技同机制、各槽各账;`choices.ts` `skillCooldownLeft` 算剩余轮数),与锦囊的「每回合每标签一张」名额互不相干。发动过技后重算选项集,同回合仍有可用锦囊/其他就绪技则窗口停留(`settleJinnangExit`)。
- **出技是公开事件**:浮字 + `category:"skill"` 战报(detail 锚 `heroSkill owner/skill/kind/target`;城目标域另锚 `prop/tile`),与出牌同口径。命令 `useHeroSkill`(`authority.ts`):指向域/城目标域的技选定后进**目标段**(载荷 `jinnang-execution.ts` `PendingHeroSkill`,与锦囊目标段互斥;可「作罢」,不记冷却)。any 域(赈济)候选含自己——自选目标回归席位格单点:候选面随席位格候选装配,自机格的点击层即候选钮(旧「你」印候选钮随仪表条退役,#700),与对手席候选同口径(金圈呼吸/点选实金停持/再点取消/不可用灰置印原因)。城目标域(#1388 火攻)候选=**合法城清单**(谓词单源 `choices.ts` `heroSkillCityTargets`:距离 ≤5、城池等级>0、城主为他人),逐城携城名/城主/距离供点选,提交通道=目标城 tileIndex(选城呈现形制归 UI 交付票)。合法性(相位/持有/冷却/费用/目标)由引擎校验(`jinnang-execution.ts` `resolveHeroSkill`),UI 永不裁决。
- **结算纪律**:复用既有结算单点(火攻 = `defense.ts` `applyFireDamage` 定向火焰伤害,#1388;锦囊【火烧连营】的随机 demolish 结算单点 `demolishOnVictim` 保留归锦囊路);技能结算内**不派发时机**(与 `grantSkillCash` 的防连锁同口径——出技不触发他人的 CashLost/CashGained 被动技;火攻技路不派 PropertyDemolished/Lost,#457 口径);主动技**不可被识破**(不经宣布通道,`fireHeroSkill` 直结算,#229/#281 口径)。
- **快照/重放**:冷却(麾下槽位 `lastFired` 随槽位全量进快照,#785)、招贤候选预掷授技(`offeredHeroes` 行携 `skillIds` 随决策窗校准快照下行,#787)、目标段载荷 `pendingSkill`、擂鼓加成 `heroDiceBonus` 全量进快照(序列化单点清单 `snapshot.ts`);得将宣告事件 `heroRecruited` 事件体携本次授技 `skillIds`(权威态随事件下行,客户端折叠不重掷)。技能命令是普通 cmd 行,重放天然复现。技能选项不含他人私隐(名将/冷却/防御值/现金均公开),ADR-0016 投影无新增泄漏面。
- **bot/托管(含看门狗代开)**:bot 出技按净值贪心(`bot.ts` `heroSkillIntent`:火攻=合法城里定向择优——等级最高→购价(`purchasePrice`)最高→`tileIndex` 小,与人类同参数不按身份分档,#1388 统一原则;赈济体力 <70 自疗、擂鼓恒用);托管中的人类座位代驾(自助或看门狗代开,#591/[ADR-0028](../../adr/0028-takeover-is-autopilot.md))与 bot **同款出技**(#580 代打行为单源,原「代驾永不主动出技」口径退役)。

### scope 与触发留痕

- **scope**(技能属主与时机主体的关系,缺省 `self`;判定 `authority.ts` `scopePasses`):`self` = 属主是主体;`others` = 主体非属主;`any` = 主体不限;`actor` = 主体恰为当前行动玩家(多数现役挂点主体即行动者;回合外主体的时机已有 `PlayerBankrupt` 的破产者/`AssetsSeized` 的债主/`TurnSkipImposed` 的被跳者等,此时 `actor` 与 `any` 分化)。
- **触发留痕**:击发记 `category:"skill"` 战报,detail 含 `skillFire owner/hero/skill/moment/subject`——每次触发可审计、可重放(日志格式见 [`../对局日志.md`](../对局日志.md))。

### 冷却与派发

- **冷却实例化**:技能可带 `cooldown`(单位 = 轮;键 = `skill.id`,记于麾下槽位 `lastFired`);同名技跨玩家、跨将均为独立实例,**各槽各账**(两玩家同技、同玩家两将同技合法共存、互不相干;`skillReady` 判「距上次触发 ≥ N 轮」)。被动技现役仅华佗带 3 轮冷却;主动技全带冷却(3~5 轮,见上表),同用此机制。
- **确定性派发**:`dispatchMoment` 按「座位序 × 麾下槽位序 × 槽内已授技序(=池声明序)」遍历,同种子下联机各端派发次序完全一致。
- **三条纪律**:破产玩家的技能不参与派发;效果函数返回 false = 条件不满足,静默跳过(不记战报/冷却);效果内禁止同步再派发时机(派发深度 >2 直接抛错防递归),效果层收益(如技能给银 `grantSkillCash`)不再触发 `CashGained`——技能链不会自我放大。
