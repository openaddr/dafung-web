# 浏览器 e2e 分类表(#1165 审计)

浏览器 e2e(`e2e/*.spec.ts`)逐条分类审计:哪些用例是**浏览器在场的理由成立**的 UI 壳,哪些是**经浏览器绕路断言引擎/协议行为**的逻辑透过 UI。分类判据、删缩依据与落点核对过程见 [ADR-0056](../adr/0056-e2e-slimming.md);验证分层口径(无头层为主力 / 浏览器层为壳冒烟 / AI 浏览器自动化为探索性工具)见[开发与测试](../how-to/开发与测试.md)。

## 分类判据(细则在 ADR-0056,此处速览)

- **UI 壳用例**:断言面 = 布局几何 / 拖拽输入 / 横竖屏形态 / 可见性(锦囊·secrecy·横幅·弹层)/ 交互语义(点选·长按·二段确认·悬停)。浏览器在场的理由成立——无头层不持有 DOM 与演出面,替代不了。
- **逻辑透过 UI**:断言面 = 引擎结算 / 协议行为,只是经浏览器绕路取证。已由无头层(单测 / 无头整局两跑门 / 黄金台账 / bot 基准 / 协议故障注入)覆盖的标「已迁(落点)」;尚未迁移的标「应迁候选」(**只登记不迁移**,另开票处置)。
- 处置只有两种:**整删**(内容全为已迁逻辑且无 UI 壳价值)、**缩**(同 spec 内删已迁用例留壳用例)。拿不准一律归「留」,不硬删。

## 总账

- spec 文件 40 个,本票后**整删 0 个文件、缩删 3 个用例**(审计基线 131 → 现 128;逐条见下表「处置」列)。用例总数会随开发漂移,本文不追踪总数,只追踪分类与处置。
- 每例的引擎语义面若无头层已覆盖,表中「已迁落点」列给出;应迁候选(无头层暂无落点)单独登记于文末,本票一律不动。

## 应迁候选登记(只登记,不迁移;处置另开票)

引擎/协议断言面暂由浏览器 e2e 承载、无头层尚无落点的清单。迁移时机与落点由后续票定,迁移完成前**不得删例**:

1. **反应窗超时代发看门狗(reactionWait)**——`react-reaction`「超时兜底」与 `react-reaction-online`「超时代发」:窗内不应答 → 权威侧定时代发「不用」。候选落点:`scripts/room.ts`+`scripts/watchdogs.ts` 编排层直驱(`test/room.test.ts` 停摆看门狗先例)或 `test/protocol-online.test.ts` 反应窗场景。
2. **断线座位反应窗超时**——`react-reaction-online`「断线座位」:窗开即断 → 服务端超时「不用」、对局不冻结。候选落点:同上(断线 × 反应窗组合场景)。
3. **降噪口静默状态机**——`react-reaction`「降噪口」与 `react-reaction-online`「联机降噪口」:点「本回合不再询问」→ 当窗代发不用 + 同回合静默 + 换回合解除。客户端静默态属 app 层,候选落点:静默判定逻辑抽纯函数后进 `test/`。
4. **折叠器闭窗算术(#461 面)**——`react-reaction-online`「非应答端可应答」:校准快照污染 per-seat 投影导致误闭窗。候选落点:`test/event-fold.test.ts`(客户端折叠单测)。
