## 现行 knip 配置口径

配置单源 `knip.json`:入口 = index.html + 手工脚本表 + **test/e2e 全量(含 .tsx 测试入口)**;忽略 = `public/fonts/**`(静态资源)、`src/app/components/ui/**`(shadcn 底件,CLI 管理,导出即 API 面)、`extensions/**`(编译产物由 `src/*.ts` 经 esbuild 再生成,装载走 `import.meta.glob` 运行时消费,静态分析不可见)。**手工脚本/测试入口漏登记 = knip 误报死文件的惯因**(历次修正皆此因,补登记即归零)——新增 scripts/ 活工具随手登记。资产判死同理:**extensions 走运行时装载,knip 与静态 grep 双双不可见,判死前必查**;全语料核验用无过滤全扫逐条判词——排除式过滤词的 grep 会按文件名吞命中;MSYS grep 对 CRLF 文件 `-o` 输出尾带 `\r`,路径存在性判定前必须剥 CR,否则全量误报死路径。

## 豁免族判据

- `src/app/components/ui/**`:shadcn CLI 管理的底件,导出即 API 面,清理制造上游 diff 噪声。
- **「导出即协议文档」族**:game-events *Body 接口(经 `GameEventMap` 键控消费,knip 按名导入判未用)、fxStore *Fx 接口、snapshot/reaction-window 联机协议面类型——按 ui/ 底件同款口径豁免。
- 组件 Props/interface 未用导出价值低,随桶文件顺手处理,不单独立票。
- 有意别名不判死(STAMINA_MAX|STARTING_STAMINA 先例:夹紧上限 vs 初始赋值两个消费角色)。
