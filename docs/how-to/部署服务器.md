# 部署服务器

面向维护者:把联机服务器部署到一台 VPS 并日常发版。服务器设计动机与决策索引见[联机架构](../explanation/联机架构.md)。

## 认清拓扑

一台 VPS 两件套,对外只暴露一个域名:**Caddy**(:443)自动签发续期 Let's Encrypt 证书,HTTPS / WSS 反代到本机端口(WS upgrade 自动透传,免配 header);**应用**由 systemd 守护 `bun scripts/server.ts`(默认 :3000)——REST 大厅 + WebSocket 对战 + 同进程静态托管 `dist/`,网页与对战同源,客户端 `serverUrl = location.origin` 免填地址。

## 首次部署

### 备好服务器与域名

- 一台 VPS(下文以 `<你的 VPS>` 指代)与一个域名,域名 A 记录指向 VPS 公网 IP;VPS 上装 Bun(`bun --version` ≥ 1.3,原生跑 TS 无转译依赖,见 ADR-0009)与 Caddy 2。
- ⚠️ 域名是 `.cn` 且 VPS 在国内:对外提供 Web 需 ICP 备案,否则 80/443 可能被拦截;海外机器不受限。

### 拉代码并构建

```bash
cd /opt && git clone <仓库地址> dafung-web && cd dafung-web
bun install && bun run build    # 产出 dist/
```

### 写应用 env

建 `/opt/dafung-web/.env.app`(**与 SSH 凭据的 `.env` 是两份文件**,见「做日常运维」末条),只写与默认值不同的项;走反代时 `HOST` 收 `127.0.0.1`,应用端口只听回环、外网摸不到。全部变量见下文 env 表:

```
PORT=3000
HOST=127.0.0.1
```

### 装成 systemd 服务

`/etc/systemd/system/dafung.service`:

```ini
[Unit]
Description=dafung-web multiplayer engine
After=network.target
[Service]
Type=simple
User=dafung
WorkingDirectory=/opt/dafung-web
EnvironmentFile=/opt/dafung-web/.env.app
ExecStart=/usr/local/bin/bun scripts/server.ts
Restart=on-failure
[Install]
WantedBy=multi-user.target
```

### 配 Caddy 反代

`/etc/caddy/Caddyfile`(站点块写真实域名,Caddy 自动签证书):
```
dafung.openaddr.cn {
    reverse_proxy 127.0.0.1:3000
}
```

### 启动并验证

```bash
sudo systemctl enable --now caddy dafung
curl https://dafung.openaddr.cn/health    # 期望 {"ok":true,"uptime":...,"rooms":...}
```

再做真实冒烟:两台设备开网页建房 → 加入 → 开局走几手(玩法见[联机对战](联机对战.md))。

## 发布新版本

```bash
cd /opt/dafung-web
git pull && bun install && bun run build
sudo systemctl restart dafung && curl /health    # + 建房走一手冒烟
```

⚠️ **动了引擎/快照结构的发版,重启前先清盘**:`rooms/<房间码>.json` 启动时经 `restoreFromSnapshot` 恢复回内存房间,新代码读旧快照字段对不上,恢复即抛错、服务起不来。先 `mv rooms rooms.bak`(验证无恙后再删)再发版——本项目不做向前/向后兼容(见 AGENTS.md)。只改前端时换 `dist/` 即可,`rooms/` 不受影响。

## 配置环境变量

全部可缺省(默认值即下表);相对路径按 systemd `WorkingDirectory` 解析为绝对路径。变量名与源码常量同名,出处列即定义所在文件:

| 变量 | 默认值 | 用途 | 出处 |
|---|---|---|---|
| `PORT` | `3000` | HTTP + WS 监听端口 | `scripts/server.ts` |
| `HOST` | `0.0.0.0` | 监听地址;源码默认全网卡(局域网直连),走反代建议 `127.0.0.1` | `scripts/server.ts` |
| `ROOMS_DIR` | `./rooms` | 房间落盘目录:`<房间码>.json` + `<房间码>.events.jsonl`,启动自动创建并恢复 | `scripts/server.ts`(`scripts/room-persistence.ts`) |
| `STATIC_DIR` | `./dist` | 静态托管目录;缺目录时接口报「先 `bun run build`」 | `scripts/server.ts` |
| `LOGS_DIR` | `./logs` | 对局日志 `<gameId>.jsonl`(ADR-0014) | `scripts/server.ts` |
| `LOG_TTL_DAYS` | `30` | 启动清扫:mtime 超此天数的 `.jsonl` 删除 | `scripts/server.ts` |
| `JIYU_CONFIG` | `./public/config/jiyu.json` | 联机机遇配置,启动读一次、改后重启生效;缺文件/坏结构回退产品默认 `ENCOUNTER_PRODUCT_DEFAULTS` | `scripts/server.ts` |
| `DECISION_TIMEOUT_MS` | `120000`(`0`=关) | 决策停摆看门狗:真人座位超时未落子由 bot 接管 | `scripts/server.ts` |
| `STATE_FILE` | — | **已废**:旧文档名,现源码不读;房间目录用 `ROOMS_DIR` | — |

## 做日常运维

- **看健康状况**:`curl /health`(存活/运行时长/房间数);排障加 `GET /room/debug?room=<房间码>`(实时相位 + 事件尾巴);当前生效的 env 值 `curl /help` 看 `env` 字段。
- **管日志**:对局日志按局写 `logs/<gameId>.jsonl`,每手增量追加;TTL 清扫只在**启动时**跑一次,改 `LOG_TTL_DAYS` 需重启生效;重放校验见[对局日志](../reference/对局日志.md)。
- **看房间**:`rooms/` 里的房间(含进行中对局)重启自动恢复;损坏的房间文件启动时跳过并 `console.warn`,不拖垮其余房间。
- **分清两份 env**:服务器上的 `.env`(`server_ip` / `server_pwd` 等)是**你自己的 SSH 运维凭据,应用不读**;应用 env 是 systemd `EnvironmentFile` 指向的 `.env.app`,别把运维凭据混进去。
