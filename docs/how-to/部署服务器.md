# 部署服务器

面向维护者:把联机服务器部署到一台 VPS 并日常发版。服务器设计动机与决策索引见[联机架构](../explanation/联机架构.md)。

## 认清拓扑

systemd 守护 `bun scripts/server.ts`，在 VPS 本机提供 HTTP 大厅和 WebSocket 对战。部署范围到本机监听地址和健康检查为止。公网入口由运维者在 1Panel 管理。

安卓 APK 自带界面，在大厅「高级(服务器地址)」填入联机地址。开发网页可选择构建 `dist/`；房间和对战接口可独立运行。

## 运维约定

- 正式联机服务在单台 VPS 上运行一个服务端进程。需要重启时安排维护窗口，允许短暂停服。
- systemd 以 `root` 运行联机服务。
- 按 Git 发布标签部署服务端，并使用同一发版号的安卓 APK 验收联机。发版号单源见[文档规约](文档规约.md#发版)。
- 维护者选定窗口后发起升级，服务随即停机切换，现有连接会断开。同一发版号重启沿用房间目录。跨发版号升级使用空房间目录，旧房间数据留作回滚。
- 普通卸载撤除联机服务，保留应用配置、房间文件和对局日志。永久清除这些数据是独立操作。

正式服务端发布包的内容与构建约定见 [ADR-0072](../adr/0072-workspace-packages-and-server-artifact.md)。下文覆盖当前可用的源码启动流程。

## 首次部署（源码启动）

### 备好服务器

VPS 需要 systemd 和 Bun，运行时版本要求见 [ADR-0009](../adr/0009-bun-toolchain.md)。使用下方源码方式时还需要 Git。

### 取得源码

将所选 Git 发布标签与 Git 仓库地址分别赋给 `release_tag` 和 `repo_url`。Bun 直接运行 TypeScript，运行目录需含地图目录和扩展目录。

```bash
git clone --branch "$release_tag" "$repo_url" /opt/dafung-web
```

### 写应用 env

建 `/opt/dafung-web/.env.app`（与 SSH 运维凭据分开）。在本机部署时明确绑定 `127.0.0.1`，端口按 VPS 可用端口选择。全部变量见下文 env 表。

```
PORT=3000
HOST=127.0.0.1
```

### 装成 systemd 服务

确保服务能读取应用目录并写入 `ROOMS_DIR`、`LOGS_DIR`。核对 `ExecStart` 中的 Bun 路径与 VPS 实际安装位置一致。

`/etc/systemd/system/dafung.service`:

```ini
[Unit]
Description=dafung-web multiplayer engine
After=network.target
[Service]
Type=simple
User=root
WorkingDirectory=/opt/dafung-web
EnvironmentFile=/opt/dafung-web/.env.app
ExecStart=/usr/local/bin/bun scripts/server.ts
Restart=on-failure
[Install]
WantedBy=multi-user.target
```

### 启动并验证

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dafung
curl --fail http://127.0.0.1:3000/health
```

本机健康检查通过后，将实际监听地址交给运维者。联机入口可用后，用同一发版号的两台安卓 APK 建房、加入、开局，见[联机对战](联机对战.md)。

## 升级与回滚

1. 选定目标发布标签，在独立目录检出，核对 Bun、地图和扩展目录后再准备切换。
2. 到维护者选定的窗口后停止 `dafung`。保留上一版部署目录和 systemd 单元，备份应用配置、房间目录和对局日志目录，注明原发版号和备份时间。
3. 准备新版应用配置，将 `ROOMS_DIR` 指向新建的空目录，将对局日志复制到新版的日志目录。旧房间目录及其房间事件文件留在上一版数据中。
4. 将 systemd 单元的 `WorkingDirectory` 和 `EnvironmentFile` 指向新版，确认数据目录可写，再执行 `systemctl daemon-reload` 并启动。查询 `/health`，检查启动日志中的房间恢复情况，再用同一发版号的两台安卓 APK 建房、加入、开局。

验收失败时停止新版，切回上一版服务单元、应用配置及停服时的数据目录，再加载单元、启动并用上一版 APK 验收。新版运行期间产生的文件单独留存。

启动时，无法读取或解析的房间文件会告警并保留。房间恢复时抛错会告警、尝试删除对应快照，再继续恢复其他房间。`/health` 只报告进程存活、运行时长和房间总数。查看启动日志的恢复数量和告警，用 `/room/debug?room=<房间码>` 核对需要保留的房间。

## 卸载

1. 停止并禁用 `dafung`，将应用配置、`ROOMS_DIR` 和 `LOGS_DIR` 归档到部署目录之外。
2. 移除 `dafung.service` 和本服务的部署目录，执行 `systemctl daemon-reload`。
3. 检查 `dafung` 已停止、本机端口已释放且归档文件可取用。确需永久清除时，单独确认并删除对应归档。

## 配置环境变量

全部可缺省(默认值即下表);相对路径按 systemd `WorkingDirectory` 解析为绝对路径。变量名与源码常量同名,出处列即定义所在文件:

| 变量                  | 默认值           | 用途                                                                      | 出处                                               |
| --------------------- | ---------------- | ------------------------------------------------------------------------- | -------------------------------------------------- |
| `PORT`                | `3000`           | HTTP + WS 监听端口                                                        | `scripts/server.ts`                                |
| `HOST`                | `0.0.0.0`        | 监听地址，VPS 部署配置为 `127.0.0.1`                                      | `scripts/server.ts`                                |
| `ROOMS_DIR`           | `./data/rooms`   | 房间落盘目录:`<房间码>.json` + `<房间码>.events.jsonl`,启动自动创建并恢复 | `scripts/server.ts`(`scripts/room-persistence.ts`) |
| `MAPS_DIR`            | `./public/maps`  | 地图清单 `index.json` 及清单引用的地图 JSON                               | `scripts/engine-helpers.ts`                        |
| `EXTENSIONS_DIR`      | `./extensions`   | 扩展包目录，目录本身必须存在                                              | `scripts/server.ts`                                |
| `STATIC_DIR`          | `./dist`         | 开发网页静态目录                                                          | `scripts/server.ts`                                |
| `LOGS_DIR`            | `./data/logs`    | 对局日志 `<gameId>.jsonl`(ADR-0014)                                       | `scripts/server.ts`                                |
| `LOG_TTL_DAYS`        | `30`             | 启动清扫:mtime 超此天数的 `.jsonl` 删除                                   | `scripts/server.ts`                                |
| `DECISION_TIMEOUT_MS` | `120000`(`0`=关) | 决策停摆看门狗:真人座位超时未落子自动托管(ADR-0028)                       | `scripts/server.ts`                                |
| `STATE_FILE`          | —                | **已废**:旧文档名,现源码不读;房间目录用 `ROOMS_DIR`                       | —                                                  |

## 做日常运维

- **看健康状况**:`curl /health`(存活/运行时长/房间数);排障加 `GET /room/debug?room=<房间码>`(实时相位 + 事件尾巴);当前生效的 env 值 `curl /help` 看 `env` 字段。
- **管日志**:对局日志按局写 `data/logs/<gameId>.jsonl`,每手增量追加;TTL 清扫只在**启动时**跑一次,改 `LOG_TTL_DAYS` 需重启生效;归档口径见[对局日志](../reference/对局日志.md)。
- **看房间**:`data/rooms/` 里的房间(含进行中对局)重启自动恢复;损坏的房间文件启动时跳过并 `console.warn`,不拖垮其余房间。
- **分清两份 env**:服务器上的 `.env`(`server_ip` / `server_pwd` 等)是**你自己的 SSH 运维凭据,应用不读**;应用 env 是 systemd `EnvironmentFile` 指向的 `.env.app`,别把运维凭据混进去。
