# 扩将指南

从[版本协作](./开发与测试.md#版本协作jj一律先开工作区)建立工作区，再按扩展目标选择内置名将或运行时扩展包。

## 新增内置名将

1. 准备可用的立绘，按[素材登记与授权](../../apps/client/public/assets/CREDITS.md)归档来源。现有资源查[素材清单](../../apps/client/public/assets/manifest.json)。
2. 在[名将数据](../../packages/core/src/engine/heroes.ts)的 `HEROES` 新增 `HeroDef`，填写唯一编号、名字、称号、立绘 URL 和 `skillPool`。立绘在客户端素材目录下时，用 `/assets/heroes/<文件名>` 作为 URL。
3. 用局内招贤或手册核对立绘与技能池。授技规则见[名将与技能](../reference/rules/08-名将与技能.md)。

项目的[素材工具](../../scripts/fetch-asset.ts)支持通过 `--local` 导入本地素材，以及通过 `--wiki` 指定 File 页或原图链接。可用参数从 `bun scripts/fetch-asset.ts --help` 查看。

## 新增技能

1. 在[技能表](../../packages/core/src/engine/skills.ts)的 `SKILLS` 为新技分配唯一 ID，并在名将 `skillPool` 引用它。用现有的触发时机与效果时，填写对应参数即可。
2. 引入新效果时在[效果注册表](../../packages/core/src/engine/effects.ts)实现并登记。用引擎公开方法改变状态，说明可触发条件和效果参数。玩家主动确认的选择用既有决策通路。
3. 引入新时机时，在[时机注册表](../../packages/core/src/engine/timing.ts)的 `GameMoment`、`MOMENTS` 和相关上下文中登记，再从对应结算点派发。需等待应答时，提供可序列化的 `MomentContinuation`。见[时机框架](../explanation/时机框架.md)。
4. 按[本地验证](./开发与测试.md#按生产变更选择本地验证)核对授技、技能生效及需要恢复的决策状态。技能文案依 [ADR-0068](../adr/0068-moment-stages.md#技能文案)书写。

## 运行时扩展包

从[太史慈示例包](../../packages/core/extensions/hero-taishici/)复制布局。按[扩展契约](../../packages/core/src/engine/extension-contract.ts)编写清单和权威入口，默认导出 `skills`、`effects`、`heroes` 中需要的贡献。更新 TS 后，按[示例编译命令](../../packages/core/extensions/hero-taishici/README.md#从源码再生成编译产物)生成 JS 入口。

客户端在构建时纳入[公共扩展目录](../../packages/core/extensions/)的清单和入口，服务端从同一目录打包，安装后从发布包的扩展目录装载。联机客户端需要对应版本内的名将数据，成套构建与部署见[部署服务器](./部署服务器.md)。服务端可用 `EXTENSIONS_DIR` 指定扩展目录。自带立绘用客户端能访问的资源 URL。

扩展在权威端进程内执行，应选可信代码。包格式和注册冲突在加载时报告。能力边界与理由见 [ADR-0022](../adr/0022-ts-extension-packages-dual-run.md)。
