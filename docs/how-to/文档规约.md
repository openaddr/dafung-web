# 文档规约

## 信息放在哪

每条现行信息最多保留一处代码定义和一处文档说明。其他页面链接到负责解释它的段落。把可计算的事实放在声明、配置或注册表里。

| 读者的问题           | 内容的位置                                                                   |
| -------------------- | ---------------------------------------------------------------------------- |
| 怎么学会打第一局     | [教程](../tutorials/)串起一次实际操作                                        |
| 怎么办成一件事       | [操作指南](./)提供入口、步骤和成功判据                                       |
| 对局怎么算           | [规则手册](../reference/rules/README.md)按机制归档                           |
| 某个术语指什么       | [术语表](../../GLOSSARY.md)给出定名和概念边界                                |
| 为什么这么设计       | [设计说明](../explanation/)解释取舍，[决策记录](../adr/)保存当时的结论和依据 |
| 视觉和交互该是什么样 | [界面与音效设计](../design/)                                                 |
| 在哪里改代码         | [代码地图](../reference/代码地图.md)指向实现与相关文档                       |

在目的地提供完整信息，引用只写读者下一步需要查什么。新增页面前先找同一主题的现有章节，搬移时一并更新入链。ADR 和验收台账中的旧事实以当时的日期和提交为准，现行口径链接到对应章节。

## 随代码一起更新

改动公开规则或操作流程时，按[完成定义](../../AGENTS.md#完成定义dod)在同一 PR 对账。文案、流程和边界条件由评审核对。数值出处链接到代码文件并标明符号名，链接随文件移动一起更新。可从代码直接读取的表格优先生成。

- 对局人数和锦囊目录由 `bun run gen:rule-docs` 回填各自规则页；保持生成区标记，手写规则放在生成区外。
- 机器检查入口见[按生产变更选择本地验证](./开发与测试.md#按生产变更选择本地验证)。

## 文字与入口

中文文件名用于深层文档，入口与 ADR 用英文文件名。给玩家的入口放在 README 开头。活文档的源码引用优先用仓内相对链接，定位到文件与符号名。
