# 开发与测试

本页是命令与恢复入口单源；红线见 [AGENTS.md](../../AGENTS.md)，测试取舍见 [ADR-0065](../adr/0065-test-economics-browser-retirement.md)。迭代只跑受影响的无浏览器检查，最终收口一次完整默认池、构建和静态检查。

## 把项目跑起来

先安装 [Bun](https://bun.sh) 与 jj，确保命令在 PATH；安卓开发另备 JDK、Android SDK/NDK 与 Rust Android 目标，环境变量指向本机实际安装目录。

| 命令                                          | 用途与成功判据                                                            |
| --------------------------------------------- | ------------------------------------------------------------------------- |
| `bun install`                                 | 首次克隆或 bun.lock 变化后安装依赖；workspace 不继承 node_modules         |
| `bun run check:freshness`                     | 每轮开工/续作先跑；基线、依赖及冲突检查全绿再分析或修改                   |
| `bun run dev`                                 | Vite :5173 与开发引擎 :3001 同起；访问 5173，单机与联机同源，热更新       |
| `bun run play`                                | 构建当前快照并启动 :3000；代码变化后重跑，提示后刷新页面                  |
| `bun run serve`                               | 部署或真机联机服务，读取 dist/；前端变化先 build，core/服务端变化另需重启 |
| `bun run preview`                             | 在 :4173 预览生产构建                                                     |
| `bun scripts/command-log.ts -- bun run build` | 类型检查与打包均成功；单次辅助可复用当前 workspace 的有效产物             |
| `bun run tauri:android:dev`                   | 安卓真机联调                                                              |
| `bunx tauri android build --target aarch64`   | arm64 release APK；排查用 `--debug`，模拟器用 `--target x86_64`           |

`dev` 房间数据在 `tmp/dev-rooms`，生产在 `data/rooms`；`DEV_ENGINE_URL` 可改开发代理目标。`play` 已有服务时只更新构建；core 或服务端变化须先退出旧服务。构建只复用本 workspace 输入与 dist/ 签名均匹配的成功产物；`build:bundle` 不代替类型检查，裸 `vite build` 不生成复用标记。

安卓环境设置 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME`/`ANDROID_NDK_HOME`，PATH 含 platform-tools。用 `java -version`、`adb version`、`sdkmanager --version` 自检；Git Bash 调 sdkmanager 时用 `.bat`。APK 在 `src-tauri/gen/android/app/build/outputs/apk/` 下；release 产物未签名，安装前需 zipalign 与 apksigner 签名、核验。

改配色只改 `src/core/theme.ts`，随后 `bun run gen:theme` 生成 tokens.css。

### 发版

玩家可见机制或视觉变更合入后，合并会话自动发版；纯文档、测试、脚本基建不触发，边界拿不准则发。版本单源 package.json，制式 `YYYY.M.P`；先 bump 经 PR 合入，不建 CHANGELOG。

在主树空停靠且 `@- = master@origin` 时执行 `bun run release`；这是发布位置约定，不以 workspace 有没有 `.git` 判断。脚本构建、用 debug keystore 签名、核对版本、推 tag 并创建带 APK 的 GitHub Release。`--draft` 建草稿，`--dry-run` 只检查前置条件；完成后附下载链接。

撞版本/tag 即停；撞 `tmp/release.lock` 时先比较发布目标 commit：已包含本次变更则让位结束，否则等锁释放或顺延版本。锁超过 1 小时仅作为残锁候选，确认原发布已停止再清理。收口前有发布在途时只备票，不做 rebase。

## APK 设备冒烟

```bash
bun run test:apk --apk <APK绝对路径> --device <adb精确serial> --package <期望包名> --version <期望versionName> --out <新证据目录>
```

设置 SDK 后以 `adb devices -l` 查 serial，设备须已授权且为 `device` 状态。入口仅使用指定 APK/设备，`install -r` 会覆盖更新该包；不卸载、不清 app 数据、不清 logcat、不启动模拟器。输出目录须尚不存在。

通过表示 APK 包名/版本、安装后版本、启动 Activity、前台归属及进程连续性均匹配；证据含 APK SHA256、版本、日志、PNG 与 report.json。失败非零退出，保留已创建的证据；不把系统遮罩或进程重启算通过。

模拟器须从待验 commit 构建匹配 ABI 的新包：`jj describe` 定格后 `jj new` 留证据层，记录不可变父 commit，构建 x86_64，沿 zipalign → debug keystore apksigner sign → apksigner verify 签名。不要调用带发布动作的 release 脚本。以 aapt 与 package.json 核对包名/版本，交接记录 commit、variant、ABI、签名及复跑命令，大 APK 不入仓库。

工具回归、设备冒烟和人工原生验收分别报告。人工按 [#215 清单](https://github.com/openaddr/dafung-web/issues/215) 在横屏 844×390 检查手势、系统返回、键盘/viewport、Dialog、首 tap/滚动、Select、后台恢复与原生保存；物理真机未验时保持该票打开，模拟器启动不能替代。样例见 [APK 冒烟验收](../reference/APK冒烟验收.md)。

## 版本协作(jj;一律先开工作区)

### 日常工作区

主树是 jj colocated，其他 workspace 共享 repo store、各有工作副本与 node_modules/dist/tmp。当前 jj 0.47.1 的 workspace 可有 `.git` 文件；不要按“次级 workspace 一律无 .git”推断 git/gh 能力。gh 操作显式指定仓库，版本操作仍走 jj。

以下从仓库根执行；代号自行替换。`ws-new` 完成 add、fetch、起基到 master@origin、install 和创建 tmp，任一步失败即停，不复用同名残场。

```bash
ws_code=1469-example
bun scripts/ws-new.ts "$ws_code"
bun scripts/ws-run.ts "$ws_code" bun run check:freshness
bun scripts/ws-run.ts "$ws_code" bun test test/<相关文件>.test.ts
bun scripts/ws-run.ts "$ws_code" jj st
bun scripts/ws-run.ts "$ws_code" jj diff --stat
```

命令 cwd 每次可能重置：工作区命令经主树绝对路径的 ws-run，或显式设置 workspace 绝对 cwd；写盘路径也必须指向该 workspace。ws-run 找不到目录或 .jj 会报错，不退回主树；需要环境变量时在外层 `export`，它不解析 `VAR=x cmd` 前缀。

`ws-new` 默认从 master@origin 起基；串行规格任务由主线明确改到集成尖端，并核对不可变父提交，不能只凭主树 freshness 的 OK。每次落盘后先 `jj st` 快照和 diff 文件集对账，再做检查。

### 最终验证与 PR 收口

以下命令在**交付 workspace 根目录**执行，也可经 ws-run 派发。先整理格式、更新基线，确认 diff 仅本票内容；若 freshness 报落后，按下节恢复。合并前即使只落后 master 一笔也先重定基。书签使用 `codex/<票号>-<用途>`，已推或已交付的 change 继续编辑先 `jj new`。

```bash
bun run fmt
bun run check:freshness
jj st
jj diff --stat
jj describe -m '<变更描述>'
jj bookmark create 'codex/<票号>-<用途>'
```

已有书签则在文件集核对后 `jj bookmark move <书签> --to @`。差分与提取的端点从 `jj log` 取当前提交，不能拿主树 git HEAD 代表 @；change id 用于追踪变更，完整 commit id 用于固定快照。

验证基线必须是当前提交的祖先，最终收口用刚刷新的 master@origin。先 plan 看检查与理由；未知生产域用 `--profile <域>` 明确分类，只会增加检查。run 串行执行基础门与受影响领域门，每轮回执独立且保留实际退出码。

```bash
delivery_bookmark='codex/<票号>-<用途>'
validation_base=$(jj log -r master@origin --no-graph -T commit_id)
validation_receipt="tmp/validation/$(date +%s)-final.json"
bun run validate plan --base "$validation_base"
bun scripts/command-log.ts -- bun run validate run --base "$validation_base" --out "$validation_receipt"
bun run validate verify "$validation_receipt" --base master@origin --target "$delivery_bookmark"
```

只有 run 全部退出 0、回执状态为 passed、verify 通过才收口。回执绑定完整跟踪内容、**精确基线**及检查计划；改码、改基线或目标书签不同树都失效，须重新 plan/run，不能借物化目标树掩盖验证错树。回执默认落 workspace 的 `tmp/validation/`，自定 `--out` 也只许在该 workspace tmp/ 内。

最后一批编辑后再 `jj st`，紧贴收口生成全链文件清单，逐项核对最后修改的文件在列。清单临时文件放系统临时目录，不能把文件路径直接当 `--expect`：

```bash
jj st
expected_paths=$(mktemp)
jj diff --from master@origin --to "$delivery_bookmark" --name-only > "$expected_paths"
mapfile -t delivery_paths < "$expected_paths"
merge_args=()
for changed_path in "${delivery_paths[@]}"; do
  merge_args+=(--expect "$changed_path")
done
bun scripts/pr-merge.ts "$delivery_bookmark" --validation-receipt "$validation_receipt" "${merge_args[@]}"
```

各步骤非零即停；文件集对账以脚本“声明 M = 实际 N”为准，多出先拆，缺项查遗漏。pr-merge 刷新远端并用 master@origin 与目标书签复核回执；因此远端基线推进也会拒收旧回执。有效回执复用已通过的 build/定向慢例，避免重复跑；不提供回执时脚本仍会跑 build 与被改慢例，不能代替其余本地门。

pr-merge 负责 push、开 PR、按号 squash、核验 MERGED、清理书签及收账；`--create-only` 只开 PR。多提交链必须落在 master@origin 上才可自动归拢。主线按派单约定接收 describe 后的交付、检查文件集并 push，代理禁 push 时由主线推；派工前查[派单模板](../agents/派单模板.md)。

批次保持一个集成书签、master 上终树单提交：每票在集成尖端 `jj new`，主线 QC 后 squash 回并；master 漂移只 rebase 这个集成提交。自动化 squash 显式 `-m` 或设 `JJ_EDITOR=true` 避免后台等编辑器。动过整链 rebase 则 push 前查 `jj log -r '<链根>::<书签> & conflicts()'`，输出必须为空。

### 按触发条件恢复

- **freshness 红**：缺依赖先 install；网络错误修复后重跑，明确离线才加 `--no-fetch`。落后自己的远端先 fetch，纯快进时 move 书签到其 @origin，否则 rebase 到远端；master 过期则在交付 workspace 重定基。`--allow-behind` 仅用于明确有意分叉，不用于绕过合并前重定基。主树有他人活时让出，不操作其 @。
- **跨 workspace rebase/abandon 或提示 stale**：先 `jj workspace update-stale`；rebase 后用 `jj log -r @-` 验父链，跨树验证前核对 @ 的完整 commit 与目标尖端，防止陈旧树假绿。变基完成后才做分支级 diff，避免共享 master 前移造成假混入。
- **rebase 冲突**：在自己的工作区解冲突，`jj st` 后核对 diff；解析位于冲突父的子提交时，只 `jj squash <冲突文件>` 回并，不能裸 squash。分叉残枝先验归属，再按完整 commit id abandon；其他 workspace 空 @ 不碰。之后 update-stale，补受影响检查并重新验证收口。
- **pr-merge 中断**：先确认 PR 状态，再重跑同一命令；已合入会进入清理与收账。`--body-file` 相对调用 cwd 解析，用系统临时文件的绝对路径。撞上多个历史已合 PR 或超过一天的旧合并时换唯一书签；确认是本票恢复态才走手动清理。**核验 MERGED 后才删远端 head**，否则 GitHub 会关闭仍在途的 PR。
- **需手动收账**：在自己的 workspace 依次裸跑 `jj git fetch`、`jj bookmark move master --to master@origin`，再在自己的空停靠位 `jj new master`；每步验退出码，fetch 不接管道。主树空 @ 正常由 pr-merge 尾步前移；有活就让出。并行收账相撞不回移 master，fetch 后用 `jj log -r 'master@origin..<合并提交>'` 验空即已入祖先链，并抽查工作副本的合入内容。
- **需定点删远端分支**：在可用的 git 仓库执行 `git push origin --delete <书签>`；`jj git push --deleted` 会扫全仓待删除书签，先 `--dry-run` 核清单，避免误关他人在途 PR。
- **workspace 目录被删**：先 `jj workspace list` 与 `jj op log` 判形态，注册仍在则先 forget。已快照内容可 `jj workspace add --revision <快照change> <绝对目录>` 接回；未快照编辑不可恢复。被 abandon 的 commit 可先 `git show <commit>` 核实，再定点恢复文件。并行时避免整仓 operation restore/裸 undo，以定点 restore 恢复自己的文件。
- **编号待落盘**：fetch 后现查 ADR 目录与 tags，开工时未占用不代表仍可用。

### 工作区清理

只清自己建立的 workspace；批量清理逐个核 @ 与最近 op，非空或 24 小时内有操作的一律跳过，其他会话残场只报告。先保存证据、快照，再 `jj workspace forget <注册全名>`，用 workspace list 确认已忘记后才删对应绝对目录；短代号可能仅 Warning 却退出 0，不能靠 `&& rm` 判断。Windows 的 os error 5 先回查注册表，已 forget 则只补删目录；用原生 `cmd /c dir` 复核，避免句柄占用或 MSYS 缓存造成假已删。

杀进程纪律见 AGENTS；只处理本次拉起且已验名的进程。新文件快照上限由 repo 配置控制，拒收大文件时先判断产物是否应入仓库。

## 上下文与长命令输出

```bash
bun scripts/context-read.ts file docs/agents/issue-tracker.md --lines 1:20
bun scripts/context-read.ts issue 1464 --repo openaddr/dafung-web --body
```

文件与票面按需分页，每页最多 4,000 个 Unicode 字符，长行连续分页，`--lines` 含首尾行。Issue 默认元信息，正文、评论、子票分别加 `--body`、`--comments`、`--children`；续页按输出的 `--page` 参数。

Codex 默认取 `CODEX_THREAD_ID`，手动调用加本次独有的 `--session <标识>`。每次重读源；同会话未变页省略，确需重读加 `--again`。

长测试、构建与最终验证经 `bun scripts/command-log.ts -- <命令及参数>` 执行，参数含空格时按 shell 引号规则传入。完整 stdout/stderr 落系统临时目录，终端显示路径、退出码、耗时及有界失败尾部；失败退出码原样返回，全文按需交 context-read。交互服务 dev/play/serve 直接跑；两工具均支持 `--help`。

## 按生产变更选择本地验证

最终收口优先用上文 validate，不再手动重复整池。基础门为 lint 零 warning、check:fmt、build、完整 `bun run test`；格式修改在验证前完成。lint 包含 `check:test-boundaries`，阻止常驻浏览器入口复活。

| 改动范围      | 追加门                                        |
| ------------- | --------------------------------------------- |
| scripts       | `bun run typecheck:scripts`                   |
| core 行为     | `bun run check:core`、`bun run check:goldens` |
| 棋盘源码      | `bun run check:board`                         |
| 局长/破产机制 | `bun run check:sim-bench`                     |
| AGENTS        | `bun run check:agents-budget`                 |

共享类型变更先 typecheck 盘点消费点。验证器还按生产影响选择既有定向检查，plan 负责展示实际范围；修改含 DAFUNG_SLOW 的测试会选中该文件，不扩大成全慢池。

## 把测试跑起来

- **迭代**：`bun test test/<相关文件>.test.ts`，TSX 同理；scripts 定向加脚本类型检查。
- **慢例**：只有对应能力改动才 `DAFUNG_SLOW=1 bun test <相关文件>`；`bun run test:slow` 仅明确需要完整审计时手动执行。
- **稳定性**：固定种子、受控时钟与状态屏障优先。不可靠例按 AGENTS 删除；保留的确定性小修串行复验一次，不反复养台账。
- **真实 bug**：先在未修代码上跑红，保持 1–3 个直接回归；脚本/环境问题可留实际失败与修后真火。普通展示、文案、样式、重复数值及删除不补等价测试，不镜像实现。

### 关键组件接线

happy-dom 接线只守关键命令、状态及私密信息通路，真组件/控制器/store 真实装配；无真实排版，不能判像素。业务等待复用 `test/wiring/controlled-clock.ts`，在 act 内推进；先卸载和清理控制器/store，再恢复计时器，原生宏任务让步用 Bun.sleep。

### 独立双端与协议故障

`test/online/online-dual-run.test.ts` 用独立 Bun 进程、生产控制器/store 与真实 WS 守健康、原座恢复、自动重连、反应窗；公开状态四向对账，私密信息按各座验证。reset 只作隔离/清理，不帮助收敛；#1297 的 outcomeKind 豁免仅限既有 Playing 恢复边界。

传输/编解码/校准变化定向跑 `DAFUNG_SLOW=1 bun test test/online/protocol-online.test.ts test/online/server-cmd-error.test.ts`；持久化/快照重建另跑 `room-recovery.test.ts`。子进程用 `Bun.spawn([process.execPath, "scripts/server.ts"])`，隔离临时目录与端口，机遇配置用 `test/fixtures/jiyu-off.json`。

### 整局样本

`headless-whole-game.test.ts` 默认每图首个固定种子两跑与关键快照恢复。确定性、引擎公共状态或整局驱动变化才定向开启该文件完整语料；多 seed 不变量覆盖不为数量扩样本。

### 黄金台账(check:goldens)

`bun run check:goldens` 重跑固定语料对比 `test/goldens/<mapId>.json`，core 行为漂移即红，首漂定位图/seed/回合及字段。台账是摘要索引，格式与语料见 [ADR-0053](../adr/0053-goldens-ledger.md)。

红时先查首漂；需逐回合证据用 `bun run sim:digest -- <seed> --map <id> --json <path>`。确认行为变化符合意图并有定向证据后才 `bun run check:goldens:update`，差异与代码同 PR 评审；不能用 update 掩盖未知回归。

### bot 基准(check:sim-bench)

`bun run check:sim-bench` 跑固定 bot 矩阵，守终局、不变量、经济扫尾、局长中位与破产率区间，输出每图每座位档统计；格式与矩阵见 [ADR-0054](../adr/0054-sim-bench.md)。平衡敏感数值、机遇、地图目标变化按需 A/B；局长/破产机制变化必跑，动刀前先留基线。

未终局/经济断言失败须修引擎或语料；区间越界先确认是否符合变更意图，符合才 `bun run check:sim-bench:update` 并同 PR 评审 `test/goldens/bench-ranges.json`，不符合则修数值。未终局不能刷新区间。

### 用户明确要求的单次浏览器辅助

仅明确请求页面观察、截图对比或浏览器复现时使用 `scripts/shot.mjs`、`visual-compare.mjs` 或 frame/cost 探针，默认横屏 844×390；实现/修复本身不授权。场景不固化为测试或门槛，APK 视觉及设备交互仍由用户验收。

## 用确定性手段调试

### 注入骰子种子复现对局

用户手动复现可带 `?seed=12345`；无浏览器测试直接向引擎/控制器传固定 seed。

### 场景确定性

用固定 seed、引擎公共命令与 `core/planter.ts` 具名种植件构造前态；不复活字段 force，不以重钓随机场景掩盖回归。

### 读 window.__dafung 四钩子

明确请求的浏览器排查可读 registry 的 installDebugHooks：

| 钩子                           | 用途                         |
| ------------------------------ | ---------------------------- |
| `window.__dafung.snapshot()`   | store 引擎快照，含全座状态   |
| `window.__dafung.getEngine()`  | 引擎实例及公共方法           |
| `window.__dafung.controller()` | 当前 local/online 控制器     |
| `window.__dafung.sync()`       | 从引擎重灌快照以排查投影脱节 |

仅 dev 或显式启用桥键时注册；键名单源为 `src/app/fx/timings.ts` 的 `E2E_DEBUG_BRIDGE_KEY`，shot 在本次辅助中预置。手动生产排查可 `localStorage.setItem("dafung-e2e-debug-bridge","1")` 后刷新。

### 按语义标识定位元素

先查各屏 `testids.ts` 单源，不硬编码 testid 字符串；棋盘格为 `data-tile="N"`，棋子为 `.bv-token`。

### 真机取证：性能诊断包(ADR-0047)

主页「性能诊断」导出设备画像、历史对局日志与最近一局帧诊。新局覆盖旧帧诊，应及时导出；历史日志含未打完局，保底 30 天。联机对局日志在服务器 `data/logs/`，诊断包仍含客户端帧诊。

APK 用「复制帧诊」取小包，或「保存文件」经原生对话框存全量；「下载文件」仅浏览器。不要用锚点下载或全量剪贴板承载 APK 大包。

| 证据                           | 归因方向                       |
| ------------------------------ | ------------------------------ |
| LoAF script 占大头             | 演出队列/React                 |
| LoAF style/layout 占大头       | 主线程回流                     |
| LoAF/longtask 小但帧距整体右移 | 合成器/栅格                    |
| 卡顿按演出上下文聚簇           | 对应演出                       |
| loafSupported=false 且帧距长尾 | LoAF 盲区，改看帧距与档 3 深采 |

采样器每帧一次 push，LoAF 只回调慢帧，上下文每 5 秒读 store、零 DOM 查询，所有缓冲有界。

### 桌面帧率薄弱点检测：probe:frames

仅用户明确要求浏览器性能排查时 `bun run probe:frames`；报告不作断言或门槛，不能代替 APK 栅格与设备交互验收。
