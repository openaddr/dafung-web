# 开发与测试:从克隆仓库到 AI 自主迭代闭环

本页面向贡献者与 AI agent:把仓库跑起来,把三层验证(类型 / 单元 / e2e)跑稳,再用确定性手段(`?seed=`、`window.__dafung`、`data-testid`)调试对局,最后跑通「改码 → 验证 → 断言 → 回改」的自主迭代闭环。**本页是常用命令与跑法的单一事实源**;何时跑什么(分层验证纪律)见 [AGENTS.md](../../AGENTS.md)。

## 把项目跑起来

先装 [Bun](https://bun.sh),然后按需取用:

- `bun install` —— 首次克隆后,以及拉到 bun.lock 变更时。
- **开工前先跑 `bun run check:freshness`** —— 基线新鲜度检查:落后自己的远端、或落后 origin/master 超阈值即失败,防止在旧基线上分析/写测试/修已消失的问题(worktree 多票并行尤其易踩)。网络不通时它刻意失败——修网络重跑,确认离线工作加 `--no-fetch`。
- `bun run dev` —— **日常开发就这一条**:一条命令同起 vite(热更新,永远最新代码,http://localhost:5173)+ 权威引擎服务器(dev 专用 :3001,编排脚本 `scripts/dev.ts`),vite 把联机 API(`/room /ws /health /help`)反代到引擎,前端取 `location.origin` 同源直连——**开 5173 一个地址,单机联机都能玩,零 build 零配置**。引擎端口刻意错开 serve 的 3000(旧 serve 挂着也不打架),房间落盘 `./tmp/dev-rooms`,与生产 `./data/rooms`、e2e `./tmp/e2e-rooms` 互不踩;`DEV_ENGINE_URL` 可覆写代理目标。
- `bun run build` —— 类型检查(tsc --noEmit)+ 生产构建产出 `dist/`;**跑 e2e 前必跑**(e2e 两组 webServer 托管的都是 dist/)。
- `bun run play` —— **快照游玩线一条命令**(编排脚本 `scripts/play.ts`):build 定格当前代码进 `dist/` + 起权威引擎服务(http://localhost:3000,单机联机同源,打印局域网真机地址)。与 dev 的分工:dev 文件一动页面就变(开发用),play 只在跑命令那一刻快照、浏览器 F5 才换新——**想玩稳定版/不想被并行改动干扰就用它**。服务已在跑时只 build + 提示 F5(serve 现读盘,无须重启);改了引擎(`src/core/`)或服务端(`scripts/`)才需退出旧 serve 重跑。
- `bun run preview` —— 本地预览生产构建(http://localhost:4173),也是 playwright MCP 实机驱动的 PROD 入口。
- `bun run serve` —— 权威引擎服务(联机:REST 大厅 + WebSocket,http://127.0.0.1:3000)——日常想玩当前代码用 `bun run play`(build+启动一条命令),裸用 serve 只在部署/真机联机场景。静态托管 `dist/` 每次请求读盘、不缓存,但**构建不会跟着代码自动走**:serve 常驻时改码/拉码后要先 `bun run build` 再刷新,否则一直端旧页面——右下角构建戳(`v年.月.日.时分`,构建时刻)变旧即为此症;改了引擎(`src/core/`)或服务端(`scripts/`)还要重启 serve。

改配色:主题单源在 `src/core/theme.ts`(玄墨鎏金),Tailwind token 由 `bun run gen:theme` 生成 `src/app/styles/tokens.css`——改色后重跑生成,不要手改 tokens.css。

## 版本协作(jj 优先)

仓库为 **jj colocated**(.jj+.git 共存):**优先用 jj**,子代理协作走 jj workspace(正式通道,#537 试点已通过;git worktree = 逃生舱)。本机 jj 在 `C:\Users\ning\AppData\Local\Microsoft\WinGet\Links\jj.exe`(shell 需前置 PATH);**jj 命令只在主树跑**(git worktree 无 .jj;jj workspace 自带 .jj 可跑,见下段)。常用口径:

- `jj st` / `jj log` —— 工作副本即提交,改码自动快照,无需暂存区。
- `jj describe -m "..."` → `jj bookmark create <名>` → `jj git push --bookmark <名>` —— 开分支推远端三步(push 新书签必须显式 `--bookmark`)。
- **push 后该 change 视为只读**:继续改活先 `jj new` 起子票——工作副本即提交,赖在已推 `@` 上改会被 snapshot amend 进已推内容,下次 push 混进 PR;子票完成后 `jj bookmark move <名> --to @` 前推书签再 push。
- 大批次:集成分支书签(先例 `xuanmo-batch`),代理各自切分支,主线逐票 QC 并入,单 PR 入 master。
- **合入后收账两步**(等效 git pull):`jj git fetch` → `jj bookmark move master --to master@origin` → `jj new master`。收账前若主树 `@` 有未推送改动,先 `jj st` 确认归属——`jj new` 会把半成品定格成独立 change(不丢,但滞留成匿名 head)。
- 大文件:>1MiB 新文件默认拒收,repo 级已调 5MiB(`jj config set --repo snapshot.max-new-file-size`)。
- squash 合入后本地 change 自动消隐,无需手动 abandon(0.45 实测)。
- `jj git init --colocate` 在已有仓库上报「target repo already exists」但实际导入成功——验 `jj log` 为准,别重复 init(0.45 话术)。
- 派单场景口径(git worktree 三律/代理 jj 速查/集成分支协作):[派单模板](../agents/派单模板.md)「jj 配方」节;政策口径:[AGENTS.md](../../AGENTS.md)「版本协作」节。

**jj workspace 通道**——与 git worktree 平行的隔离通道(`jj workspace add ../dafung-web-ws-<用途或代号>`,一条命令建仓,#534 实测 1.9s,随用随建随删);派单身份:workspace = 正式通道(#537 试点已通过);git worktree = 逃生舱。workspace 自带 .jj(经相对链接共享同一 repo store),jj 命令在内可跑——不像 git worktree 必须回主树。运行条件(#534 实测,workspace `dafung-web-ws-verify` 六项全通):

- `bun install` 必做:node_modules 不继承,缓存热 ~15s。
- e2e 前必先 `bun run build`:dist 不继承(实测 17.4s 一次通过);`mkdir -p tmp` 同样先建。
- 构建与主树并行互不踩(「隔离即构建锁」同款),并行仅余 CPU 争用,预算各放宽 ~15%。
- repo 配置随 workspace 全量生效:EOL(eol-conversion=input)与 5MiB snapshot 守卫逐字一致且实弹验证。
- workspace 内无 .git,gh 探测不到仓库——gh 调用补 `-R openaddr/dafung-web`(或设 `GH_REPO=openaddr/dafung-web`)。

收尾 `jj workspace forget <名>` + `rm -rf`,谁建谁清;并行期 undo 定点纪律与主树停靠位约定见[派单模板](../agents/派单模板.md)「jj 配方」节「代理 jj 速查」。

## 把测试跑起来

- **单元**:`bun test`(bun:test),覆盖 `src/core/` 纯游戏逻辑,用例在 `test/`。
- **lint / 格式**:`bun run lint`(oxlint,0 warning 基线;配置 `.oxlintrc.json`,test/ 关非空断言两则)+ `bun run fmt`(oxfmt 写格式;配置 `.oxfmtrc.json`,`public/` 生成物不碰)。改完码先 `bun run lint && bun run fmt`;EOL 口径由 .gitattributes 统一(2026-10-05 #401 落地,检出恒 LF,fmt 不再批量重写行尾),`oxfmt --check` 全仓通过是隐性标准(基线幂等已证)。本仓库已移除 GitHub CI(2026-09-28 拍板:外部 CI 只会诱导空等与取证式复跑),验证责任全在本地分层纪律,门禁=PR 前本地全绿。
- **类型**:只改 `src/` 想快速查类型可单跑 `bun run typecheck`(build 内置同款);改了 `scripts/`(CLI + 服务器)再跑 `bun run typecheck:scripts`——scripts 走独立 tsconfig,主 build 不含。
- **架构门禁**:`bun run check:core`——core 纯度(红线 #1/#2)可执行检查,PR 前必跑;给红线**加新规则**时存量违规经 `bun run check:core:baseline:update` 登记进 `.core-purity-baseline.json`(指纹不带行号),门禁只对新增违规红,存量修复后清条目。
- **文档死链**:`bun run check:links`——全仓 md 内链(相对路径存在性 + GitHub slug 锚点;围栏代码块与裸词目标不查)。改名/搬目录/引用大扫除等文档重 PR 收口前跑一次,这是 DoD「全仓库无死链」的可执行口径。「新建文件先 `git add` 入跟踪集再跑」是 git 通道旧话术——#533 起脚本为 jj 单路径(git worktree 无 .jj 跑不了,jj workspace 内可用),jj 自动快照会收编新文件;磁盘有而跟踪集无 = gitignore 排除或超 snapshot 上限,报错会注明。
- **e2e**:`bun run test:e2e`(Playwright;runner 必须跑在 Node 上,勿迁 bun,原因见 playwright.config.ts 头注)。它自带静态 preview 与引擎服务器两个 webServer,都吃 dist/。
- **CLI 对局(LLM 演练线)**:`bun scripts/cli.ts <command>`——纯 CLI,每命令一进程、state 文件持久(默认 `data/cli-state.json`,`--state path` 覆盖),AI/LLM 可脚本化驱动完整对局(与 server 共用 `scripts/engine-helpers.ts` 与 state 格式)。定位:给 LLM 当对局演练台——`status` 吐 `prompt`/`choices`/`reaction` 三份机读现场,`auto` 把 bot 步一口气推完、停在人类决策点,人(或 LLM)按现场发命令。典型流程:

  ```bash
  bun scripts/cli.ts new --map huanyou --encounter jiyu --seats 2 --bot 1 --state data/cli-state.json  # 开局(参数面:--map/--difficulty/--starting-cash/--encounter/--reaction-window-ms)
  bun scripts/cli.ts auto-setup    # 自动选都到 Playing
  bun scripts/cli.ts auto          # 连续驱动 bot,轮到人类即停(stoppedBy:"human")
  bun scripts/cli.ts status        # 读 prompt / choices / reaction 决定下一步
  bun scripts/cli.ts roll          # 人类命令(或 cmd <json> 发任意 GameCommand)……循环到终局
  ```

  全 bot 局(`--bot 0,1`)可 `run-to-end` 一步跑完到终局;四相位机读命令 JSON 示例见 `cli.ts help`。

e2e 五个口径:

- **分层验证**:日常开发/工单收口只跑本工单相关 spec——`bun run test:e2e:one e2e/<相关>.spec.ts`(等价 build + 定向 playwright);flake 取证用 `npx playwright test <spec> --repeat-each=3` 定向三连,不跑全量。**全量 `E2E_WORKERS=4 bun run test:e2e` 每分支只跑一次,PR 前收口**;另:fmt 全仓收口(大改/多票合流后)单独成 commit,不混功能 diff(#401 口径)。
- **workers**:全量用 `E2E_WORKERS=4 bun run test:e2e`——2026-09-29 原生 Windows 重标定(81 例:W2=447s 且并发互踩挂例 / W3=265s / **W4=192s 全绿** / W6 起挂例 3-6 个且墙钟反升,W10=355s)。旧「稳态=2」系 WSL 环境标定,Windows 原生不适用。全量墙钟口径:**门禁=下方放行判据,墙钟只是预算参考 ~5 分钟**(2026-10-12,94 例插电态实测 4.3-4.9 分钟;192s 系 81 例旧标定),显著超预算先查环境(电池/新增后台负载)再疑代码;逐例时长并行下含水,不做逐例预算(见 #295)。
- **全量放行判据**(#463-#468 三批标定):全量有失败时,按「**两轮失败集轮间零重叠 + 全落已知族 + 存疑例 `E2E_WORKERS=1 bun run test:e2e:one` 同树复验**」定性放行;轮间复现同一例 = 真回归嫌疑,禁放行。本机常驻负载(后台 VPN ≈1/3 核)是真实测试水位,判据按此标定,不要求关环境。已知族按「spec:行 + 错误签名」登记于此并注明观察日期(加固落地即退役):react-reaction-online(8s 反应窗×看门狗赛跑,并发极敏感)、长链路联机全程例(react-online)、cutover 指纹通道例、quickStart「一手已自动走完」竞速(以上 2026-10-11 观察时点,晚于 #371 三处加固)、react-board「滚轮缩放」例(满载下缩放步进 toBeGreaterThan 不足;2026-10-12 观察:两轮全量零重叠 + `E2E_WORKERS=1` 单跑绿)。
- **时间倍率**:`E2E_TIME_SCALE`(默认 `0.25`)是 e2e 专用时间倍率:`e2e/fixtures.ts` 在页面加载前(addInitScript)把值写入 localStorage 键(键名单源 `src/app/fx/timings.ts` 的 `E2E_TIME_SCALE_KEY`),演出编排(骰子 / 横幅 / 行军 / bot 延时)按倍率加速,缩短测试墙钟;设 `E2E_TIME_SCALE=1` 回退全速。仅测试注入,生产与真人局无此键,零感知。联机 / 韧性 spec 用免注入的 `testUnscaled`——对局节奏由服务端驱动,客户端加速只会造快照洪流。
- **电源**:全量门禁跑在**插电**态——笔记本电池供电的降频会放大联机时序 flake 并显著拉长墙钟(2026-10-04 实测:同机同码,电池态挂 5-10 例、6-9 分钟;插电态 ≤1 例、4.3-4.7 分钟)。日常跑单 spec 无所谓。检查:`powershell -NoProfile -Command '(Get-CimInstance Win32_Battery).BatteryStatus'`——2=交流供电,台式机无电池恒插电;命令过 bash 传参须整体单引号(双引号内 `$b` 会被 bash 先吞)。
- **浏览器渠道**:平台条件化(见 playwright.config.ts)——Windows 用系统 Edge(`channel: "msedge"`,免下载);Linux/macOS 回退 playwright 自带 chromium,首次需 `npx playwright install chromium`(国内网络配镜像,否则 ECONNRESET)。
- **条件性缺失元素**:e2e 里对「可能不在场」的元素(如活跃席位卡——自身回合不出卡)禁用裸 locator 读:`textContent()`/`getAttribute()` 对缺失元素会挂等到测试超时,**`.catch()` 接不到**。要快照+DOM 比对时,收进单次 `page.evaluate` 里用 `querySelector` 原子采样(缺失即 `null`,顺带消掉快照与文本的跨拍竞态)。react-solo「三区数据一致」曾在单核 CI 必挂/快机器偶过,真根因即此(#269 取证)。

多个 agent 并行跑 e2e 时,按 agent 分配互不相同的 `E2E_STATIC_PORT` / `E2E_GAME_PORT` / `E2E_ROOMS_DIR` 做环境隔离(协议见 playwright.config.ts 头注)。jj workspace 派单(正式通道)同一用法不变——三件套在 workspace 内全量生效(#534 实测,房间文件实落 workspace 本地目录),与 git worktree 时代一字不差。

## 用确定性手段调试

### 注入骰子种子复现对局

URL 带 `?seed=12345`(`src/app/App.tsx` 的 `urlSeed()` 解析)即固定骰子序列,落格 / 抉择全程可复现,供 e2e 与手工调试。e2e 里用 `e2e/react-helpers.ts` 的 `quickStart(page, seed)` 一键开局;该文件还有 `pickCapital` / `snap` / `waitForSnapChanged` / `waitForEngine` 等共享工具,联机多客户端断言见 `e2e/react-online*.spec.ts`。

### 换图重钉:e2e 场景编排随图走

改地图的环序 / 布局 / 格数后,**只换 e2e 里的选择器不够**——场景编排(停靠点、种植位、骰走位)也钉在图上,换图即系统性失效(实锤:#476 首轮全量 12 挂,两棒重钉)。规矩:

- **自然骰一律显式钉死**:Bun 与浏览器 V8 的 sort 比较器调用数不同,依赖骰序的编排跨运行时必碎——用 `marchQueue` / `diceQueue` 种骰,不赌自然骰。
- **开局链核算**用 `bun scripts/sim-jinnang.ts <seed>`:海选种子、预览 draftOrder / 起手牌 / 首骰落点(draftOrder / 首骰 / 起手与实测一致;选都候选有已知系统性偏差,权威停靠点以 e2e 实测为准,见脚本头注)。
- 改完地图先 `bun run check:map-docs`(tileCount / docs 数值对账),再跑受影响 spec。

### 读 window.__dafung 四钩子

浏览器控制台或 Playwright 可直读完整游戏状态(钩子挂载于 `src/app/controllers/registry.ts` 的 `installDebugHooks`):

| 钩子                           | 用途                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `window.__dafung.snapshot()`   | zustand store 里的引擎快照(god view):`{ phase, turnPhase, round, activeIndex, players:[{cash, netWorth, position, …}] }` |
| `window.__dafung.getEngine()`  | GameEngine 实例,可直接调公共方法                                                                                         |
| `window.__dafung.controller()` | 当前 GameController(local / online),交互入口                                                                             |
| `window.__dafung.sync()`       | 手动从引擎重灌快照——怀疑 UI 与引擎脱节时排查                                                                             |

钩子有**双门禁**:仅 dev 构建注册,或注入 localStorage 桥键(键名单源 `src/app/fx/timings.ts` 的 `E2E_DEBUG_BRIDGE_KEY`;e2e fixtures 与 `scripts/shot.mjs` 自动预置)——生产构建零引擎改写面。手动排查生产问题时,先在控制台 `localStorage.setItem("dafung-e2e-debug-bridge","1")` 后刷新。

### 按语义标识定位元素

所有交互元素带 `data-testid`,常量集中定义在各屏的 `testids.ts`(单源),如 `action-buy|upgrade|skip|halt|continue|confirm|cancel`、`dash-cash`、`dice-face`;棋盘格用 `data-tile="N"`,棋子为 `.bv-token`。写测试先查对应屏的 testids.ts,勿硬编码字符串。(对局屏旧右栏挂点 `hand-panel`/`status-*`/`treasury-*`/`others-*`/`sidebar-*`/`scroll-jinnang-*` 已随布局重构 #253/#255/#256 退役,新挂点为 `topbar-*`/`seat-*`/`dash-*`/`actionbar-*`/`log-tab`/`pile-row`。)

## 跑通 AI 自主迭代闭环

1. 改代码(`src/` 或 `public/maps/*.json`)。
2. `bun run build && bun test` —— 类型 + 单元。
3. `bun run test:e2e` —— 浏览器端到端(含速战档全程巡检)。
4. 或用 playwright MCP 实机驱动(`localhost:4173` PROD / `5173+` dev)+ `window.__dafung.snapshot()` 读状态断言。
5. 失败 → 回第 1 步改,直至全绿。

**全程不变量**(速战档 spec 自动巡检,见 `e2e/react-solo.spec.ts`;任何违规立即失败,锁定回归):

- 现金非负(非破产玩家)
- 位置合法
- 身价非负
- 破产无残留
- 终局有 winner
