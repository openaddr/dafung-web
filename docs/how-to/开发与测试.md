# 开发与测试:从克隆仓库到 AI 自主迭代闭环

本页面向贡献者与 AI agent:开发迭代只做受影响的无浏览器验证,最终收口一次完整默认池、构建和静态检查。视觉与设备交互由用户在 APK 中验收。命令与跑法以本页为准,策略见 ADR-0065。

## 把项目跑起来

先装 [Bun](https://bun.sh),然后按需取用:

- `bun install` —— 首次克隆后,以及拉到 bun.lock 变更时。
- **开工前先跑 `bun run check:freshness`** —— 基线新鲜度检查:落后自己的远端、或落后 origin/master 超阈值即失败,防止在旧基线上分析/写测试/修已消失的问题(worktree 多票并行尤其易踩)。网络不通时它刻意失败——修网络重跑,确认离线工作加 `--no-fetch`。jj 化后不依赖 .git,**workspace 内可跑**;还会查主树占用(在主树跑时 @ 非空即红 = 有会话留活,见「版本协作」『主树口径』段)。
- `bun run dev` —— **日常开发就这一条**:一条命令同起 vite(热更新,永远最新代码,http://localhost:5173)+ 权威引擎服务器(dev 专用 :3001,编排脚本 `scripts/dev.ts`),vite 把联机 API(`/room /ws /health /help`)反代到引擎,前端取 `location.origin` 同源直连——**开 5173 一个地址,单机联机都能玩,零 build 零配置**。引擎端口刻意错开 serve 的 3000(旧 serve 挂着也不打架),房间落盘 `./tmp/dev-rooms`,与生产 `./data/rooms`、e2e `./tmp/e2e-rooms` 互不踩;`DEV_ENGINE_URL` 可覆写代理目标。
- `bun run build` —— 每次检查类型,再生成或复用生产产物 dist/。输入与产物摘要收据仅在打包成功时生成;单次辅助工具可复用该产物。`build:bundle` 只保证打包新鲜完整,不代替类型检查。
- **打包复用边界(#1434)**:本 workspace 的输入与 `dist/` 内容签名都与成功标记一致才复用。输入包括 `src/`、`public/`、实际含前端模块的 `scripts/`、Tailwind 自动扫描文件(含文档/测试)、入口、根构建配置/tsconfig、`package.json`、`bun.lock`、`.env*` 及 `VITE_*`/`NODE_ENV` 环境变量。文件修改/删除、依赖或产物变化都会明确重建;输入无法读取直接报错。开始类型检查或打包前先撤销完成标记,成功且输入未变才重写,失败/中断不会继续放行旧产物。标记只落本地 `dist/`,不跨 workspace 复用,不增加全局锁。直接裸跑 `vite build` 不生成此标记,下次正式入口会保守重建。
- `bun run play` —— **快照游玩线一条命令**(编排脚本 `scripts/play.ts`):build 定格当前代码进 `dist/` + 起权威引擎服务(http://localhost:3000,单机联机同源,打印局域网真机地址)。与 dev 的分工:dev 文件一动页面就变(开发用),play 只在跑命令那一刻快照、浏览器 F5 才换新——**想玩稳定版/不想被并行改动干扰就用它**。服务已在跑时只 build + 提示 F5(serve 现读盘,无须重启);改了引擎(`src/core/`)或服务端(`scripts/`)才需退出旧 serve 重跑。
- `bun run preview` —— 本地预览生产构建(http://localhost:4173),也是 playwright MCP 实机驱动的 PROD 入口。
- `bun run serve` —— 权威引擎服务(联机:REST 大厅 + WebSocket,http://127.0.0.1:3000)——日常想玩当前代码用 `bun run play`(build+启动一条命令),裸用 serve 只在部署/真机联机场景。静态托管 `dist/` 每次请求读盘、不缓存,但**构建不会跟着代码自动走**:serve 常驻时改码/拉码后要先 `bun run build` 再刷新,否则一直端旧页面;改了引擎(`src/core/`)或服务端(`scripts/`)还要重启 serve。
- `bunx tauri android build --target aarch64` —— **出安卓安装包(APK,唯一正式交付形态)**。环境四件套(用户级 setx,新进程生效):`JAVA_HOME=C:\App\env\jdk-17`、`ANDROID_HOME=C:\App\env\android-sdk`、`NDK_HOME`/`ANDROID_NDK_HOME=C:\App\env\android-sdk\ndk\27.0.12077973`,PATH 含 platform-tools;rustup 已装 aarch64/armv7/i686/x86_64-linux-android 四目标。`--target aarch64` = arm64 单架构瘦包,覆盖 2015 年后的现代手机;模拟器调试临时加 `--target x86_64`。**构建档位(#1060 起)= release 优化档**(.so 140→23.7MB,APK 154→27.6MB 实测;debug 档需显式加 `--debug`,仅排查用)。产物在 `src-tauri/gen/android/app/build/outputs/apk/universal/release/`(目录名随 CLI 布局走,2.11.4 实测落 `universal/` 而非目标名;包体 ABI 由 `--target` 过滤,实包仅含 arm64-v8a;release 档产物**未签名**,装机走 release 脚本内化签名或手动 zipalign+apksigner),版本单源 package.json(tauri.conf.json 经路径引用);新 shell 自检 `java -version && adb version && sdkmanager --version` 全通即环境在位(git-bash 里 sdkmanager 要带 `.bat` 后缀调)。真机联调走 `bun run tauri:android:dev`。
- `bun run release` —— **发版一条命令**(出包 → 签名 → tag → GitHub Releases 带 APK 资产,#894):版本单源 package.json(先 bump 走 PR 合入 master),远端 tag 查重 → `tauri android build`(release 优化档,#1060)出包 → **zipalign+apksigner(debug keystore)签名固化在脚本内** → APK versionName 与版本号对账 → `git tag v<版本>` 推远端 → `gh release create` 挂 `tmp/release/v<版本>-aarch64.apk` + `--generate-notes`。须在主树跑(workspace 无 .git,tag 通路不通)且 @ 空停靠、父=master@origin(树上内容=发布内容);旗标 `--draft` 先草稿、`--dry-run` 只跑前置对账。debug keystore 签名包可装、同机可覆盖升级;正式签名未配,配好再换 keystore。
- **发版时机(2026-11-01 拍板)**:玩家可见变更(DoD 清单口径:相位/数值/牌/事件/地图字段/操作流程/视觉通道)合入 master 后,**合并会话自动发版不等确认**——bump 走 PR 合入、主树 `bun run release`、发完汇报附下载链接,用户离开回来即有新包可测;纯文档/测试/脚本基建合并不触发,拿不准就发(多包无害)。**防挤兑三闸(多会话并行)**:①bump 单点——version 单源 package.json,两会话同 bump 必撞 PR;②tag 查重——同版本远端已存在即红(拿锁后还重查一次,堵「查重后被他会话发掉」的窗口);③发版锁——脚本内置 `tmp/release.lock` mkdir 原子锁(Git Bash 无 flock 的替代),撞锁红字让位「本次变更滚入下一版勿抢」,持锁超 1h 视为被杀残锁,删锁即接管。**撞锁先定性再让位(#990 实锤)**:读锁 holder 的发布目标 commit,若已含我方变更(比对快照是否在我最后合并之后)——让位即终结,内容已随对方版本走,勿改号再抢;仅不含时才让位等锁或顺延版本号(#991 实录)。

改配色:主题单源在 `src/core/theme.ts`(玄墨鎏金),Tailwind token 由 `bun run gen:theme` 生成 `src/app/styles/tokens.css`——改色后重跑生成,不要手改 tokens.css。

## APK 设备冒烟

`bun run test:apk --apk <APK绝对路径> --device <adb精确serial> --package <期望包名> --version <期望versionName> --out <新证据目录>` 只操作显式指定的 APK 和设备。先按上节准备 SDK,设置 `ANDROID_HOME`,用 `adb devices -l` 查 serial;设备须已授权并处于 `device` 状态。证据目录必须尚不存在。命令不选择另一台设备、不查找“最新 APK”,不启动模拟器、不清 logcat、不清 app 数据或卸载既有应用。

入口用 SDK 的 aapt 核对 APK 包名、versionName 与启动 Activity,记录 SHA256 和 versionCode;随后在指定设备 `install -r`,核对安装后版本,用 `am start -W`、包进程与前台 Activity 核对启动。启动后和截图后均核对 `mCurrentFocus` 归属本包,截图后进程还须与本次启动相同,不能把系统遮罩或进程重启当通过。观察后采集本包、本次设备起点之后的日志及原始 PNG。失败以非零退出,已创建的证据目录保留 `report.json` 中的步骤、命令输出与错误;不覆盖既有证据。缺少必填参数或证据目录不可创建时在 stderr 定位,不会生成通过报告。安装/升级会更新指定包,应选专用测试设备或确认该设备适合覆盖安装。

模拟器验收须从待验代码构建匹配 ABI 的新包。先 `jj describe` 定格代码,再 `jj new` 留出证据提交,记录不可变父 commit;在这个工作区执行 `bunx tauri android build --target x86_64`。release 未签名包沿既有 `zipalign` → debug keystore `apksigner sign` → `apksigner verify` 通路签名后再交给冒烟入口,不调用带 tag/发布动作的 `release.ts`。包名/版本以 aapt 与 package.json 对账,不能用旧 arm64 包冒充当前模拟器构建。证据报告与交接文档记录构建 commit、variant、ABI、签名核验及复跑命令;APK 大产物不提交仓库。

三种完成口径分开交接:工具实现完成以 CLI 回归和脚本门禁为证;设备冒烟通过以指定设备的报告、日志与截图为证;人工原生验收完成须逐项执行 [#215 安卓 WebView 清单](https://github.com/openaddr/dafung-web/issues/215)。标准横屏 844×390、真实手势、系统返回、后台恢复、原生保存及清单中的键盘/viewport、Dialog、首 tap/滚动和 Select 项分别登记证据或待验。模拟器安装启动通过不能替代这些检查,物理真机未验时保持 #215 打开。归档样例见 [APK 冒烟验收](../reference/APK冒烟验收.md)。本通路不扩展 [#1354](https://github.com/openaddr/dafung-web/issues/1354) 后置的 APK AI 桥或设备农场。

## 版本协作(jj;一律先开工作区)

仓库为 **jj colocated**(.jj+.git 共存):**一切会话(主线与代理)任何写盘改动一律先开 jj workspace**——正式通道(#537 试点已通过;2026-10-18 起扩大到主线,主树 @ 只做停靠位,见文末口径;git worktree = 逃生舱)。本机 jj 在 `C:\Users\ning\AppData\Local\Microsoft\WinGet\Links\jj.exe`(shell 需前置 PATH);jj workspace 自带 .jj 可跑 jj(git worktree 无 .jj,那才必须回主树)。常用口径:

- `jj st` / `jj log` —— 工作副本即提交,改码自动快照,无需暂存区。
- **正典模板行(基线指纹汇报可直接复制)**:`jj log -r @ --no-graph -T 'commit_id.short() ++ " " ++ description.first_line() ++ "\n"'` —— 模板整段单引号,`++` 与函数调用不得移出引号。
- **后台/无头 shell 跑 jj 的编辑器坑(2026-11-01 #945 实锤)**:`jj squash` 折入两笔都带描述的变更时会拉编辑器求合并描述(Windows 默认记事本),后台 shell 无人理会即挂死(实锤挂 25 分钟)。**跨机器/CI/新环境兜底配方**:跑前 `export JJ_EDITOR=true`——`true` 秒退 0 即原样接受预填(两段描述拼接)。**本机已全局关**(jj 用户配置 `ui.editor`,机器级不随仓走),本机自动化链可不带;交互想手写描述用 `-m` 或单次 `JJ_EDITOR=notepad <命令>` 覆盖。
- **diff/审查类工具的端点 = change 哈希**(`jj log` 取 hex,`git diff <基线>...<hex>`):colocated 下主树 git HEAD 停在 master 不跟 @ 走,拿 HEAD 当「当前改动」端点会得空 diff(2026-10-17 code-review 实踩)。**跨提交提取文件内容同理认 change id,不认 git hash**——jj 每次快照都重写 git hash,拿旧 hash 会提出旧版内容(2026-10-18 实锤:workspace 搬运提出重放前旧版);提取后 grep 一个关键标记自证。
- `jj describe -m "..."` → `jj bookmark create <名>` → `jj git push --bookmark <名>` —— 开分支推远端三步(push 新书签必须显式 `--bookmark`)。名 = `<票号>-<名>`(如 `738-retro-gates`)——票号前缀是撞历史分支名的保险:头分支名参与 pr-merge 恢复预检的全历史匹配,裸语义名(如 `retro-gates`)撞上几个月前旧 PR(#594 实锤)会被误判进恢复模式、删头分支关掉在途 PR(#753)。
- **push 后该 change 视为只读**:继续改活先 `jj new` 起子票——工作副本即提交,赖在已推 `@` 上改会被 snapshot amend 进已推内容,下次 push 混进 PR;子票完成后 `jj bookmark move <名> --to @` 前推书签再 push。
- **rebase 前后两查**(并行环境):rebase 类操作前先 `jj workspace update-stale`——stale 副本上 rebase 会**静默不生效**,只在后续命令吐 stale hint(2026-10-20 实锤:误判已 rebase,update-stale 又把 @ 复活成旧父,连环两坑);完成后回读父链(`jj log -r @-`)确认落位——命令回显的「Added/Modified files」只是工作副本材料化行数,不代表 rebase 已生效。**跨 workspace rebase/abandon 后,验证前两关:`jj workspace update-stale` + 核对 `@` 的 commit_id=目标书签尖**——在别的 workspace 跑 rebase 会让本 workspace 转 stale,陈旧树上 typecheck/bun test 照样出「全绿」(#712-#725 波两次实锤:验证跑在旧树出假全绿)。
- **分支级对账在变基落地后跑**:并行会话收账会把本地 master 书签推前(共享 repo store),behind 状态下 `jj diff --from master --to @` 会把并行提交反向计进 stat、得出假混入(2026-10-20 #650 收口实锤:36 文件幻影)——先 freshness/变基、后对账。
- **里程碑快照(2026-10-29 retro 实锤)**:jj **只在命令调用时**触发工作副本快照——Edit 工具/脚本的写盘不自动入库;写盘改动每里程碑跑一次 `jj st`(零成本),未快照内容在 workspace 被并行清扫/误操作时**不可恢复**(经济 v3 票实锤:未快照编辑随误删全丢整轮重做)。**被清 workspace 的恢复配方**:①`jj workspace list` + `jj op log` 分辨形态——注册表还在=仅目录被删(forget 没跑),`jj workspace forget <名>` 清注册后按需重开;②快照过的 change 永在对象库:`jj workspace add --revision <快照change> <同名目录>` 直接接回工作态(含描述);③rebase 撞冲突回滚:本版本无 `jj op undo`,用 `jj operation restore <rebase 前的 op id>` 整仓视图还原(实锤:他人票冲突不抢写,restore 后改走 GitHub squash)。
- **清扫工作区先验活(2026-10-29 两连实锤)**:批量清理前逐个看 `jj workspace list` 的 `@` 是否非空、`jj op log` 最近操作时间——**机械按注册表名单全清会误删活跃工作区**(清扫会话把带未快照改动的活跃 ws 一并 forget+rm,当日两连);`@` 非空或 24h 内有 op 的一律跳过,残枝等属主会话自清或下次大扫除复验。
- 大批次:集成分支书签(先例 `xuanmo-batch`),代理各自切分支,主线逐票 QC 并入,单 PR 入 master。
- **合入后收账**(等效 git pull):**`pr-merge.ts` 收口尾步自动做**——`jj git fetch` → `jj bookmark move master --to master@origin` → 主树**空停靠的 @** 前移 `jj new master`(jj 命令不依赖 .git,workspace 直跑;空 @ 无内容可折,防折写禁令核心不受影响,@ 有活不动让给在场会话)。手动通路仅剩网页合并/`--create-only` 后主线收口以外场合:同三条顺序,在自己 workspace 跑 fetch/move——收账的 `jj new` 会连 @ 一起运走,主树只许脚本尾步动空 @(2026-10-18 实锤:收口在主树收账把并行会话的工作副本连切两次);`jj new` 会把半成品定格成独立 change(不丢,但滞留成匿名 head)。**拔河条款(2026-10-19 实锤)**:手动收账与并行会话收账相撞(自己的 move 把 master 移到较旧位,或移完发现又被推进)——停手勿回移,fetch 后验自己的合并提交已入 `master@origin` 祖先链(`jj log -r 'master@origin..<该提交>'` 空输出即已入链)即让位,并行收账会把书签带到正确位置。**fetch 硬规(#628 实锤)**:收账语境的 `jj git fetch` 裸跑不接管道(退出码被 `| tail` 吞掉=静默失败,收账对着陈旧 master@origin 进行,@ 停旧头),非零即中止重跑;收账完抽查合并内容已在工作副本(一条 grep 即可),对不上=fetch 没落,先补 fetch 再动 @。**删书签定点删(#635/#655 实锤)**:手动删单个远端书签走 git 逃生舱(仅主树有 .git):`git push origin --delete <名>`——jj 0.45 的 `--deleted` 与 `--bookmark` 互斥,「定点删」在 jj 侧不存在;`jj git push --deleted` 是全仓扫尾(先 `--dry-run` 看清单),会顺推删其他会话本地已删的待清残枝——残枝若挂未合并 PR 即被连带误关(合并后的残枝被扫掉属设计内清理,pr-merge 尾步即此语义,无害)。
- **批次集成正典(2026-10-31 #898 批次 retro 实锤,终段烧 ~2h)**:多票批次的集成分支**不做多提交长链**——整链重定基时 jj 逐提交重放,中继态逐环物化冲突(push 三连拒、三方冲突、`.jjconflict-*` 物化树被快照收进提交),且 push 前不可见。正典=**master 上终树单提交**:集成书签恒指单提交,新票在其上 `jj new` → 完工 `jj squash` 回并(书签恒单提交);master 漂移即对单提交 `jj rebase -d master@origin`(重放要么干净要么一处,无中继环);批次收口再走「`jj new master@origin` + `jj restore --from <集成尖>`」出终树单提交开 PR(粒度历史留各票评论+op log,squash 合并终态一致)。**push 前置闸**:凡动过整链 rebase,先 `jj log -r '<链根>::<书签> & conflicts()'` 验零冲突——jj 只在 push 时才报中继冲突,反馈最贵。
- 大文件:>1MiB 新文件默认拒收,repo 级已调 5MiB(`jj config set --repo snapshot.max-new-file-size`)。
- squash 合入后本地 change 自动消隐,无需手动 abandon(0.45 实测)。
- `jj git init --colocate` 在已有仓库上报「target repo already exists」但实际导入成功——验 `jj log` 为准,别重复 init(0.45 话术)。

## 把测试跑起来

自动测试全部不启动真实浏览器;组件接线的 happy-dom 也属于此范围。取舍单源为 [ADR-0065](../adr/0065-test-economics-browser-retirement.md)。

- **开发迭代**:`bun test test/<相关文件>.test.ts` 或对应 TSX 文件;改 scripts 时定向加脚本类型检查。
- **PR 最终收口**:`bun run lint`、`bun run fmt`、`bun run check:fmt`、`bun run build`、`bun run test` 各执行一次。lint 已包含浏览器回归边界检查。额外领域门见 AGENTS,不重复跑单独的全仓 typecheck 与 build 类型阶段。
- **完整慢池**:`bun run test:slow` 仅在明确需要完整审计时手动执行;日常、普通批次和发版不自动触发。修改含 DAFUNG_SLOW 的测试或其能力时运行对应文件,不扩大到整个慢池。
- **稳定性**:固定种子、受控时钟和状态屏障优先。不可靠例默认删除;只有一两行确定性修复能根除且覆盖独有时保留。串行复验一次即可,不反复定性养台账。
- **回归证据**:真实 bug 的直接回归先在未修代码上跑红;不为删除或纯文档补测试,不镜像实现。脚本/环境缺陷保留实际失败与修后真火结果即可。

### bot 基准(check:sim-bench)

bot 对战基准 + 历史区间台账(票三):3 图(关中/中原/兖州,同黄金台账语料源)× 座位档 2/4 × seed 4001-4050 = 300 局全 bot 自对弈,**按需跑,不进默认门**(实测墙钟 ~23s)。stdout 出统计报告(每图每档:终局率 / 轮分布 min·p50·p90·max / 终局方式 / 胜者身价中位 / 破产率),平衡性调参前后各跑一次 A/B 就是现成对照。格式冻结与带宽口径见 [ADR-0054](../adr/0054-sim-bench.md)。

- `bun run check:sim-bench` —— 矩阵全跑 + 逐局断言 + 区间对账。断言四条:终局必须达成(finished=false 列 seed 清单即红)、零不变量违规(driveToEnd 守卫,引擎抛错原样上抛)、终态经济扫尾(netWorth 有限 / 非破产座位 cash ≥ 0 / 破产事件座位旗子落位)、局长中位数与破产率落历史区间(`test/goldens/bench-ranges.json`,越界报「图/档/实测 vs 区间」)。
- `bun run check:sim-bench:update` —— 按当前矩阵重算区间,打印新旧对比(不静默);遇未终局局拒刷(未终局的区间不可信)。

**何时跑 / 何时红**:改数值表 / 机遇目录 / 地图目标线等平衡敏感面之后跑;**影响局长 / 破产面的机制改动必跑(2026-11-07 拍板,#1165,与 AGENTS.md 门槛清单同口径)**;动刀前先跑一次留 A/B 基线。红 = 信号,两种红两种处置——①终局未达成 / 经济断言红 = 引擎或语料问题,回去修,update 盖不掉;②区间越界 = 平衡真漂了,**确认漂移符合预期**(对照本票改动意图)后 `bun run check:sim-bench:update` 重刷区间(台账 diff 与代码同 PR 入库);漂移不符合预期 = 回去修数值。「红了解决不了就 update」同上节口径,是绕门不是流程。

### 用户明确要求的单次浏览器辅助

只有用户提出页面观察、截图对比或浏览器复现时执行本次辅助;普通实现/修复任务不触发。可复用 `scripts/shot.mjs`、`visual-compare.mjs`、frame/cost 探针,默认移动横屏 844×390。临时场景不变成常驻测试,不接入开发、合并和发版门槛。视觉与设备交互由用户在 APK 中验收。

## 用确定性手段调试

### 注入骰子种子复现对局

URL 带 `?seed=12345` 固定骰流,供用户手动复现。无浏览器测试直接向引擎/控制器传入固定 seed,不依赖浏览器助手。

### 场景确定性

无浏览器测试通过固定 seed、引擎公共命令和具名种植件构造前态;种子漂移先核对规则变更,不通过重钓随机场景掩盖回归。

### 读 window.__dafung 四钩子

浏览器控制台或 Playwright 可直读完整游戏状态(钩子挂载于 `src/app/controllers/registry.ts` 的 `installDebugHooks`):

| 钩子                           | 用途                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `window.__dafung.snapshot()`   | zustand store 里的引擎快照(god view):`{ phase, turnPhase, round, activeIndex, players:[{cash, netWorth, position, …}] }` |
| `window.__dafung.getEngine()`  | GameEngine 实例,可直接调公共方法                                                                                         |
| `window.__dafung.controller()` | 当前 GameController(local / online),交互入口                                                                             |
| `window.__dafung.sync()`       | 手动从引擎重灌快照——怀疑 UI 与引擎脱节时排查                                                                             |

钩子有**双门禁**:仅 dev 构建注册,或注入 localStorage 桥键(键名单源 `src/app/fx/timings.ts` 的 `E2E_DEBUG_BRIDGE_KEY`;`scripts/shot.mjs` 在明确请求的单次辅助中预置)——生产构建零引擎改写面。手动排查生产问题时,先在控制台 `localStorage.setItem("dafung-e2e-debug-bridge","1")` 后刷新。

### 按语义标识定位元素

所有交互元素带 `data-testid`,常量集中定义在各屏的 `testids.ts`(单源),如 `action-buy|upgrade|skip|halt|continue|confirm|cancel`、`seat-cash`、`dice-face`;棋盘格用 `data-tile="N"`,棋子为 `.bv-token`。写测试先查对应屏的 testids.ts,勿硬编码字符串。(对局屏旧右栏挂点 `hand-panel`/`status-*`/`treasury-*`/`others-*`/`sidebar-*`/`scroll-jinnang-*` 已随布局重构 #253/#255/#256 退役;旧顶栏/仪表条挂点 `topbar-active`/`topbar-target`/`topbar-deck`/`dash-*`/`log-tab`/`mute-button`/`reset-view` 与托管钮 `autopilot-button` 已随 #700 全浮层骨架退役;「N 轮」chip 挂点 `topbar-round` 已随 #853 chip 退役,轮次断言走 `turn-capsule`。现役挂点为 `topbar-overview`/`settings-*`/`seat-*`/`hand-zone`/`pile-*`/`actionbar-*`/`log-drawer`/`turn-capsule`。)

### 真机取证:性能诊断包(ADR-0047)

桌面探针(CPU 节流)测不到真机体感;真机卡顿取证走**帧诊通道**——对局屏挂载即自动采样(rAF 帧距直方图 + longtask/LoAF 慢帧拆分 + 演出上下文快照),**主页「性能诊断」小字入口随时可导**(不绑对局屏——测试常不打完就退出;帧诊=最近一局定格,历史对局日志=IndexedDB 全量含未打完局),产 `dafung-diag-<发版号>.json`:设备画像(UA/DPR/视口/发版号)+ 全部历史对局日志(IndexedDB 归档全量,30 天保底内的含未打完局)+ 当前帧诊缓冲。帧诊只留**最近一局**(开新局被顶替,导出要趁早)。联机局的日志在服务器 `data/logs/`,不在诊断包里;帧诊部分照采(采样在客户端)。

APK 内导出通路(#1053/#1056 两次演进):**APK WebView 没有锚点下载**,点「下载」是死的;剪贴板装不下全量(安卓限长 ~~500KB+大串复制冻结主线程)。面板三钮按面分派——**「复制帧诊(推荐)」**=帧诊小包(帧诊+画像+省略局数,几 KB~~百 KB)进剪贴板,粘贴给开发者,真机归因主要吃它;**「保存文件」**(Tauri 面,dialog+fs 插件)=系统存储对话框落盘全量包(含全部历史日志),文件管理器自行取件,不怕大小;**「下载文件」**仅浏览器面。

拿到诊断包后的判读映射(证据签名 → 结论):

| 证据签名                           | 结论                                       |
| ---------------------------------- | ------------------------------------------ |
| LoAF 里 script 占大头              | 演出队列/React 侧(演出积压型)              |
| LoAF 里 style/layout 占大头        | 主线程仍有回流(渲染债)                     |
| LoAF/longtask 都小、帧距整体右移   | 合成器/栅格欠债(GPU 型,JS 无责)            |
| 卡顿事件按演出上下文聚簇           | 某类演出独,定点修                          |
| `loafSupported=false` 且有帧距长尾 | WebView 过老,LoAF 盲区,以帧距+档3 深采为准 |

采样器恒轻纪律:每帧 1 次 push、LoAF 只对慢帧回调、上下文 5s 一拍读 store(零 DOM 查询)、缓冲全有界——改采样器先守这条。

### 桌面帧率薄弱点检测:probe:frames(#1028)

仅用户明确要求排查浏览器帧率或性能问题时运行 `bun run probe:frames`。它输出一次观测报告,不做断言、不接入开发或发版门槛;桌面浏览器不能替代 APK 真机的栅格与设备交互验收。
