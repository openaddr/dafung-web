# 开发与测试:从克隆仓库到 AI 自主迭代闭环

本页面向贡献者与 AI agent:把仓库跑起来,把三层验证(类型 / 单元 / e2e)跑稳,再用确定性手段(`?seed=`、`window.__dafung`、`data-testid`)调试对局,最后跑通「改码 → 验证 → 断言 → 回改」的自主迭代闭环。常用命令清单以 [AGENTS.md §验证命令](../../AGENTS.md#验证命令) 为单一事实源,本页只讲什么时候用、怎么用对。

## 把项目跑起来

先装 [Bun](https://bun.sh),然后按需取用:

- `bun install` —— 首次克隆后,以及拉到 bun.lock 变更时。
- `bun run dev` —— 日常开发,热更新开发服务器(http://localhost:5173)。
- `bun run build` —— 类型检查(tsc --noEmit)+ 生产构建产出 `dist/`;**跑 e2e 前必跑**(e2e 两组 webServer 托管的都是 dist/)。
- `bun run preview` —— 本地预览生产构建(http://localhost:4173),也是 playwright MCP 实机驱动的 PROD 入口。
- `bun run serve` —— 权威引擎服务(联机:REST 大厅 + WebSocket,http://127.0.0.1:3000);纯单机开发用不到。

改配色:主题单源在 `src/core/theme.ts`(古风水墨),Tailwind token 由 `bun run gen:theme` 生成 `src/app/styles/tokens.css`——改色后重跑生成,不要手改 tokens.css。

## 把测试跑起来

- **单元**:`bun test`(bun:test),覆盖 `src/core/` 纯游戏逻辑,用例在 `test/`。
- **类型**:只改 `src/` 想快速查类型可单跑 `bun run typecheck`(build 内置同款);改了 `scripts/`(CLI + 服务器)再跑 `bun run typecheck:scripts`——scripts 走独立 tsconfig,主 build 不含。
- **e2e**:`bun run test:e2e`(Playwright;runner 必须跑在 Node 上,勿迁 bun,原因见 playwright.config.ts 头注)。它自带静态 preview 与引擎服务器两个 webServer,都吃 dist/。

e2e 三个口径:

- **workers**:本机用 `E2E_WORKERS=2 bun run test:e2e`——默认 workers 因 CPU 超载会成片超时,2 为实测稳态。
- **时间倍率**:`E2E_TIME_SCALE`(默认 `0.25`)是 e2e 专用时间倍率:`e2e/fixtures.ts` 在页面加载前(addInitScript)把值写入 localStorage 键(键名单源 `src/app/fx/timings.ts` 的 `E2E_TIME_SCALE_KEY`),演出编排(骰子 / 横幅 / 行军 / bot 延时)按倍率加速,缩短测试墙钟;设 `E2E_TIME_SCALE=1` 回退全速。仅测试注入,生产与真人局无此键,零感知。联机 / 韧性 spec 用免注入的 `testUnscaled`——对局节奏由服务端驱动,客户端加速只会造快照洪流。
- **浏览器渠道**:平台条件化(见 playwright.config.ts)——Windows 用系统 Edge(`channel: "msedge"`,免下载);Linux/macOS 回退 playwright 自带 chromium,首次需 `npx playwright install chromium`(国内网络配镜像,否则 ECONNRESET)。

多个 agent 并行跑 e2e 时,按 agent 分配互不相同的 `E2E_STATIC_PORT` / `E2E_GAME_PORT` / `E2E_ROOMS_DIR` 做环境隔离(协议见 playwright.config.ts 头注)。

## 用确定性手段调试

### 注入骰子种子复现对局

URL 带 `?seed=12345`(`src/app/App.tsx` 的 `urlSeed()` 解析)即固定骰子序列,落格 / 抉择全程可复现,供 e2e 与手工调试。e2e 里用 `e2e/react-helpers.ts` 的 `quickStart(page, seed)` 一键开局;该文件还有 `pickCapital` / `snap` / `waitForSnapChanged` / `waitForEngine` 等共享工具,联机多客户端断言见 `e2e/react-online*.spec.ts`。

### 读 window.__dafung 四钩子

浏览器控制台或 Playwright 可直读完整游戏状态(钩子挂载于 `src/app/controllers/registry.ts` 的 `installDebugHooks`):

| 钩子 | 用途 |
|---|---|
| `window.__dafung.snapshot()` | zustand store 里的引擎快照(god view):`{ phase, turnPhase, round, activeIndex, players:[{cash, netWorth, position, …}] }` |
| `window.__dafung.getEngine()` | GameEngine 实例,可直接调公共方法 |
| `window.__dafung.controller()` | 当前 GameController(local / online),交互入口 |
| `window.__dafung.sync()` | 手动从引擎重灌快照——怀疑 UI 与引擎脱节时排查 |

### 按语义标识定位元素

所有交互元素带 `data-testid`,常量集中定义在各屏的 `testids.ts`(单源),如 `action-buy|upgrade|skip|halt|continue|main|branch|confirm|cancel`、`hand-panel`、`dice-face`;棋盘格用 `data-tile="N"`,棋子为 `.bv-token`。写测试先查对应屏的 testids.ts,勿硬编码字符串。

## 跑通 AI 自主迭代闭环

1. 改代码(`src/` 或 `public/maps/*.json`)。
2. `bun run build && bun test` —— 类型 + 单元。
3. `bun run test:e2e` —— 浏览器端到端(含速战档全程巡检)。
4. 或用 playwright MCP 实机驱动(`localhost:4173` PROD / `5173+` dev)+ `window.__dafung.snapshot()` 读状态断言。
5. 失败 → 回第 1 步改,直至全绿。

**全程不变量**(速战档 spec 自动巡检,见 `e2e/react-solo.spec.ts`;任何违规立即失败,锁定回归):

- 现金非负(非破产玩家)
- 位置合法
- 身价非负
- 破产无残留
- 终局有 winner
