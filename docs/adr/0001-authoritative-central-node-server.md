# 权威引擎部署于中心 Node 服务器(单进程,内存房间)

联机对局的权威裁决跑在一台中心云 Node 服务器上:单进程、内存中按 roomId 持有各局引擎;玩家设备作瘦客户端经网络提交命令、接收快照。

放弃了 Cloudflare Durable Objects——它虽与"有状态单线程权威"模型高度契合、且 WebSocket Hibernation 对回合制很友好,但带来厂商锁定 + 本地 dev 与生产运行时不一致 + 额外学习曲线;选择了可移植、Node 原生、本地与线上一致的纯 Node 服务。也放弃了 P2P/WebRTC,因为它放弃了引擎的权威设计(可作弊、状态可分歧),与项目红线相悖。

当前为"小骨架":单进程 + 内存房间。横向扩展(多进程 + 外部状态存储如 Postgres/Redis)留作未来演进——因引擎已可序列化,扩容是局部改动(落盘换 DB、内存 Map 换按 roomId 取),无需现在引入。
