# ADR-0040: 棋盘双板拆分——静态底板与动态顶板分离,根除行军整板闪帧

状态:已采纳(2026-10-31,卓易通行军闪帧报告即席拍板,与 ADR-0039 同一治本路线的第二波)

## 背景

用户实机报告:角色移动时画面「闪一下,一瞬间城池全没只剩背景色」。本地桌面(含 swiftshader 软渲染 + CPU 节流,两轮 5300+ 帧 CDP 录屏)无法复现——桌面合成器栅格余量太大;但机制在代码层明摆着:

- 行军播放每帧写 token 的 `style.transform`(SVG 子元素)→ Blink 按整张 SVG 失效 → **每帧全板重绘记录+栅格**;fx 挂载卸载(浮字/铜钱/流光路径 append/remove,全在 SVG 内)同罪叠加;
- 真机(卓易通兼容层,弱 GPU/软件栅格,DPR3)栅格赶不上帧期时,合成器把未完成的光栅块按**纯色背板**显示 = 「城池全没只剩底色」一瞬间。#908 之前主线程被常驻动画打满、栅格长期欠债,行军一触发必闪——与报告吻合。

ADR-0039 已把常驻装饰迁出 SVG,但**逐帧写 SVG 的还有两户**:棋子行军(transform)与 fx(挂载/一次性动画)。栅格欠债的源头没拔干净。

## 决策

棋盘拆成**上下两张 SVG**(双板),按「动不动」分家:

- **底板 `#board`(静态层)**:defs/纸面/地形/驿道/城池。对局中只吃事件驱动的低频变化(归属/档位/宣告);手势(拖拽/捏合/滚轮)与落格点击全在本板。
- **顶板 `#board-tokens`(动态层)**:棋子/特效(#bv-fx)/流光(#bv-flow)。`pointer-events:none`(触摸穿透到底板),`absolute inset-0` 与底板同盒;viewBox 由 usePanZoom **同拍双写**(新增可选第三参 tokensSvgRef),两板像素永远对齐。
- 氛围层(ADR-0039)DOM 序居两板之上,不变。

行军逐帧失效范围从「整板(40 城+纸面+地形)」收缩到「顶板内数个元素」,重绘代价降几个量级;fx 的挂载卸载与一次性动画同样被圈进顶板——ADR-0039 缓办的「活动期 fx 污染」一并解决,无需 FxLayer 出 SVG 迁移。

## 消费点零改动的前提(实测核过)

`useMarch`(查 `#bv-tokens [data-token-player]` 与 `#bv-flow`)、`FxLayer`(读 `#board` 客户宽/viewBox/getScreenCTM——两板同盒同 viewBox,数值恒等)全是**全局 query 型消费**,换板不换码;e2e 读 `#board` viewBox 与 boundingBox 的用例(react-board/gesture 族)不受影响。

## 承认的取舍

- **两份 viewBox 状态**:同拍双写即无漂移窗口(单写者仍是 usePanZoom 的 view ref);代价是 apply 多一次 setAttribute(手势期每帧,纳秒级)。
- **顶板仍为 SVG**:行军 transform 写 SVG 子元素仍走主线程样式/布局(板内小树,实测够快);若未来仍观测到顶板瓶颈,再议棋子出 SVG 入 HTML(第三波,不在本票)。
- **tile 点击目标在底板、棋子在顶板**:视觉上棋子压城池,交互上棋子本就 pointer-events none(#30 前即如此),语义零变化。

## 验收

- 844×390 截图与单板版逐像素一致(选都定格帧,四旗/活跃环/光晕/微光全对位);
- 探针复跑(6x→4x 节流,seed 2026 托管整局):活动期 4x fps 中位 **38(27~44)**——ADR-0039 时 16~~33、最初 12~~23,DoD ≥30 达成;基线主线程占用 43%→29%;
- gesture 族 e2e 7/7 全绿(且各例耗时 16~~19s → 10~~15s,卡顿减少的副作用信号);board/seat-cells/setup/short-stage/warlords 全绿;bun test 926 pass 0 fail。

## 后果

- 正面:行军/特效逐帧失效与静态板彻底分家,真机「整板闪成背景色」的栅格欠债源头拔除;活动期帧率达标,ADR-0039 缓办项就此销账;
- 代价:board-area 内两个 svg 根(心智上「棋盘」= 两层,领域词汇仍是一张棋盘);手势双写的 setAttribute 一条;
- 后续:若真机仍有顶板级卡顿,第三波=棋子出 SVG 入 HTML 合成层。
