# 名将与技能解耦:技能池、招募授技与共享首批

日期:2026-10-30;设计定案档,实现随后续实现票(波及面清单见文末)。

## 背景与问题

名将自 #188/#360 体系定型起与技能强绑定:技能内联 `HeroDef.skills[]/active`、一将恰「1 被动 + 1 主动」、技 id 带将名前缀、招募即得全部技能。三条问题:

1. **招募无方差**:同名将在任何一局完全同体,招贤三选一的决策深度止于「挑哪张卡」,卡内零变化;招到手的将也毫无「我的周瑜与你的周瑜不同」的叙事。
2. **技能无法复用**:技与将一一对应、零跨将共享,「曹丕配擂鼓」一类跨将设计在数据上无位;技 id 的将名前缀把属主焊死在名字里,复用即撒谎。
3. **状态表达力到顶**:玩家侧内联整份 HeroDef、快照只存展示字段按 id 回查补全——「同一名将不同玩家持不同技能」在现结构下无法表达;这是本变革的硬前提,也是解耦的最大改造点。

## 决策

**技能升一等公民,名将与技能解耦为「池 + 授技」**:

- **技能池(Skill Pool)**:每名将声明**允许拥有**的技能集合(被动 + 主动;池内技 id 唯一,池可含多条主动技——逐字拍板表周瑜池即火攻+擂鼓双主动,逐技独立冷却)。技能独立成表,一条技可入多个名将的池——重叠是特性,不做去重守卫。技 id 去将名前缀,改技名拼音(`jixing`/`huogong`/…),全局唯一由表自证。
- **授技(Granted Skills)**:招募落定时从池中掷得子集:先掷基数 k(1..池大小均匀),再从池中均匀取 k——「至少一技」天然成立,零保底。授技终身不改(无补技通道);遣散释放不保留,该将回池后再被人招 = 重新掷。
- **招募预掷明牌**:招贤三选一在**候选生成时**即掷定各候选的授技,卡面亮结果再选将——授技结果直接影响选将决策,这是预掷的成立理由。机遇「义士来投/以宝换贤」与锦囊「求贤令」两路维持盲盒(今日即无选将决策,将身份落定一刻同掷授技);送将路明牌化若要做,属独立产品票。
- **同名技 = 独立实例**:跨玩家、同玩家跨将的同名技互为独立实例,冷却各自记账(内嵌麾下槽位,键 = 技 id、作用域限本槽);两玩家同技、同玩家两将同技均合法共存。
- **首批共享表**(零新增数值,3 条技改双属主,风味同系成对):周瑜{疾行、火攻、擂鼓}、曹丕{渔利、征辟、掷金}、张星彩{掷金、擂鼓、疾行}、华佗{青囊、赈济}。共享三条 = 疾行(周瑜↔张星彩)、擂鼓(张星彩↔周瑜)、掷金(张星彩↔曹丕),余五条单属主。**池大小 = 强度旋钮**:三将池 3(授技期望 2,与现状持平)、华佗池 2(期望 1.5,神医定位「池窄必得一手」)——不对称有意,数值留观。

配套拍板:

- **主动技无保底**:与被动技同池同 roll。「麾下有将无主动技」乃至「某局全场无赈济」是这套设计的戏剧性,真频发再谈保底。
- **麾下槽位**:玩家侧从内联 HeroDef 改为槽位 `{heroId, skillIds[], lastFired}`(冷却内嵌,实例天然独立;遣散整槽弃,无孤儿键);skillIds 按池声明序存,派发确定性重钉 = 座位序 × 槽位序 × skillIds 序。
- **协议面**:`heroRecruited` 事件体补 skillIds(预掷结果是权威态,客户端折叠不得自行重掷);`offeredHeroes` 行扩 skillIds,随决策窗校准快照下行(零新事件);快照麾下行改存槽位全量——麾下内容由展示字段升为游戏状态,「回查表补全」只保留技能定义一面。
- **UI 呈现**:卡面(紧凑 chips 与详情档)一律只显**已授技**;技能池全貌收进技能全览弹层,卡面保持紧凑。

## 后果

- **骰流契约变化**:候选生成期与送将落定新增授技掷骰消耗(基数 + 子集抽取),同 seed 重放整体漂移;骰流探针类测试按新契约改写。
- **方差即产品目标**:华佗期望微降、全体方差放大;强度整体账走 dogfood 留观,分布变体(保底/加权)不预先拍。
- **实现票波及面**:core = heroes.ts 拆表、model.ts 槽位、三送将路接同一授技单点、authority 派发重钉、choices、snapshot、event-fold/game-events;app = HeroCardFace 双输入、HeroPickScroll、SkillGlossaryDialog、HandRack、PileModal、SeatAttrModals、WarlordsOverview、testids;test = game/hero-skill/timing/huatuo/event-fold/extension-taishici 布场方式全改。
