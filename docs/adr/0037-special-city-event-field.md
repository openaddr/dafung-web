# ADR-0037:特殊城池制第一步——城池 event 字段与落格链序改造

日期:2026-10-31;规格源:#823(特殊城池制);实施票:#824(T1,engine+expand)。

## 背景与问题

盘面是 45 格双轨制:38 座城池 + 7 个不可购买的功能格(锦囊格×3、商市、税关、天命格、卧龙岗)。功能格不可购买、不可交互,是盘面上的「白踩之地」;格子价值密度被稀释,844×390 横屏下盘面高度被挤到极限。拷问会拍板**特殊城池制**:功能格这一格子类型整体退役,盘面上一切格子都是城池;特殊城池 = 普通城池全权(购买/升级/收租/入区/交易链)+ 落地固定事件。

本票(T1)只落引擎地基:城池格可选 `event` 字段 + 落格链序改造,以测试 fixture 图在引擎缝自证整链。地图迁移(环游图重排)、TileType 收窄、UI/编辑器随行分别归 T2–T5。

## 决策

### 1. 城池格可选 event 字段(`board.ts`)

`TileDef.event?: TileEvent`,值域 `"hero" | "jinnang" | "fate" | "market" | "treasure"`(`TILE_EVENTS` 白名单)。语义是「**这块地有没有固定事件**」——普通城无 event 是合法态,不是缺省兜底。

装载器校验(`board-loader.ts` `loadMap`,响亮报错):

- 值不在白名单 → 当场拒绝;
- **只许配在普通城**(`type` 缺省或 `"Property"`)上:功能格行为随格型承载(T3 才退役)、宝物城迁移归 T2,`event` 配上去即双轨指定,按数据 bug 当场拒绝;
- TileType 联合本票不动,旧功能格与 `TreasureCity` 原样并存(T1 过渡口径,已随 #826 收口退役)。

### 2. 落格链序:一处分流,两条链(`movement-flow.ts`)

- **普通城 = 机遇必出 → 交易链**(现状零变,ADR-0035);
- **事件城 = 固定事件 → 交易链**,随机机遇不掷。

分流判断单源:`isEventCity(tile)`(`event != null`),挂在两处落格机遇口——`settleMarchLanding`(普通行军落格)与拦停止步 `settleAmbushStop`(`reaction-window.ts`,拦停落格同门)。**必停都城截断不走此门**:驻跸是「都城通路」不是落格结算,机遇必出零豁免照旧(ADR-0035)。

固定事件结算 `resolveCityEvent`,四类复用现役实现(与旧功能格逐字同款——旧承载已随 #826 退役,等价对拍随之改钉事件城单边;抽件 `applyFateReputation`/`applyJinnangDraw`/`applyMarketSwing` 与招贤域 `tryRecruitHero` 单源共用):

| event      | 复用的现役流                           | 解毕走向                                         |
| ---------- | -------------------------------------- | ------------------------------------------------ |
| `hero`     | 招贤三选一明牌流(`recruitment.ts`)     | 解完续交易链;池空/麾下满员事件沉默               |
| `jinnang`  | 落格必抽 1(`drawJinnang`)              | 续交易链                                         |
| `fate`     | 声望泉 +20、±100 夹紧(`addReputation`) | 续交易链                                         |
| `market`   | 随机行情 ±100–200                      | settled 续交易链;清算/破产中断落格(与机遇同规则) |
| `treasure` | **本票不接线**(珍宝城迁移是 T2)        | 免掷机遇、直入交易链,字段值合法即可              |

交易链照旧走 `resolveProperty`(购地/扩军/珍宝交涉)与 `finishTradeChain` 收口;链上时机派发零变化。

### 3. 触发语义(规格拍板写死)

- **固定事件全员无差别(含城主)**;付费(过路租)仅访客;纯被动,城主无主动能力;
- **落己都城的「补给+招贤」通路不动**:都城即使带 event,走都城分流(驻跸截断与落都城两路都不进固定事件分支);
- **固定事件与机遇总开关脱钩**:引擎缺省 `enabled=false` 下事件城照常触发固定事件(普通城不掷)——固定事件是地的属性,不归机遇系统 `enabled` 开关管辖;
- 招贤池空或麾下满员 → 事件沉默,城照常买卖(交易链照走),没有折现补偿(与旧格型的沉默语义一致;机遇里的「折现」是机遇效果,不适用于地的固定事件)。

### 4. 续跑机制:`pendingCityEvent`(快照面唯一改动)

招贤型固定事件跨越命令边界(进 `AwaitingHeroPick` 等玩家作答),解完要回到**同一落格**的交易链——而固定事件分支挂在 `resolveLanding` 内部,盲目重入会二次触发。照 `pendingEncounterHalt`(ADR-0035)先例加引擎状态 `pendingCityEvent: boolean`:进三选一相位时置位,`resolveHeroPick` 解完据此续跑 `resolveLanding`,入口消费即清、直入交易链不再触发。同步事件(jinnang/fate/market)与沉默路径同走此标记统一续跑,生命周期与 `AwaitingHeroPick`/落格结算同栈或同相位,无悬挂态。

**序列化面**:`event` 走静态格定义,零序列化;唯一快照改动是 `pendingCityEvent`(interface + `SNAPSHOT_FIELDS` 各一条)——它是对局中途可被快照/联机广播的续跑标记,不随快照走则恢复后招贤解完丢交易链。

## 后果

- **行为变化**(fixture 图或带 event 的自定义图内):事件城落格不再掷随机机遇;四类固定事件替代;其余一切(普通城、旧格型、都城通路、机遇开关语义)零变化——既有测试不改全绿是 T1 验收线(#826 收口后旧格型不复存在)。
- **术语转正**:正典「珍宝城」「特殊城池」;「宝物城」「功能格」入 GLOSSARY `_Avoid`(均已废)。环游图真数据走旧格型的过渡已随 T2 迁移、#826 收口终结,规则页以新概念组织。
- **测试**:`test/city-event.test.ts` 新增(fixture 图 + 定种子):装载缝、落格链(机遇门/链序/访客城主/池空满员/探宝先行/快照续跑);旧「四类与功能格同种子等价」四例随功能格退役改钉事件城单边行为(#826)。
- **留观**:壳行数锁(`check-core-purity` shell-line-cap 1350)在本票基线前已超(基线 1358),本票净增 7 行——锁在基线上已是红,不属本票修;域逻辑零进壳(仅状态字段),后续治理票压回。

## 落地记录(2026-10-31,T3/#826 收口)

TileType 收窄、双轨拒绝删除、环游图七格原地转城已随 #826 全量落地:上文「只许配在普通城/TileType 本票不动」两条是 T1 时的过渡口径(现行装载器只接受唯一格型值,`resolveSpecial` 分流与 `TaxPaid` 表现态一并退役);四类「与功能格逐字同款」的对拍测试随功能格退役改钉为事件城单边行为。「功能格」「锦囊格」「天命格」「商市格」等旧格型话语词入 `check-retired-phrases` RETIRE 清单。

## 备选

- **直接收窄 TileType 并迁移真图**(否):那是 T2–T3 的活;T1 只落引擎缝,真图不动保证既有 e2e/守卫零扰动。
- **机遇门放在 `maybeApplyEncounter` 内部**(否):必停都城截断同走该函数,内部按落点分流会把「驻跸截断机遇必出」一并吞掉,违反 ADR-0035 零豁免;门必须挂在落格口、驻跸口不挂。
- **招贤城解完重掷一次固定事件分支**(否):pendingCityEvent 消费即清的续跑就是为此;重入式触发若无标记会死循环或双触发。
- **`treasure` 事件提前接线探宝前置**(否):规格点名 T2(链尾探宝拆除+前置是语义位移,须连真图迁移一起验收)。
