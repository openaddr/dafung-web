# ADR-0053: 黄金台账 + check:goldens 差分门禁(票二)

日期:2026-11-07 · 状态:已采纳 · 票:[#1162](https://github.com/openaddr/dafung-web/issues/1162) · 地图:[#1160](https://github.com/openaddr/dafung-web/issues/1160)(无头确定性 e2e 测试体系,wayfinder)· 前提:[ADR-0052](./0052-headless-deterministic-testing.md)

## 背景

票一落地了无头整局驱动器与逐回合状态摘要,但「游戏对不对」的常驻证据仍只有同机两跑(同 codebase 内自洽)——**跨版本行为漂移**(引擎/数值表/机遇目录/驱动器的任何改动改了游戏事实)没有任何机器门守着:改了行为的 PR 若无 spec 断言到,漂移静默入库。本 ADR 记票二:把固定语料的逐回合摘要定格成 jj 跟踪的黄金台账(test/goldens/),`check:goldens` 进程内重跑差分,首个漂移定位到回合并逐字段报 diff;漂移走「确认 → 评审 → update 台账」。

参考仓 vera20k 的 `.github/workflows/determinism.yml`(票一只认心智,本票正式借)。

## 参考与取舍

### 学了什么(照单)

| determinism.yml 的做法                                                              | 学到的                                                                                                              | 本仓落地形态                                                                                              |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 各平台跑 sim-bench 产 `hashes/<map>.txt`,compare job 用 `cmp` **全等对齐**,不等即红 | 门禁的判据是「产物逐位全等」,不是重新断言一批期望值——期望就是上次的产物本身;产物按地图分文件,天然并行、天然按图定位 | 台账一图一文件 `test/goldens/<mapId>.json`;check 模式重跑语料与台账逐位对齐,首漂即红                      |
| 分歧输出 `diff … \| head -n 4`——只给首分歧截头,不给全文                             | 差分报告的价值在**定位到点**,不在罗列;全文 diff 在长局里是噪声                                                      | 只报「首个漂移处」:图/seed/第几笔摘要(turn·round)+ 该笔逐字段 diff(哈希截头展示),fail-fast 不跑完剩余语料 |
| matrix 五平台 + wasm 各自产产物,compare 集中对齐                                    | 「产」与「比」分离:产物是中间件,门禁只吃产物对齐                                                                    | 产(重跑语料投影成台账记录)与比(逐字段对齐)分离;update 模式复用同一产路径,打印新旧差异后重写               |

### 什么不适用、为什么

- **CI 本体**:它活在 GitHub Actions(workflow_dispatch 手动触发、secrets 拉零售数据、跨 runner artifact 上传下载);本仓 2026-09-28 拆除 CI,验证责任全在本地分层纪律——门 = 本地 `bun run check:goldens`,PR 前跑,无远端闸。矩阵(五平台 + wasm)也不适用:本仓运行时单 Bun,同机确定性已由票一两跑门守着,台账门守的是**跨版本**漂移,不是跨平台漂移。
- **逐帧(逐 tick)粒度**:vera20k 是实时 RTS,帧是它的语义切分;本仓回合制,回合边界是语义自然切分点(ADR-0052 已定),逐帧摘要是噪声。
- **「证据非判决」口径**:vera20k 对比的是两套引擎(移植 vs 原版),分歧只是侦查线索;本仓同一引擎对台账重跑,分歧即「行为变了」的实锤,直接红——处置不是排查引擎,而是判读「这漂移是否符合本票预期」。

## 决定

### 台账格式(存储投影;摘要定义冻结口径见 ADR-0052)

- **一图一文件** `test/goldens/<mapId>.json`,内含 `{ format: 1, corpus: [{ seed, seats, digests: [...] }] }`,corpus 按 seed 升序;语料 = 票一同款(guanzhong/zhongyuan/yanzhou × seed 3001-3010 × 4 bot 座,机遇 = 产品默认,**不装扩展包**——与票一测试同口径,防名将池污染)。
- **每笔记录 = 内存 TurnDigest 的瘦身投影**:`{ round, turn, phase, turnPhase, activeIndex, isOver, rngState, logHash, logCount, stateHash, kinds: string[] }`。投影是显式逐字段(非展开),内存摘要加字段不会自动进台账——入库须 format 升版 + update,存储格式独立冻结。
- **kinds 不存事件正文**:stateHash 已对「快照全量 + 本回合事件批」钉死,事件正文入库 = 造第二事实源(违全仓纪律),且正文体积不可行(全语料逐回合全事件载荷会顶穿 repo 5MiB 快照红线);kinds 序列保留漂移可读性——多了/少了哪类事件、批长度变没变,一眼可见,定位足够。台账是索引,不是记录全文。
- **落盘排版**:骨架缩进、每笔摘要压成一行(紧凑 JSON)。首版全缩进排版实测最大单文件 4.2MB,贴 repo 快照 5MiB 上限;逐笔一行减半空白(最大 2.6MB)且台账 diff 中「变了的回合」逐行可见,评审性反升。JSON.parse 不挑空白,排版不是格式面。

### 门禁语义

- `bun run check:goldens`:进程内重跑语料,逐图逐 seed 逐笔逐字段对齐;**首个漂移即红**(exit 1),报「图/seed/第几笔摘要(turn·round)+ 逐字段 diff」。台账缺文件 / format 不符 / 语料(种子集、座位表)不符 / 记录字段集漂移 = 当场抛(零兜底——台账自身坏了要让门禁坏得响亮,不许静默放行)。
- `bun run check:goldens:update`:重生成台账;打印新旧摘要差异(逐图「N 笔中 M 笔不同 + 首漂位置」,新建/零差也明说),不静默。语义 = **确认漂移符合预期后的主动刷新**,不是「红了解决不了就 update」的橡皮章。
- 全绿汇总打印「N 图 × M 种子、总笔数、总耗时」;单局未终局(触回合上限)不拦——isOver 已入记录被钉住,漂移自会红,平衡判读归消费方(口径同 sim-batch)。

## 后果

- 任何 core 行为漂移(引擎、数值表、机遇目录、驱动器、摘要口径)从此在 PR 前必红——没有 spec 断言到的行为改动不再能静默入库。
- 有意行为变更多一步台账刷新(`check:goldens:update`),台账 diff 与代码同 PR 入库,行为变更在评审里显形。
- 票一测试头注的「先消灭源再谈台账」完成闭环:同机确定性(两跑门)与跨版本可追溯性(台账门)分层成立;票三 bot 基准、票四故障注入的确定性前提齐备。
- 已知边界:台账只钉语料内行为(3 图 × 10 种子),语料外漂移不红;语料扩容 = 改 SEEDS/MAPS + 全量重刷(update 打印语料差)。摘要素材里的墙钟/ts 已由 ADR-0052 排除口径兜住,台账不新增非确定面。
