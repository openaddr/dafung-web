# ADR-0025: 地图收敛——核心维护环游图

日期:2026-10-12
状态:已接受(2026-10-11/12 走查与移除过程中的两次用户拍板;施工 #476/#478)

## 背景

内置地图曾有三张:环游图(huanyou,默认图,#249 环序重排+#470 后加东西延伸列)、群雄逐鹿(sanguo,40→43 格手写图)、棋盘天下(chessboard,45 格,以 sanguo 环序为参照的生成脚本派生)。sanguo 的底部簇在 43 格密度下被走查证实**不存在让新卡牌完全无碰的落位**(#471 五轮定位迭代无解);chessboard 的生成脚本以 sanguo 为参照派生,自身布局表早已漂移(重跑即炸)。三张图意味着:每次机制变更(如宝物城并权、删辅路)要把数据、生成脚本、e2e 场景编排、文档数值改 N 遍;e2e 的场景编排钉在各自的环上,换图即系统性失效(实锤:#476 首轮全量 12 挂,两棒重钉)。

用户在 #471 走查中途与后续连续两次拍板:移除 sanguo、「往后核心维护环游这个地图」;随后追加移除 chessboard,「环游图就是它的上位替代,然后再修复遗留问题」。

## 决策

1. **移除 sanguo 与 chessboard 两张地图**(`public/maps/sanguo.json`/`chessboard.json` 及生成脚本 `make-chessboard-map.ts`),`index.json` 只剩环游图与中原图(zhongyuan,8 城极简图,仅维持现状)。
2. **环游图是唯一核心维护图**:任何新地图工作(机制调平/布局/数值)只对环游图;地图相关测试(单测引擎源、e2e 场景编排)长在环游图上是有意选择——它的每次变更都是有意识的,测试随之维护。
3. **环游图生成脚本自再生**:经济源从 chessboard.json 改为读 `huanyou.json` 自身,重跑零 diff 为验收口径;手改 `huanyou.json` 经济字段会被重跑抹掉(脚本=唯一事实源,设计如此)。
4. **换图重钉纪律**(沉淀至[开发与测试](../how-to/开发与测试.md)):改环序/布局后 e2e 场景编排随图重钉,自然骰一律 marchQueue/diceQueue 显式钉死;开局链海选用 `scripts/sim-jinnang.ts`;文档数值过 `check:map-docs` 对账。

## 后果

- 旧 sanguo/chessboard 对局存档与引用两图的房间数据作废(零兼容原则,无需迁移)。
- 中原图不参与新机制调平(用户明示维持纯买地极简定位)——给它加机制需另行拍板。
- 地图数值的文档对账有了机器守卫(`check:map-docs`),「改图忘改文档」从 review 抽查变为必红门禁。
- 选都候选池、环上格型分布等布局敏感的测试在换图时需要重钉——这是把维护成本从「N 张图」收敛到「1 张图」的代价兑付。

## 备选

- 保留 sanguo 并重排底部簇版面:#471 五轮定位迭代证实 43 格密集图无解,否。
- 保留 chessboard 但不再维护:僵尸图比没图更糟——玩家可选中、机制变更不覆盖、脚本再生已坏,否。
- 全收敛到单图(连 zhongyuan 也删):zhongyuan 的极简定位有独立价值(新手/快速局),用户明示保留,否。
