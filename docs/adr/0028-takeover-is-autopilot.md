# 接管即自动托管:单一开关,删接管状态域

联机代打此前有**两个平行的状态域**:自助托管的 `autoPilot` 集与「接管」的 `takeover` 集(#118 停摆/#380 保留窗写后者,房主 `/room/takeover` 端点也写后者)。行为策略在 #580 已归一(bot 同款,经 #587 合入),但状态与生命周期仍分立,产生三种不一致:节拍观测分叉(接管 0ms 直推 vs 托管 2s/步,本票归一)、解除路径分叉(被接管者无自助解除,夺回得断线重连)、生命周期分叉(接管重连即夺回,托管重连不清)。而房主 takeover 端点**从未接任何 UI**——生产上真实的非自触发源只有看门狗两道,双状态域是为已退役的保守口径与房主强令语义服务的残留机器。

故废弃双域,立**单一开关**:每个人类座位只有一个「托管」开关(`autoPilot` Set),`takeover` 状态域(集合/`{ev:"takeover"}` 事件/`takeoverSeat` 方法/`/room/takeover` 路由/room-record 字段)整体删除。

- **触发源两道,出处入日志**:玩家自助(`setAutoPilot`,可开可关)与看门狗代开(#118 决策停摆、#380 掉线保留窗到期,只开不关)。autopilot 观测事件与对局日志行带 `by: "self" | "watchdog"`——重放与审计可分辨开关是谁拨的;**UI 不区分**(「托管中」同一徽章,「收回」是唯一解除按钮,状态表达原则)。
- **重连不动开关**:重连(token 归座,ADR-0005)不再清任何代打状态;被托管的人回来点「收回」即拿回控制。替代 ADR-0002 的「重连即夺回」——夺回不再需要断线重连这种别扭方式。
- **房主代开退役**:ADR-0002 给房主的出口只剩「解散房间」;保留窗、停摆看门狗照常兜底,无需第三只手。
- **ADR-0002 核心保护不变**:掉线默认冻结 + 保留窗口期不代打(「朋友手机闪断不应被 AI 替打一手」)原样成立——保留窗到期才代开托管,窗口内座位照样冻结停摆。

放弃的替代:保留 takeover 作纯别名(双域同构即双倍生命周期维护);看门狗直接驱动而不落状态(重连后无从知道该座位在托管,「托管中」徽章与一键收回都失去依据);UI 区分 self/watchdog 出处(观战者无需理解托管来源,机读日志已足)。
