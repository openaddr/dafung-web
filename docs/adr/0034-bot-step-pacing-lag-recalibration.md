# ADR-0034:bot 步进配速与落后判据再定标

日期:2026-10-28
状态:已拍板(2026-10-28 实机报告 #730,诊断台架 A/B 臂实测;用户拍板「接受 bot 更慢的节奏,要玩起来正常、看得清」)

## 背景

实机报告两症状(#730):①单机 bot 回合瞬间结算、没有移动过程;②演出还在播其他玩家的回合,引擎已到我的回合,「出牌/不出」按钮提前出现。

诊断台架复现(seed 1 可复现,真链路 LocalController→SnapshotEffects→LagCalibrator,五个演出叶子换时长忠实 mock,`test/solo-presentation-regime.test.ts` 的前身):75s 普通局(人类托管自走)中,追帧×3 顶格常开、**吸附 4 次**,积压从未清零(末拍欠 14 批/批龄 27s),人类决策点采样 116/116 压着未播旧批。症状①=吸附整块作废;症状②=恒定积压叠加 ADR-0029 §4 的设计口径(决策 UI 只等本座位演出,不等全局排空)——积压恒在时,设计口径的观感即「按钮出来了我还在看别人走棋」。

病根三层:

1. **bot 产出零配速**:`bot-driver.ts` `stepDelayMs` 只给 autoPilot 集配速(ADR-0028 托管 2s/步),bot 座位恒 0ms 连锁——ADR-0029 §3 判据基调「产出端节拍已由 ADR-0028 收口为单节拍,播放侧治理无需产出端配套」的前提**只对托管成立**,bot 是漏网的。
2. **演出厚于产出**:每批演出 1x 播放约 3-5s;对照臂(bot 并入 autoPilot 集 2s/步)积压收敛到欠 2-4 批但仍发散——产出端不配速,欠账是结构性的。
3. **判据水位低于正常局**:LAG(gap≥3 批/批龄 10s/连超 4 吸附)在正常局水位之下——开局 4.6s 即触发追帧,欠 3 批/批龄 4.9s 即可凑满连超进吸附;应急机制成了每局常态。

## 决策

### 1. 产出端补课:bot 步进配速(`BOT_STEP_MS = 3000`)

bot 座位每步决策间隔 3s(`src/core/timings.ts` `BOT_STEP_MS`,权威节奏单源,单机/联机同表同值,不吃 E2E_TIME_SCALE)——ADR-0028 单节拍口径的自然延伸:托管替人玩 2s/步「节奏像人」,bot 是背景演出,节奏 ≥ 托管(可读底线,`choreography-invariants` 钉 `BOT_STEP_MS ≥ AUTOPILOT_STEP_MS`)。数值定标:诊断台架 3000ms 下普通局**追帧/吸附零触发、人类决策点零旧批采样**(40-75s 窗,末拍 gap=1=健康尾流)。

这修订 ADR-0029 §3 的前提句:「产出端节拍已由 ADR-0028 收口」改为「已由 ADR-0028(托管)+本票(bot)收口」;追帧/吸附的语义、观感全静默口径、判据挂点(出队点)全部不动——治理的是同一件事,只是普通对局从此**够不着**校准线,校准回归「掉线追平/全 bot 观战级持续发散」的本位。

注入通道(选项家族先例:decisionTimeoutMs/reactionWindowMs/retentionWindowMs 全是「缺席=关」):

- `RoomRegistryOptions.botStepMs`:0/缺席 = 无配速(**bun 测试缺省**,既有用例预算按 0ms bot 连锁书写);
- 生产装配层显式传 core 常量:单机 `local.ts` 解析链 `SoloRoomConfig.botStepMs ?? e2e localStorage 键 ?? BOT_STEP_MS`;联机 `server.ts` = env `E2E_BOT_STEP_MS` ?? `BOT_STEP_MS`(显式 "0" = 关);
- e2e 默认关:playwright server env 与单机 fixtures 默认 "0"(隔离,既有 spec 墙钟零变化);要验配速行为的用例经 env 显式开启。

### 2. 判据再定标:LAG 阈值抬到正常局水位上

`gapBatches` 3→**5**(配速后健康水位=在播 1-2 批的回合内尾流;差 5 批≈一个完整 bot 回合未开播才追帧)、`ageMs` 10s→**20s**(队列头等待 2-3 批×播放≈6-10s 的 2× 余量)、`consecutiveForSnap` 4→**6**(3× 顶速连播 6 块≈10s+ 仍追不上才是结构性发散);倍率域 1.5-3 不变。口径不变:主尺=到达序游标差(机器时间)、分类非布尔、连超才吸附、回落归零。

## 后果

- **玩家可见**:bot 回合从「毫秒级瞬结+跳块+常开加速」变为逐拍可读(每步 ≤3s 间隔+演出 1x 跟播,轮到你时棋盘已追平);对局墙钟变长(拍板接受)。回填 rules/03(回合节奏)、rules/10(数值总表)、GLOSSARY「产出配速」。
- **修订**:ADR-0029 §3 前提句(见决策 1);ADR-0028 的「单节拍」语义扩展覆盖 bot 座位(数值独立双常量)。
- **测试**:`solo-presentation-regime.test.ts` 新增(40s 实速稳态钉子:追帧/吸附/决策点旧批三零,配速坏掉 ~5s 内转红);`bot-step-pace.test.ts` 新增(配置→驱动链接线);`catchup.test.ts` 场景构造改参数化推导(K ≥ gap+snap,连超长度=K−gap+1);`e2e-time-scale.test.ts` 恒等快照同步。**死亡常量清除**:`fx/timings.ts` 的 `BOT.stepDelayMs` 与 `AUTOPILOT.idleMs`(#398 单机统一后零生产消费,仅快照测试钉着「>0」的空壳,#730 清算)。
- **留观(不在本票扩面)**:托管/人类 autoPilot 仍 2s/步,长托管局仍可能进浅追帧(1.5x)——配速落地后真机复测再议是否同步抬 `AUTOPILOT_STEP_MS`。

## 备选

- **只抬阈值不动产出**(#730 选项 B,否):A 臂数据证明欠账结构性发散,吸附更少但每次跳更多,观感本质不变。
- **决策 UI 落后缓弹/提示**(#730 选项 C,否/缓):需推翻 ADR-0029「观感全静默」一处;配速落地后深积压不再出现,补丁失去对象。真机复测若仍有浅落后观感再立项。
- **演出瘦身压播放时长**(否):伤「画与戏」基线,与 DESIGN 方向冲突。
- **bot 配速吃 E2E_TIME_SCALE**(否):权威节奏不吃浏览器 localStorage 倍率是既有纪律(#399 单源表文件头),联机/单机同值是同构底线;e2e 提速走显式注入通道(与 E2E_REACTION_MS 同模式)。
