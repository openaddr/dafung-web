# 拼点签面:全屏多骰演出取代棋盘双印,拼点点数入事件流

拼点的演出此前只有一条残缺通路:半路杀出拦检在**失败/平局**时,棋盘现场钤「拼点双印」(两枚骰点方印错拍+合印「失/平」);拦检**拦胜**时什么都看不到;连环计·二虎竞食的两人对拼从头到尾没有任何骰面演出。根因是一条省钱口径——「拼点掷点不入引擎事件(零新事件口径,`fx/event-extract.ts` 注释)」:点数只进战报文本与 `reactionFailed` 的 aRoll/bRoll(还只有拦检负/平带),表现层想画也没数据。玩家视角:发生拼点却看不到骰子。

故两项决议:

- **引擎:`resolveDuel` 内统一 emit `duelResolved`**——两方座位、两枚点数(aRoll/bRoll)、胜者(winnerSeat,平局为 null),拦检与连环计(将来若扩 N 人)同源。既有边界「拼点骰不派 `DieRolled`、不触发张星彩掷金」不变:`duelResolved` 是独立词汇,掷骰事件仍只归行军。`reactionFailed` 保留(拦检负/平的宣告语义),但其表现消费(duelStamps 提取)随双印退役,拦检浮字的「(掷 X 对 Y)」点数括注摘除——骰面即是信息,点数不落第二处。
- **表现:全屏「拼点签面」取代棋盘双印**——签面是本作掷骰的正名语言,拼点签面是其多签变体:每名参与者一枚骨牌大字签面,并排立于全屏玄墨幕,签头=玩家色底+国号(连环计拼的是「别人俩」,身份签头尤其要紧)。版式与节拍:
  - 版式(N=2,拦检与连环计同式;N>2 横排列开):中缝朱砂「拼」印锚对抗关系;判词=胜者金光圈+金描边、败者降饱和沉暗,不加「胜/负」文字章(DESIGN §4.6 状态表达原则);平局双方无圈、中缝印钤变为金「平」——「都没圈」与「还没判」不可区分,这是文字该承载的语义例外。
  - 节拍:幕启(玄墨幕渐入、两签虚位立起)→ **并行起摇**(签面虚影轮换,悬念并行不拉长全程)→ **依座位序错拍落定**(前拍落定→clackGap→后拍落定,延续既有拼点节拍)→ 判词拍(合印 stamp 音;**点差 ≥3 震屏**,DESIGN §6「拼点大胜负」既有规则原样延续)→ 停留渐出。表现编排串行,棋盘后果(止步/续走/cashChanged 浮字)天然排在签面收场之后。
  - 联机零特殊处理:点数随事件批自然过网,全员同见(拼点本就公开信息)。

放弃的替代:棋盘锚定骰签(现场感强,但格子小、离注意力远,连环计双方都不是「我」);探宝拼点纳入本演出(单人 2d6 对珍宝等级,非玩家对拼,已有金「得」印,GLOSSARY「拼点」② 维持现状);各场景各补点数事件(拦检补拦胜、连环计另补——事件词汇碎片化,表现层逐场景直译);双印保留作棋盘现场痕迹(与全屏签面双通道说同一件事,违反 §4.6)。
