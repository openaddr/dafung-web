# ADR-0017:反应窗为 per-seat 非阻塞决策(联机不暂停全场)

日期:2026-09-23
状态:已实施(#281,2026-09-27;引擎相位 `AwaitingReaction` + 反应锦囊识破诡计/半路杀出 + 牌架即反应窗 UI 同窗落地);#284 补记窗级 deadline 与时长单源(2026-09-28,见文末)

## 背景

#188 档 1 引入反应锦囊:手持「即时」标记的锦囊可在任意玩家的结算窗打出。这要求一个新的询问语义,即原 #188 Q2 挂起的两个问题:超时时长、以及**是否暂停全场等反应**。全局暂停实现最简单(引擎在结算点 `await` 全座位应答),但在联机会放大等待:3 人局每个结算点都可能平添一档倒计时,而多数结算点根本没人想出反应牌。

实证参考:无名杀(noname)实机验证(`docs/design/ui-reference/research-sanguosha.md` §6)——锦囊结算按座位序逐个询问,每人独立倒计时,超时兜底是「自动取消」或「交给 AI」,从不让无牌可打的人干等;另有「暂定无懈」一键「本回合不再询问」的降噪口,同一结算链的最后一次询问自动解除。

## 决策

1. **非阻塞:反应询问不暂停全场**。被询问者各端独立走自己的倒计时(联机默认 3s,按相位配置表驱动);倒计时归零视为「不用」,引擎取默认行为继续。其余座位全程无感,不等这 3 秒。
2. **超时兜底走既有「服务器定时经同一条命令路径代发」口径**(同行军自动化 #225):计时与兜底在权威侧(单机=LocalController,联机=server 房间循环),客户端倒计时只是投影;超时代发的命令就是一条普通的「不用/跳过」命令,重放天然复现。
3. **单机同步等待**:本机无网络延迟,同步等满倒计时窗口(3s)无副作用,bot 持牌即时代答不等满。
4. **降噪口**:提供「本回合不再询问」。解除时机实施定案(#281)=**持续至当前行动者回合结束**(行动者变更自动解除),比 noname「同一结算链解除」(research-sanguosha.md §6.3)更降噪——逐链解除会让同一回合的下一个结算点立刻重新弹窗,与按钮语义不符;客户端本地态,不入快照。
5. **UI 形态随反应窗词条**(GLOSSARY.md):结算文案 + 此刻可打反应锦囊(手牌架金边呼吸),点牌 → 目标 → 落印。

## 后果

- 协议侧:反应询问是 private 通知(ADR-0016 投影白名单新增 `private(seat)` 载荷),超时兜底在权威侧执行——挂起的人不阻塞他人,断线者超时即「不用」,无需冻结特殊处理。
- bot/看门狗/托管:持「即时」牌的 bot 按既有意图评分即时代答;托管座位**永不主动出反应牌**(沿用 #148/#229「代驾不花牌」口径,超时一律不用)。
- #188 Q2「是否暂停全场」就此销题;时长数值留档 1 实装期校准(配置表驱动,不改语义)。
- 全局暂停方案被否:若未来某反应牌需要「强制全场决」(如投票型),那是新决策相位,另立 ADR。

## 补记(#284,2026-09-28):窗级 deadline 与时长单源

#281 实装后拷问会(#283)复盘出两处实施缺口,随 #284 收口,决策本体不变:

1. **窗级 deadline(seq 判据)**:#281 的联机权威计时器随 bot 驱动链重开而重武装——一人应答(或任一命令触发链重开)会**重置他人倒计时**,与本 ADR「各端独立走自己的倒计时」相悖。修正:`PendingReaction` 增单调 **seq(窗实例号)**,引擎每次开新窗 +1、随快照序列化;传输层(`room.ts` `armReactionWait`)武装前比对 seq,**同一窗只武装一次、到期时刻一次算死**,seq 变了才撤旧起新。语义对照:新月杀/FreeKill `lua/server/request.lua` 的「timestamp+timeout 随包下发、客户端本地倒计时、deadline 开窗一次算死、同窗不重置」——本仓取同一语义的更干净形态(同 seq 一律不重武装,deadline 自然只算一次)。seq 是 cmd 流派生状态,重放重算天然复现。
2. **windowMs 进快照(时长单源)**:开窗时长由引擎开窗时写入 `ReactionView.windowMs` 随 view 走——客户端横幅/倒计时投影与联机权威侧定时器同读一份快照值,不各自引常量表(双源消灭);联机权威侧可经服务器 env `E2E_REACTION_MS` 整体覆盖(联机 e2e 注入加长窗;缺省走 `constants.ts` `REACTION_WINDOW_MS` 表,是配置不是兜底)。现行时长数值见 `constants.ts` 单源。

> 2026-10-23 补记:默认窗长已由 3s 调至 15s(两触发点同调,`constants.ts` `REACTION_WINDOW_MS`);配置表驱动与决策本体不变,上文「3s」为决策时点数值。
