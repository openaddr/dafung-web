# ADR-0054: bot 对战基准 + 历史区间台账(票三)

日期:2026-11-07 · 状态:已采纳 · 票:[#1163](https://github.com/openaddr/dafung-web/issues/1163) · 地图:[#1160](https://github.com/openaddr/dafung-web/issues/1160)(无头确定性 e2e 测试体系,wayfinder)· 前提:[ADR-0052](./0052-headless-deterministic-testing.md) · [ADR-0053](./0053-goldens-ledger.md)

## 背景

票二把「行为逐位不变」钉进了黄金台账,但台账只回答「变没变」,不回答「变好还是变坏」——平衡性调参(数值表 / 机遇目录 / 地图目标线)需要一层统计事实:局多长、谁破产、怎么终局。本 ADR 记票三:bot 对战基准(`check:sim-bench`,按需跑,不进默认门)+ 历史区间台账(`test/goldens/bench-ranges.json`,jj 跟踪),平衡漂移(局长中位、破产率越出历史带宽)越界即红。

参考仓 vera20k 的 `src/bin/sim-bench.rs`(899 行)。

## 参考与取舍

> 学了什么(照单)与落地物清单见 [参考仓索引](../reference/参考仓索引.md) 单源,不复写;本篇只留裁决与台账口径。

### 什么不适用、为什么

- **场景三型(march/match/skirmish)**——它是 RTS 基准的三种负载剖面(纯移动 / 中盘会战 / 全局对局),存在的理由是「不同系统瓶颈要分开测」;本仓是回合制大富翁,瓶颈只有一个(引擎状态机+数值结算),场景只有一型:**全 bot 自对弈跑到底**。拆多型 = 造没有对应瓶颈的剖面,纯开销。
- **预热段(`after_orders_mean_ms` 跳过前 150 tick / march 的 order_spread)**——它是**性能时序**的稳态窗:头几帧吃 JIT/缓存冷启动、首批指令扩散,不剔掉均值就是歪的。本仓基准不测墙钟性能(单局 ~100ms 量级,性能归 ADR-0047 帧诊通道),测的是游戏统计事实——统计没有冷启动问题,每一局从第 1 轮起都算数。判:不适用。
- **座位档 8**——票面写「座位档(2/4/8 若引擎支持)」;vera20k 大地图 30 start 才撑得起 8 家,本仓引擎座位上限 4、国号池四家(sim-batch 校验 2-4),8 无引擎承接面。矩阵定为 **2 与 4**(2 档是双人对弈形制,4 档是产品默认形制)。
- **逐帧计时(CSV / cpu_ms / frame_profile)**——同预热段一条:那是性能基准的器官,本票是平衡基准,不搬。

## 决定

### 矩阵与语料

3 图(guanzhong/zhongyuan 内置 + yanzhou 夹具,同票一语料源)× 座位档 {2, 4} × seed 4001-4050 = **300 局**;机遇 = 产品默认(ADR-0035),不装扩展包(与票一/票二同口径——区间只依赖仓内内容,扩展目录变动不进基准)。seed 段 4001-4050 与票一/二语料 3001-3010 分开,两门互不踩。定位 = **按需跑**(平衡调参时、动数值表前后 A/B),不进默认门;实测墙钟 ~23s(Bun 单进程)。

### 断言面(种子固定 = 确定性,不飘)

1. **终局必须达成**:`finished=false` 即红并列 seed 清单;触回合上限 = 平衡发现,处置 = 调语料或本 ADR 记判读——不是 update 能盖掉的(update 模式遇未终局局直接拒刷)。
2. **零不变量违规**:driveToEnd 六守卫(相位/归属/无进展/词表/数值/僵死,ADR-0052)已覆盖全程,引擎抛错原样上抛,本脚本不接不包。
3. **终态经济扫尾**:全员 `netWorth` 有限;非破产座位终态 `cash ≥ 0`;局中 `playerBankrupt` 事件座位(subject=破产者,timing.ts)终态 `isBankrupt` 必须 = true(事件↔旗子交叉核对);终局而无胜者同样炸。首跑 300 局全部天然成立(2026-11-07 实证)。
4. **历史区间门**:局长中位数与破产率落 `bench-ranges.json` 历史区间,越界红,报「图/档/实测 vs 区间」。

### 区间台账(`test/goldens/bench-ranges.json`,格式冻结)

- 每 `(mapId, seats)` 一键(`guanzhong#2` 式),记 `{ medianRounds: [lo, hi], bankruptRate: [lo, hi], format: 1 }`;校验模式要求键集与矩阵严格相等(缺键 / 未知图档 / 字段漂移 / format 不符当场抛,零兜底——同票二台账门心智)。
- **带宽口径**:首跑中位 ±25%。轮数是整数量纲,四舍五入取整;破产率(局均破产人次,`isBankrupt` 旗为单源)是小数量纲,**保留两位小数**——取整会把低速率带宽压成 `[0, 0]` 伪门(zhongyuan#4 实测 0.50 → 取整即 [0,1] 粒度,0.24 档直接塌成 [0,0]),两位小数保住 ±25% 的真实带宽。
- **越界处置**:先判读再动手——越界 = 平衡真漂了(确认符合预期)→ `bun run check:sim-bench:update` 重刷区间(打印新旧对比,不静默);漂移不符合预期 = 回去修数值。台账 diff 与代码同 PR 入库。
- 双模式与格式冻结心智同票二(check-goldens):默认校验、`update` 子命令刷新;`update` 遇未终局局拒刷(未终局的区间不可信)。

### 统计口径(沿 sim-batch 先例)

分位数 `q(arr, p) = arr[floor(p·(n-1))]`(p50 即中位);破产率 = 局均破产人次(全座位 `isBankrupt` 旗合计 / 局数);报告字段 = 终局率 / 轮分布(min/p50/p90/max)/ 终局方式分布 / 胜者身价中位 / 破产率。

## 后果

- 平衡性调参有了统计事实与跨版本区间门:数值表/机遇目录/地图目标线的任何改动若把局长中位或破产率推出 ±25% 带宽,`check:sim-bench` 按需一跑即红;有意调平衡走 update 留痕。
- 断言面与票一/票二分层不打架:逐位确定性(票二台账)、统计区间(本票)、不变量守卫(票一驱动器)各守各的;本票不进默认门,`bun test` / `check:goldens` 墙钟零增加。
- 已知边界:区间只钉 50 种子的中位与均值型指标,个体 seed 的极端局不设门(那是黄金台账逐位门的辖区);带宽 ±25% 是首拍经验值,过宽/过窄随第一次真实漂移再校准(改 BAND 常数 = 区间格式语义变更,须全量重刷并记本 ADR)。
