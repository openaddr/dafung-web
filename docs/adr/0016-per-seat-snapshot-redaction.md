# ADR-0016:暗牌的 per-seat 快照投影(redaction)

日期:2026-09-09
状态:已接受(2026-09-09 锦囊拷问会与用户确认)

## 背景

锦囊系统(docs/explanation/锦囊设计.md,#122)引入了全游戏**第一个隐藏信息**:暗置手牌。现状是联机对每个座位广播**同一份全量快照**(`clientView` 直接展开 `engine.snapshot()`,scripts/room.ts;`broadcast` 对房间内所有 WS 发同一 JSON,scripts/server.ts)——连珍宝牌堆剩余都全网可见。手牌若进快照,泄漏面有四处:players[].hand、对局日志行(log 全量随快照过网)、派生 choices 载荷(卷轴文段)、以及未来的私有通知(抽牌/窥探)。

## 决策

1. **引擎快照保持 god-view,单一事实**。手牌/牌库/弃牌堆全量进 `engine.snapshot()`,序列化与重放不变。可见性问题**只在传输层解决**:`clientView(room, seat, snapshot)` 增 per-seat 投影( redaction),broadcast 改为按座位各发各的投影。
2. **投影白名单制**:每类载荷的可见性显式登记,新载荷引入时必须声明归属——`public`(全员)/`count-only`(只给数量,如他人手牌)/`private(seat)`(只发本人,如抽牌结果、窥探目标手牌、决策 choices 的卷轴文段只留 decisionOwner)。未登记的默认 public。
3. **对局日志源头不落手牌内容**:引擎日志只写「抽了一张锦囊」不写牌名(抽牌 dice 驱动,重放可推导)——日志随快照过网也无需再裁,且日志文件保持可安全外发。出牌/结算本身是公开事件,命令行照记。
4. **单机不设防**:引擎在本机,只做 UI 层隐藏(bot 手牌同样不渲染);不为其引入投影层复杂度。

## 实现口径(T1 落地时定,2026-09-09)

- **数量是引擎状态,不是投影产物**:手牌数/牌库剩余数全员可见,而联机客户端以「restore→重新 snapshot」重水合,投影层注入的视图字段会在重生成时丢失——故 `jinnangHandCount`/`jinnangDeckCount` 为引擎正式字段,在抽牌等唯一改动点维护;投影只裁内容,不造数据。
- **传输层「最新者胜」合并**:快速托管局是单 tick 数百步的 bot 连锁,逐步直发全量快照会灌爆 WS 背压(Bun 超限静默丢消息,页面永久停留旧态)——broadcast 按座位标记脏,同一 tick 合并为一份终态发送;人类节奏流程(每命令一 tick)语义不变。

## 后果

- broadcast 从「一消息全房」变「一座份一消息」:同房 N 座位 N 份序列化,量级可接受(快照本就每手全量)。
- 重放/持久化/看门狗/托管零影响(都在 god-view 侧);断线重连、host 移交不变。
- 客户端多收不到他人手牌后,**任何新 UI 想展示他人手牌必须走引擎的显式窥探机制**,不能指望快照里有——这是特性不是缺陷。
- 新增快照载荷的评审清单多一问:「它该登记哪档可见性?」漏登记的默认公开,暗牌系统下的失误方向是「泄密」而非「丢失」,评审可按此定责。

## 术语(登记入 CONTEXT.md 语言表)

- **投影(Redaction)**:传输层按座位裁剪快照的公开/计数/私有三档规则。
  _Avoid_: 过滤(引擎侧 choices 的 available 过滤已占用此词)、脱敏(安全口吻,这里是玩法)
