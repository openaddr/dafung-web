# ADR-0072 联机服务器与安卓客户端独立构建

状态：已接受

APK 的单机模式在本机使用权威引擎、房间编排和协议。联机服务器也使用这些逻辑。当前运行时代码跨越 `src/core/`、`src/app/` 和 `scripts/`，容易把共享房间逻辑误归为服务端专用代码。在同一 Bun workspace 内建立三个包，保持规则单源，并让两个宿主分别构建和交付。

| 包              | 职责                                                                            |
| --------------- | ------------------------------------------------------------------------------- |
| `packages/core` | 权威引擎、房间编排、协议、座位投影、地图数据和扩展契约，按职责组织子目录。      |
| `apps/server`   | Bun HTTP 与 WebSocket、应用配置、文件持久化、对局日志及磁盘扩展装载。           |
| `apps/client`   | React 与 Tauri、界面素材、联机连接，以及单机的内存传输、Worker 时钟和本地归档。 |

两个宿主通过公共包的导出入口使用共享代码。公共包使用两端均可运行的接口。开发和发版编排留在仓库工具层，开发网页的静态托管由开发入口提供。单机仍按 [ADR-0066](0066-local-protocol-hydration.md) 通过房间协议驱动水合副本。

## 交付

- `bun run build:server` 构建服务端 JS 并打包地图、扩展清单及已编译入口。地图和扩展保留为可核对的文件，供启动时读取和装载。VPS 使用构建与验收确认的 Bun 版本运行发布包。
- `bun run build:client` 构建 WebView 界面资源，APK 构建消费该产物。两条构建入口各自检查依赖边界和产物。
- APK 和服务端发布包由同一固定提交构建，作为同一 GitHub Release 的资产交付，分别核对校验和。部署时显式选择发版号。

部署范围是 VPS 本机上的 systemd 进程、监听端口和健康检查，公网入口由运维者在 1Panel 管理，见[部署服务器](../how-to/部署服务器.md)。
