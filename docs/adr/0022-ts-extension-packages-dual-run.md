# ADR-0022: TS 扩展系统——双跑加载与一次搭全的骨架

日期:2026-10-04
状态:已接受(2026-10-04 架构拷问会,用户拍板「中间态」口径)

## 背景

内容即代码:名将/珍宝/机遇是引擎内 TS 模块,加内容=改源码走完整开发回路,无 UGC 通路、无热更(APK 需重装)。对标 FreeKill 的 Lua 包生态(客户端 libgit2 自行 clone、两端各自加载同一份包代码)后,用户明确要求第三方扩展灵活性,且指定用 TS/JS 而非 Lua。拷问中撤回了早期的「扩展仅权威侧加载」方案——灵活性需求下,客户端也要加载扩展代码做表现。

## 决策

1. **TS 双跑**:扩展=TS 模块(分发编译后 JS),权威侧加载做裁决,客户端动态 import 做表现。同语言无嵌入税;作者有类型、lint、现有工具链。
2. **骨架一次搭全**(用户口径:架子这次做好,后续直接长进去,不再大动地基):
   - 包清单(manifest):名称、版本、入口;
   - 双端加载器:权威侧与客户端各自安装/加载;
   - 注册面全类型定义:技能/效果注册(对齐既有效果注册表与时机总线)、交互 handler、动画 handler、渲染 hook——**含第一版不实现能力的接口位**(新牌类型、新格子类型、自定义面板、音效、文案)。
3. **第一版实现到**:三能力(交互 handler/动画 handler/渲染 hook)各一个最小示例,随官方示例名将包走通全链路(装包→双端加载→对局可玩→UI 生效)作为架子票验收标准。
4. **未实现能力每项登记跟踪票**(用户明令防忘),挂 wayfinder 图,按票兑现。
5. **信任模型**:无沙箱、无随机数/时钟纪律(ADR-0021 删仪器后无从谈起),信任扩展作者;公网陌生人局与沙箱分级另行拷问,不在本决策内。

## 后果

- 扩展注册面成为事实契约:引擎重构要么维护它,要么按零兼容原则连带掀桌重写扩展。
- 服务器运行第三方代码=信任作者;朋友圈成立,公网化前必须补沙箱(登记票)。
- web 端内容热更达成(刷新即得);APK 仍需发版才能更新**客户端侧**扩展面代码,纯数据/资源包可热载。
- 与 ADR-0020 咬合:扩展动画走事件流,扩展交互补足决策选项集之外的定制问询。

## 备选

- 仅数据外置(JSON 化数值画像):不够——用户要的是技能级灵活性,技能语义是代码不是数据。
- 嵌入 Lua:宿主本身是 JS 系,嵌入第二语言徒增边界税与双运行时维护。
- 扩展仅权威侧加载:撤回——客户端表现灵活性(自定义问询/动画/渲染)是需求的一部分。
