# ADR-0066: 单机状态读取收口协议水合副本

日期:2026-11-15
状态:已接受(#1479、#1480,承接 #1239/#1243)

单机已复用房间编排和内存双工协议,但客户端仍直接读取同进程权威引擎、发送侧每拍恒发快照。这让单机绕开 [ADR-0020](./0020-event-stream-sync-model.md) 的事件折叠与校准口径,协议缺失也会被直读状态掩盖。

`LocalController` 改持独立水合副本:开局同步段建立权威对局后入座,首连整房摘要同步水合;后续事件批折叠推进,快照无条件校准。界面、决策归属与交互全部读取副本,命令继续经原 wire 协议上行。行军位置在折叠或水合前捕获,表现仍消费原事件批。

内存发送侧复用现役服务器的校准窗口、节点事件与闭沿判定,登记单源仍是 `seat-projection.ts` 的 `CALIBRATION_*`。普通拍不恒发全量快照;房间元数据变化通过差异化 `lobby` 消息送达,托管回读由下行座位表提供。单机的房间字段留在控制器,不激活 `netStore` 的联机界面分支。

代价是单机也承担副本折叠与权威状态之间的协议边界,失步须在协议处暴露和修复。Worker 挂死产生的异常终局立即下发完整状态,保持既有同步终局契约。单机销毁仍解散房间,无网络重连或跨进程恢复语义;不为测试或调试另建权威写入口,浏览器回归继续遵循 [ADR-0065](./0065-test-economics-browser-retirement.md)。

落格决策交接(#1497)补齐 `landingResolved` 公开事实事件:权威在固定事件落账、最终决策挂起后宣告相位、地产决策、交涉上下文与落格结果。`marchArrived` 只折叠位置与行军路径,不复制城池规则或提前预测;招贤闭窗续接交易链同走最终事实,自动结束回合仍由回合事件清场。招贤候选保持既有入窗校准,普通购地、扩军和珍宝交涉不增加全量快照。
