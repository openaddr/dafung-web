# ADR-0014:对局日志系统(复现级全量事件 + 双轨落盘 + 保底清理)

日期:2026-08-26
状态:已接受(2026-08-26 与用户四项决议对齐)

## 背景

需要"从日志几乎完全复现一局游戏"。现状缺口:LogEvent 无时间戳/轮次、无局头(地图/seed/座位)、部分事件未记(三候选/托管/房间进出)、无独立日志文件、无清理机制。

## 决策(与用户对齐的四项)

1. **双轨自动落盘**:联机 = 服务器每局流式追加 `logs/<gameId>.jsonl`;单机 = 浏览器 IndexedDB 每局一存(手动导出保留)。
2. **双层 + 局头重放**:每行事件 = 中文自然语言 message + 机读 params(英文键值);局首行记 gameId/地图/seed/座位/起始现金/目标——复现采用**命令流重放**:引擎给定 seed+座位后是确定性的,记录每条玩家命令(GameCommand)即可精确重建,事件日志作人类可读层。
3. **覆盖全集**:引擎玩法事件全量 + 26 时机触发(技能)+ 房间生命周期(加入/离开/托管/接管/解散)。复盘无盲区。
4. **30 天保底清理**:服务器启动时扫描 logs/ 删过期文件;单机 IndexedDB 写入时顺手清过期局。无定时器,零运维,不追求精确到天。

## 基本信息字段(每行必备)

时间(epoch ms)/ 轮(round)/ 回合(turnNumber)/ 玩家(guohao 或座位)/ 特征类型(category:玩法事件类 | 时机类 | 命令类 | 房间类)/ 中文 message / params(机读)。

## 后果

- LogEvent 结构升级(加 timestamp/round),快照序列化随之;快照契约测试保障联机一致。
- 重放校验成为验收手段:scripts/replay-log.ts 读 jsonl → 重建引擎 → 逐步重放 → 断言终态一致;日志系统自身用"全 bot 局生成日志→重放→逐字段相等"自证。
- 日志体积量级:单局 0.1~0.5MB,30 天上限可控。

## 术语(登记入 CONTEXT.md)

- **对局日志(Game Log)**:一局一个 jsonl 文件,局头+事件流+命令流双层。_Avoid_: 战报(已退役的 UI 概念)、history。
- **局头(Game Header)**:日志首行的重放要素(地图/seed/座位/现金/目标)。_Avoid_: meta。
- **命令流重放(Command Replay)**:以 seed+座位+玩家命令序列重建引擎的复现方式(区别于读叙述推理)。
