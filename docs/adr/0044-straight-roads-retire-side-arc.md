# 驿道恒直线:避城弧线算法退役

日期:2026-11-01;票:[#928](https://github.com/openaddr/dafung-web/issues/928);收殓 2026-10-17「调 threshold vs 消费 waypoints」两杠杆悬案。

## 背景与问题

驿道弯直的唯一判据曾是 `edgeWaypoints` 的「两城中心距 ≥300 必弯」——与线上有无遮挡无关,也没有「空旷直行」出口。该规则在两张在役地图上全面空转:

1. **全弯零直**:环游图 #823 重排 36 城 9×4 网格后,边长只剩 320/380 两档,36 条边 100% 触发避城弧线;中原图 8 边(361~495)同样全弯。玩家看着挨着的城,路线一律拐弯。
2. **避让无物可避**:全量几何验证,两图每条边的直线线段到最近城池中心的最小距离为 320/361,而城卡半高仅 97(104×88 × 2.2 缩放)——直线穿卡数为 0。`sideArc` 的六候选避让打分在役数据上从未真正避过东西。
3. **演出代价**:弯边行走序列每格 3 段 CSS transition,各段 easeInOutSine 段尾速度趋零,棋子每格停顿 2 次;弧线路程 +15~21%,匀速 720px/s 下时长 608/537ms,直边 460/444ms——「更长、更卡」的双重来源。

弧线的原始设计意图(手绘蜿蜒风+把驿道压进两排间走廊)已被用户否决:横平竖直的网格图上,蜿蜒弧线读作视觉噪音而非风味。

## 决策

拷问一轮收敛(2026-11-01 拍板):

1. **驿道恒直线**:城池间路线一律城心直连,行走序列=起点中心+逐格落位中心。`sideArc`、`edgeWaypoints`(含 300 阈值语义)、`TileDef.waypoints` 预留字段全删;`MovePath.waypoints` 保留(行走序列本体,快照 lastMove 随行序列化)。
2. **路线畅通是地图设计的责任,不是算法的责任**:网格间距(横 380/纵 320)天然保证直线行廊;若未来作者手搓出直线穿卡的密集图,那是地图数据的问题,该在数据层解决(届时再谈显式手段),不为「理论上可能有」供养一套零测试的避让打分机制(「理论上到不了」式防御,零兜底原则禁绝)。
3. **三案对比**:A 全直删弧(取);B 能直则直(直线距城心 ≥ 安全半径才直,否则降级弧)——否决,理由=core 层引入与视觉卡尺寸挂钩的常量+整套打分机制继续在役;C 阈值 300→400——否决,语义仍是「长度定弯直」,400 顶 380 是拿全局常数凑本地几何,改间距即复发。
4. **MARCH 常量不动**:一次只改一个变量;直边后每格一段一气呵成,顿挫源已除,节奏调参(若有)另票。

## 后果

- src 净删 54 行(26 增/80 删);行军演出每格单段,横边 608→460ms、竖边 537→444ms,每格两次减速顿挫消失。
- 静态驿道/流光/箭羽/行军走线四处消费同一行走序列,天然一致;箭羽锚退化为边中点。
- 测试重钉:board.test「恒直线」钉(computePath waypoints 只含 tile 中心)、choreography-invariants 每段恒两点、map-loader sideArc 专用 describe 删除。
- 自定义地图若布局密集到直线穿卡,视觉上由作者自负(编辑器暂无提示;真需求出现再议数据侧显式通道)。
