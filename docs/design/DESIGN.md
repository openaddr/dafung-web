### 4.6 状态表达原则(2026-09-25 定,用户拍板)

**能用 UI 状态变化标识的,不增加文字标牌。** 选中/可选/候选/激活等状态一律优先用边框、色彩、位移、光圈等**状态变化本身**承载(如候选席位=金边框+光圈,不再贴「择」字章);文字只保留给状态变化表达不了的信息。理由:文字标牌占面积、小尺寸下不易识别,且与既有状态语言重复——双通道说同一件事,读者反而要学两套。

- 判据:撤掉这段文字,状态是否仍然可辨?可辨 → 不加文字。
- 例外:语义必须由文字承载的(禁用**原因**、数值、牌名),文字本身即信息,不受本条约束。
- AI/贡献者做 UI 设计前**先读本文**(尤其 §4.2 语义、§4.6 本条);设计评审按此原则打回冗余文字标牌。

**快捷键退场(2026-09-30 定,#360/r5 裁定②)**:**本作不重视快捷键——UI 不设键盘快捷键依赖。**选择类交互以点选为唯一口径,不为快捷键设展示件(招贤三选一的 1/2/3 键位角标与监听已随之撤除);存量出牌阶段态的数字键/Enter 属既有交互语义,不扩面、不复制——新 UI 一律不再引入键盘快捷键依赖与键位角标。

**UI 只显示当前状态,历史归日志/战报(2026-09-30 定,#361/r5 决议④)**:状态 UI 只呈现**当下**的持有与数值——珍宝/名将弹层陈列现持有全件,不设「曾持有」区、不给已失去的物件留灰化展位;何得何失、来龙去脉一律归战报抽屉与对局日志(ADR-0014,历史在那里本就是唯一事实源)。理由:状态 UI 混入历史,「现在有多少」就要靠辨读,毁掉一眼可读;同一事实两处陈列(状态区+历史区)必然漂移。

**弹窗可拖动(2026-10-24 定,#674)**:全部**居中式弹窗**(ui/dialog 底件系与 BannerShell 横幅系全部成员)题名行可拖,拖离中心遮罩墨纱减淡(0.42→0.15)、拖回吸附带回正复原——决策弹窗「边看边掂量」正需要它(破产变卖、机遇抉择都是看着棋盘做的决定);模态语义(遮罩拦指针/焦点陷阱/Esc/点外关闭)不随拖动变化。位置零记忆(每次打开回中心),抽屉族(战报/贴底)与全屏覆盖不参与。行为口径与翻案理由见 [ADR-0031](../adr/0031-draggable-dialogs.md);原语单源 `src/app/hooks/use-dialog-drag`。

### 4.7 移动端形态原则(2026-09-27 定,用户拍板;2026-10-27 形态分档修订,#703)

**移动端只做横屏,竖屏游戏布局不做。** APK 已锁 `sensorLandscape`(启动即横屏);手机浏览器无法强制横屏,竖屏打开给「请横屏游玩」提示层——提示层是形态门卫,不算游戏布局。对局屏同构模板一套、按视口分两档(#680):矮横屏档(`orientation: landscape and max-height: 500px`)= 全浮层紧凑档,允许重排;桌面档(其余一切横屏)= 布局零重排、密度舒展,无桌面专属布局。对局屏全浮层构图与几何定案见 [ADR-0032](../adr/0032-hud-float-form-tiers.md);裁决细节与后果见 [ADR-0018](../adr/0018-mobile-landscape-only.md)。
