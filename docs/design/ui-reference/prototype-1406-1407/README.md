# 联机大厅入口与开局等待

关联 [#1406 建房／入房](https://github.com/openaddr/dafung-web/issues/1406) 和 [#1407 开局等待](https://github.com/openaddr/dafung-web/issues/1407)。同一条联机流程分两次决策，两个方案可以任意搭配。

[打开离线交互原型](./lobby.html) · [844×390 布局对照](./lobby-compare.png)

从界面里的「创建房间」进房，点「选择地图」和「确认选择」，再点「开局」。原型下方的「服务器接受开局」和「收到首份棋局」用来分别推进真实流程中的两道边界。也可直接进入「房主／来宾」样张。入口和等待方案分别切换，当前选项会记在 URL 中。

## #1406 建房与入房

- **A 同屏双栏（推荐）**。左边建房，右边直接输入房间码。两项主行动各自固定，加入无需先打开表单。检出有上次房间时，在右栏分隔后提供「重进」，房间码保留阅读字族。输入框留给本次收到的房间码。
- **B 先选入口**。首屏放「创建房间／加入房间」，点选后展开对应表单，上次房间可直接重进。首屏少一组字段，每条新路径多一步。

示例对照使用现役的 2～8 席、入房后选图流程。建房默认显示「按地图默认」，具体数值随选图解析。选图摘要标示该图的默认目标；两张现役地图当前同为 30,000 两，数据来自地图配置。显式自定义通过原有目标校验和提交路径，换图后仍保留。房内目标提示区分本房自定义与地图预设，未掌握房间自定义配置的来宾或重进情形只把该数值标为「地图默认」，不把它说成该房实际目标。高级网络设置保持默认折叠，探活和请求失败可见。

## #1407 开局等待

- **A 按钮旁提示（推荐）**。房间码、地图和座次仍可读。房内按钮保留原文案，开局期间锁住操作，在按钮旁只显示一处当前状态。失败在同位置显示原因并恢复可用操作。
- **B 居中遮罩**。同一条状态放在大厅卡片中央，暂停操作时更醒目，会压暗房间信息。失败撤遮罩，再恢复按钮和原因提示。

| 到达的状态 | 房主见到 | 来宾见到 |
| --- | --- | --- |
| 房主已点击，开局请求尚未返回 | 正在开局… | 等待房主开局… |
| 开局请求成功，首份棋局尚未收到 | 正在同步棋局… | 缺少开局信号时仍等待房主 |
| 收到并应用首份棋局 | 切入棋局 | 切入棋局 |
| 请求明确失败 | 显示服务端／网络错误，操作可重试 | 仍在房间 |
| 连接中断 | 复用现有连接恢复提示 | 复用现有连接恢复提示 |

状态来源见 [LobbyScreen](../../../../src/app/screens/lobby/LobbyScreen.tsx)、[联机控制器](../../../../src/app/controllers/online.ts) 和 [房间规则](../../../../scripts/room.ts)。方案不依赖新增协议阶段或倒计时。

## 并行实施边界

两票分别拍板，再汇总成一份联机大厅规格。入口分支负责建房／加入／重进表单、默认目标说明；开局分支负责按钮旁或遮罩的等待呈现，以及开局失败的恢复。入口和等待各自建组件、样式和定向验证。共享的 LobbyScreen 将两组状态、现有请求、地图目录接入组件，由集成分支单独负责，避免两份改动同时编辑同一入口。确认真有前置依赖再排序。

将错误、首包到达、选图与提交行为接到既有无浏览器验证。844×390、软件键盘、八席显示和真实触达归安卓 APK 验收。原型以 v2026.11.63 的源码、配色、离线字体和真实地图配置制作，房间与回包可手动模拟。
