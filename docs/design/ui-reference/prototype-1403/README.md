# 反应窗构图对照（C3）

玩家要看懂谁用了哪张锦囊、能保护谁或哪座城，并在时限内落印或选「不用」。这组 844×390 Chromium 触屏样张采用关中图、8 席和种子 49。基线为 [506709ec](https://github.com/openaddr/dafung-web/commit/506709ec55d55007fc507e624b4c13f394ff82a7)。以引擎命令产生横征暴敛及火烧连营的根窗，用曹丕的「放逐」对照触发卡。

## 两种构图

- **A 单行横笺**把倒计时、来者、选份和拍板排在一条上。选份时横幅向左展开，拍板仍在右端。「本回合不再询问」收在「更多」，面板内说明本回合的询问都会按「不用」处理。收架时横幅给右下锦囊钮留 6px。
- **B 双层分区**把来者、倒计时和降噪口放在上排，选份与拍板留在下排。选牌前下排提示「先选反应锦囊」。候选出现前后，横幅和拍板的位置一致。降噪可以一步直达。

## 点按与验收

- 两版均用圆笺表示诸侯、横笺表示城池，金边表示选中。七个席位份各有 40×40 触区，城份随文字展开。「子午谷」和「卧龙岗」都在 70×40 的按钮内单行显示。落印为 56×44。选份、确认与放弃均抽测了离各边 2px 的命中。
- 现版和两版都实点了选牌、选份、收架、重开和取消。城份落印后的引擎账目显示，选中的卧龙岗保有 2 点防御，另两座从 2 降至 1。两版也实点了降噪并观察同一行动者回合的下一次询问自动以「不用」应答。
- 倒计时取引擎的 `view.windowMs`，样张中的窗为 15 秒。真机应复验横屏安全区、圈笺与横笺边缘、收架后「锦囊」与拍板可达、危急段和超时。交付阶段可用无浏览器测试核对按份命令及本回合降噪。
- 样张覆盖按份根窗，供布局拍板。读规则可查[锦囊](../../../reference/rules/06-锦囊.md)和[名将与技能](../../../reference/rules/08-名将与技能.md)。触区交叉证据见 [TOUCH-01](https://github.com/openaddr/dafung-web/issues/1402#issuecomment-6910476019)。

## 原型入口

在本原型分支运行 `bun run dev`，于对局入口带 `?variant=a` 或 `?variant=b`。横征暴敛或火烧连营的反应窗在场时，加 `&variants=1` 可用底栏切换现版、A、B。
