# 锦囊共用目标选择

工单 [反应窗的份额选择、拍板与降噪层级](https://github.com/openaddr/dafung-web/issues/1403) 的设计决策。玩家沿同一条操作路径选择诸侯、城池或要保护的一份，看到选中结果后再出牌。

## 三国杀对照

- 游卡国战牌例有三种不同选择语义。铁索连环选择一至两人。借刀杀人先指定持武器者，再指定其攻击范围内的对象。南蛮入侵由牌义圈定全体其他角色。[铁索连环](https://guozhan.sanguosha.com/a/kapaiyilan/youxipai/jinnanpai/2013/0128/102.html) · [借刀杀人](https://guozhan.sanguosha.com/a/kapaiyilan/youxipai/jinnanpai/2013/0128/98.html) · [南蛮入侵](https://guozhan.sanguosha.com/a/kapaiyilan/youxipai/jinnanpai/2013/0128/108.html)
- 开源复刻 FreeKill 的 `ReqUseCard` 统一处理选中、取消、重算候选与确认。卡牌通过 `targetFilter` 和 `feasible` 提供规则。铁索连环声明数量区间，借刀杀人的第二个候选依赖第一个选择。无名杀也以 `selectTarget`、`filterTarget` 驱动共用的可选和已选状态。[FreeKill 选择入口](https://github.com/Qsgs-Fans/FreeKill/blob/671b0ad698c36b703808d8b29f3483ce54b36631/ltk/core/request_type/use_card.lua#L38-L166) · [FreeKill 借刀杀人](https://github.com/Qsgs-Fans/FreeKill/blob/671b0ad698c36b703808d8b29f3483ce54b36631/packages/standard_cards/pkg/skills/collateral.lua#L6-L38) · [无名杀选择入口](https://github.com/libnoname/noname/blob/c73270948d72949aa80009536b9fd5400767d091/apps/core/noname/game/check.js#L3-L89)
- FreeKill 的普通无懈可击询问带上当前生效对象和来源锦囊，取消的是该次效果。群体锦囊的出牌对象与当下要抵消的那一份分别表示。群雄逐鹿的识破诡计由持牌者在反应窗内主动选择一份，按现行规则提交。[FreeKill 无懈询问](https://github.com/Qsgs-Fans/FreeKill/blob/671b0ad698c36b703808d8b29f3483ce54b36631/ltk/core/skill_type/cardskill.lua#L330-L365) · [本仓锦囊规则](../../../reference/rules/06-锦囊.md)

## 统一操作

动作条固定在顶部，显示牌名、当前选择提示、已选对象和对应按钮。候选诸侯在席位上点亮，候选城池在棋盘上点亮。点选改变草稿，再点取消。手牌架收起后，动作条和已选对象仍可读可操作。

反应窗采用 B 的分区。在点反应锦囊前同时显示出牌者、牌名、影响范围和倒计时，选牌、选对象、出牌都在同一位置查看。「出牌／不出」位置固定，「本回合不再询问」单独分开，一步可达。影响范围读本次事件的对象，火烧连营列受击城的名字，横征暴敛给出受影响的诸侯人数。这些文字在选中保护对象后继续显示。

| 场景           | 本步选择                                   | 确认后的行为                       |
| -------------- | ------------------------------------------ | ---------------------------------- |
| 窃玉偷香       | 一位有珍宝的诸侯                           | 出牌                               |
| 连环计         | 先选第一位，再选另一位，第二步可返回改选   | 「下一步」进入第二步，「出牌」提交 |
| 火烧连营       | 在棋盘选一座火源                           | 引擎计算火源和溅射的受击城         |
| 横征暴敛       | 引擎圈定全体其他诸侯                       | 直接出牌                           |
| 识破诡计       | 从能保护的席位份或城份中选择一份           | 按当前反应窗规则出牌               |
| 将来的弹性多选 | 在同一组中点选 1 至 N 个，满足下限即可确认 | 提交整组选中项                     |
| 将来的依赖选择 | 提示写明每步对象，下一步候选随上一步变化   | 逐步确认，末步提交                 |

同牌可以同时出现手选目标和规则推导的受击对象。出火烧连营只选火源。显示溅射预览时，由引擎从火源推导受击城。使用识破诡计时，从当前反应窗的受击城中选保护对象。反识破和整计免选的情况直接使用该窗给定的对象与操作。

从后续步骤点「上一步」，先前的选择仍显示为选中，可保留或更换。再次前进时重新计算候选，后续步骤重新选择。连环计改选第一位后，原第一位重新成为第二步候选。「取消选牌」回到手牌区，最终点「出牌」才结算。

## 落点

现有 `TARGET_DOMAIN_STAGES`、`choices`、`pendingJinnang` 和反应窗载荷继续提供规则事实。共用界面消费本步提示、带对象类型的候选、已选项、数量边界、下一步或最终提交。反应份另外携该次效果的身份，避免同个诸侯或同座城受到多份效果时混淆。城格和座位即使编号相同也用各自的对象类型。具体规则与提交校验由引擎负责，界面复用选中、摘要、按钮可用状态和拍板。已有的目标段与反应窗命令可作为两种接入。

第一轮实盘用连环计两步、火烧连营选火源、识破同一幕的城份检验同一套构图。844×390 下要能看到已选、读清长城名、取消当前选择，并随着阶段正确进入下一步或最终提交。反应窗附加验证收架后找得到「锦囊」、降噪与拍板触区避让，以及实际遮挡。弹性多选在固定示例中检验交互，正式新增牌时补对应权威校验。

正式规格同步修订 [ADR-0032 的响应条位置](../../../adr/0032-hud-float-form-tiers.md) 和 [DESIGN 的反应窗](../../DESIGN.md)。出牌与反应期间临时显示顶部动作条，原位置的知会槽让位。安卓验收检查顶部第一排城格、手牌开收和按钮触区。
