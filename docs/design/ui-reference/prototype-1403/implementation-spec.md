# 实施规格草案：锦囊共用目标选择

来源为 [#1397](https://github.com/openaddr/dafung-web/issues/1397) 的 C3 决策 [#1403](https://github.com/openaddr/dafung-web/issues/1403)。交互以维护者确认的 [844×390 实盘样张](in-game/README.md) 和 [设计决策](target-selection.md) 为准。

## 玩家遇到的问题

玩家选好锦囊之后，要根据牌和使用时机找不同的确认按钮。反应窗用括注显示目标，火烧连营列城名，横征暴敛写「全场」，玩家还要判断识破会保护哪一份。连环计进入第二步后，改第一位会退回手牌重来。「落印」「作罢」也让玩家多猜一步。

## 方案

出牌阶段与反应窗共用目标选择和顶部动作条。下方手牌区选牌，右侧席位区选诸侯，地图选城。动作条保留牌名、当前提示、已选对象和下一步操作。规则已经圈定对象的锦囊显示范围并直接出牌。反应窗采用 B 的信息与操作分区。

## 玩家故事

1. 作为出牌者，我希望点中一张锦囊后就知道去哪里选目标，避免在手牌、席位和地图之间试点。
2. 作为出牌者，我希望点选目标后看到已选对象，再用「出牌」确认，避免误点直接打出去。
3. 作为连环计的出牌者，我希望能退回第一步改选，保留当前锦囊和原先的第一位，方便比较候选。
4. 作为火烧连营的出牌者，我希望手牌架在选城时让开地图，能点到画面边缘的城。
5. 作为横征暴敛的出牌者，我希望在确认前看见征收范围和每位上限，然后直接出牌。
6. 作为持有识破诡计的玩家，我希望先看到来者、来牌、影响范围和剩余时间，再决定是否出牌。
7. 作为使用识破诡计的玩家，我希望从本次实际受影响的诸侯或城池里选要保护的对象，并在确认前看到保护的是哪一份。
8. 作为选择放弃反应的玩家，我希望能立即点「不出」，也能单独选择「本回合不再询问」，避免误关后续询问。
9. 作为横屏玩家，我希望收起手牌后仍能操作动作条，且需要选牌时能用「锦囊」圆钮重新打开。

## 实施决定

- 动作条在出牌或反应期间临时占用顶部位置，该期间同位置的知会横幅让位。正文用现有阅读字族，按钮用项目规定的操作字族。候选和选中优先用边框与亮度表示。
- 有目标段的锦囊使用「选目标」「下一步」「上一步」「出牌」「取消选牌」。目标选择中显示「正在选目标」。「取消选牌」回到手牌重选，锦囊保留。卡牌段或反应窗放弃用「不出」。
- 使用统一的候选与确认接口。引擎提供当前目标域、有效候选、选中数量或步骤约束并负责校验。界面以座位、城格及本次反应效果的身份区分目标，消费权威数据，在目标充分时启用确认控件。单选、顺序多步和自动圈定对象接入现有牌，接口为将来的同组多选保留数量上下限。
- 连环计在第二步点「上一步」时返回第一步并保留原首选。改选后点「下一步」，第二步重算候选且清空旧选择。新首选从第二步候选排除，原首选恢复为可选。只有最终「出牌」才执行结算、消耗锦囊。
- 主动火烧连营选火源，结算由现行规则导出受击城。主动横征暴敛直接根据权威信息显示征收人数和每位上限。识破火烧连营从实际受击城选一份，识破横征暴敛从实际受影响席位选一份。反识破、整计识破和半路杀出的直接应答也用相同的确认区及其现行规则。
- 反应窗从开窗起显示来者、牌名或行军事件、影响范围和权威倒计时。火烧连营列出受击城，横征暴敛显示受影响人数。切换选牌或目标时这些信息和「出牌／不出」按钮位置稳定。「本回合不再询问」单独分隔，一次点按即对当前窗和当前行动者本回合后续询问按「不出」处理。窗口超时同走现有权威通路，选牌、收架和改选均沿用原窗口的截止时刻。
- 单机和联机共用交互与权威校验。出牌阶段同处一个界面的主动技沿用其发动命令和文案，接入改动须覆盖现有选人、选城入口。结束或失去当前目标选择资格时清理草稿。
- 正式交付更新锦囊规则页、相关术语与设计文档。同步修订 [ADR-0032](../../../adr/0032-hud-float-form-tiers.md) 中的反应条位置约束，记录经确认的顶部动作条方案。[倒计时和降噪约束见 ADR-0017](../../../adr/0017-non-blocking-reaction-windows.md)。

## 验证决定

- 从现有引擎命令和对局接线测试入口验证可观察行为。重点验证连环计退回改选、重新进入第二步时排除新首选、最后只结算一次。普通选人、选城和全体牌覆盖命令提交，并守住原有主动技通路。
- 反应窗验证城与席位两种目标提交、保护结果、超时、降噪以及收架重开后选择连续性。复用现有锦囊、反应窗和降噪测试及具名种植件。在规则单测或接线测试中选择能直接观察目标行为的最高入口。
- 安卓 APK 在 844×390 八席局按 [已确认样张](in-game/README.md) 验收。核查安全区、顶部第一排城格和长城名、收起再打开手牌、两种保护对象、降噪与出牌按钮之间的命中避让。普通触区至少 40px，主操作至少 44px，八席零滚动；跨屏触控项参照 [#1402](https://github.com/openaddr/dafung-web/issues/1402)，原生验收参照 [#215](https://github.com/openaddr/dafung-web/issues/215)。

## 范围

本规格覆盖现有锦囊的目标选择、反应窗和相关操作文案。新增锦囊、平衡数值、主动火烧连营的溅射预览，以及 [文案排查](in-game/copy-audit.md) 中的行殇、购地、扩军、选都和珍宝交易各按其后续事项处理。

## 拟拆实施票

1. **让出牌阶段共用顶部动作条和目标选择。** 可立即开工。交付下方选牌、席位选人、地图选城、横征暴敛直接出牌，以及连环计返回改选的完整路径。验收以原型四类操作和现有主动技接线为准。
2. **让反应锦囊接入同一套目标选择。** 依赖第 1 票的动作条与选择接口。交付选牌前的信息区、城和席位保护、直接应答、固定确认按钮和降噪入口。两票集成后按上述安卓验收清单核查。
