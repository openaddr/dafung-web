# 研究存档:参考仓「演出落后于权威」治理先例深挖

票 #600(地图 #596「演出自洽三不变量」决策票)· 2026-10-18 · 三仓浅克隆实查(本机 `C:\Data\Pro\` 平级目录),行号以外部仓冻结快照为准,仅本仓锚点遵循「活文档禁写行号」。

**研究问题**:三仓现成实现里,「客户端演出落后于权威产出」的治理先例各是什么机制、哪些可直接借给三不变量(①提取即定格 ②单写者 ③落后即校准),尤其③校准/追帧与交互锁解绑?

**本仓现状对照**(`src/app/net/snapshot-effects.ts`,#385/ADR-0020 折叠切换③):联机端演出 = `fxQueue` Promise 链全序串行 + `pendingChunks` 在途计数;`OnlineController.interactive` 以 `playing`(= pendingChunks > 0)为门,演出未排空即锁交互。产出速率 > 播放速率时队列无界堆积(演出漂移),且交互被全局演出排空锁门——正是③与「锁解绑」要治的两病。

## 一、colyseus:演出不追权威,权威/判定各自迁就时间线

colyseus 的滞后治理是一族互补机制,分布在核心仓(服务端滞后补偿)与 sdk(客户端演出平滑/回滚校准)两处。**方向上没有一家催赶演出**:演出始终在自己的时间线上自洽播放,落后的代价由「判定基线」或「视觉平滑」吸收,从不反压输入。

### 1a. 服务端 Rewind(滞后补偿)—— `packages/core/src/Rewind.ts`

机制:

- **每实体数字字段历史环**:`EntityHistory` 环形缓冲,容量 = `maxRewindMs / sampleIntervalMs + 4`(:75),`record()` 每 tick 在实体移动后采样(:372-386);任意过去时刻取值 `valueAt(time, col)`,`linear`(连续运动)与 `step`(离散运动,保持前值)双插值(:91-109)。
- **滞后窗口显式封顶**:`DEFAULT_MAX_REWIND_MS = 500`(:4);`at()` 把目标时刻钳到 `[lastRecordedAt − maxRewindMs, lastRecordedAt]`,注释明说这是 anti-spoof / clock-skew bound(:504-508);未同步(time ≤ 0)读最新样本(live fallback)。
- **「所见即所判」**:`lastSeenBy(sessionId)` 把判定基线设为该客户端最后所见时刻(:558-571)——命中判定对着客户端**实际显示的**位置,而不是 ~RTT 之后的真实位置。
- **双时间线声明**:`RewindMode = "snapshot" | "reckon"`(:42):snapshot = 客户端插值渲染时间线(滞后实时),reckon = 前推外推时间线(≈ serverNow);attach 时声明,且**必须与客户端实际显示该目标的方式成对**(:254-266 "must match how the CLIENT displays this target")。

方向辨析:这是「**权威迁就所见**」——治理手段是把判定基线改到显示时间线,演出本身从不被催赶、不被锁。演出落后被建模为一等公民:有名字的常量、有上界的窗口、有声明的时间线。

**可借**:

- 「落后」显式声明 + 硬上界(≠ 隐式容忍):对应③的落后度量该是显式常量(队列深度/游标差阈值),进 `sc`(`src/app/fx/timings.ts`)登记纪律。
- **step/linear 分档**(:131、:253):离散瞬移不许插值抹平(否则在跳变上 smear),连续运动不许跳变。直接映射我们的病:行军落点是 **step 事件,吸附即正确**;棋子滑移是 linear,平滑即正确。①「提取即定格」的定格对象恰是 step 档事实。
- 时间线/显示模式两端口径必须单源成对声明——对应①的「提取即定格」:提取时刻的口径单源,消费端不许再猜。

**不可借**:整体是 FPS 命中判定需求;我们回合制操作合法性由权威引擎裁定(命令直达权威服),不存在「按客户端所见判命中」。Rewind 治「判定对齐所见」,不治「演出落后堆积」。

### 1b. 客户端 Predict / Reconciler(演出平滑 + 回滚校准)—— `packages/sdk/src/predict/`

**这是③的直接先例。**

机制:

- **演出自治时间线**:`lerp` 模式缓冲近期快照,在 `renderTime − delay`(默认 100ms)处插值渲染(Predictor.ts:110-121)——演出按自己时间线匀速走,权威流何时到达不影响播放节奏。
- **snap 阈值(硬吸附档)**(Predictor.ts:169-184):新样本与前一值差超过阈值 → 判为 TELEPORT,平滑态重置、立即渲染,**不滑过间隙**;且刻意与时间无关("Deliberately time-free":延迟/抖动只改到达时机、不改携带值,突发投递不会误触发);sizing 公式:远大于 `maxSpeed × patchInterval`、小于最小合法瞬移。
- **校准双档(回滚 + 视觉渐变)**(reconciler.ts:8-9、:27-28):逻辑校准 = rewind-and-replay 回滚重放(权威态为恢复点);视觉校准 = misprediction 吸收为 per-field 视觉偏移、几帧内衰减到 0,"corrections never pop"——**逻辑瞬移、视觉渐变**。
- **漂移遥测与分类**(drift.ts:17-46、:73-78):每次 reconcile 的校正量折进 `ema`(持续分量)与 `peak`(衰减峰值)→ `classifyDrift` 分三档:**matched**(双零,无事)/ **jitter**(ema 低 peak 高 = 瞬时网络抖动,平滑吸收,**不校准**)/ **diverging**(ema 高 = 真发散,确定性 bug 级,才校准);硬 resync(重生)时 `resetDrift`(:38-43),防故意跳变污染遥测。

**可借(对③)**:

- **落后检测必须分类,不是布尔**:持续落后(真堆积 → 校准/吸附/丢弃)与瞬时抖动(平滑吸收不动)分开判;ema/peak 双分量的思路可直接搬到「队列深度 EMA vs 单批峰值」。
- **校准分两档**:硬吸附只给「无因果意义」的跳变(teleport 语义;对应我们断线重建、过时批丢弃的生命周期语义——#596「零兜底红线」注记的口径互证),视觉渐变给「有因果意义但有误差」的。
- **硬重置后遥测归零**:我们已有同构物——`resetEventFace()`/`dropStalledBatch()`(snapshot-effects.ts:55-66)重连边界清游标;③是把同一生命周期语义从「断线」推广到「非重连的落后」。
- snap 阈值「与时间无关」的定标原则:我们阈值按「批数/段数」定,不按墙钟,防突发到达误触发。

**可借(对锁解绑)**:Reconciler 的输入**即时生效**(零延迟手感,先本地预测后对账,：8-10),演出误差被吸收为视觉偏移,**从不反压输入**——交互可用性与演出排空天然解耦。映射:interactive 的门挂引擎回合态(轮到谁/什么相位),不挂 `fxQueue.pendingChunks`。

**不可借**:回滚重放依赖客户端本地模拟;我们联机端无本地引擎推进(ADR-0020 折叠),校准 = 换锚/吸附/丢弃,不重放。lerp 的 100ms delay、50ms smoothMs 级常量是连续运动口径,我们以离散事件为主,step(吸附)是主档,渐变档只用于「落后但仍有因果」的加速播放。

## 二、boardgame.io:版本门只在命令面,演出面从不设门 —— `src/master/master.ts`

机制:

- `_stateID` 随每次成功 move 递增(`src/core/reducer.ts`:461、:541、:561 等 `_stateID: state._stateID + 1`;初值 `src/core/initialize.ts`:59)。
- 服务器在 onMessage(MAKE_MOVE) 中核对命令携带的 stateID:**不等即拒并 `logging.error`**,除非该 move 显式声明 `ignoreStaleStateID`(master.ts:290-297)。sync 流程同源取 `prevState._stateID`(master.ts:425)。
- 存在理由:客户端**双跑 reducer**(乐观执行)模型的固有代价——客户端先跑,服务器用 stateID 验「你跑的是不是最新状态」。

方向辨析:这是**命令面**治理——「过期」被建模为命令属性(拒绝重放),从不波及演出;客户端演出正确性靠「渲染下一个权威 update」天然达成,没有演出追赶问题可治。

**可借**:丢弃发生在入口且显式报错(`logging.error`),不是静默吞——与我们零兜底红线同构;「版本化丢弃」语义若③要做「过时演出批丢弃」,丢弃判据应挂在批的到达序/版本号上(我们已有 `eventBatchSeq` 游标),而不是挂在墙钟上。

**不可借**:它治「命令撞过期状态」,不治「演出落后」;其存在依赖客户端双跑 reducer,我们不双跑(命令直达权威服,此类竞态物理不存在——台账「已对过的账」已记,维持 #596 出 scope 裁决)。

## 三、FreeKill:产出端垫时——防堆积先于追堆积 —— `lua/server/request.lua`

机制:

- `Request:ask()` 轮询等待所有被询问者(:203 起);当只剩 AI/人机可答(人类全部离线或发送失败)时置 `ai_start_time`(:262-266),AI 经 `use_ai` 秒答。
- `_finish()` 收尾时对 AI 即时答案**垫时**(:370-373):`to_delay = 800 − (os.getms() − ai_start_time)/1000`,正数则 `room:delay(to_delay)`——**服务器自己 sleep**,保证 AI 答案从询问发出起至少 800ms 才广播,人类观感里 AI「思考」过。`ServerRoomBase:delay` 实现在 `lua/server/roombase.lua`:267-271(yield 等唤醒)。
- `_test_disable_delay` 测试开关(:307 ask 循环;roombase.lua:269-270 delay 直返):测试零等待,与真实延迟同一开关位。

方向辨析:这是**产出端节流(生产限速)**——在权威推进侧插入「人类感知节奏」下限,让演出落后在源头不发生,而不是在播放侧追。

**可借**:

- **治理顺位先例**:防堆积比追堆积便宜。我们已有同位物——ADR-0028 托管单节拍把 bot 产批钉在单节拍上;③的校准阈值定标时必须先确认产出端节拍已收口,否则是下游兜底。
- 测试开关与真实延迟同一开关位,对应我们 e2e 时间倍率仅测试生效的既有纪律。
- 垫时语义 = 演出观感需求**反向约束产出端**的先例:③的阈值同样从观感出发定标(落后多少毫秒/多少批才可感知),不是拍脑袋的内部数。

**不可借**:800ms 是固定墙钟垫,**不测实际落后量**;它防「AI 秒答破坏临场感」,不是「播放速率低于产出速率」的堆积治理——不能替代③的落后检测。

## 六、结论精要(供 #596 立③的实施票)

1. **锁解绑有全仓先例背书**:三仓无一锁交互等演出;interactive 改挂引擎回合态(相位/座位),`pendingChunks` 退化为纯演出内部状态。
2. **③的落后检测用「分类」不用「布尔」**:借 drift.ts 的双分量(持续 vs 瞬时)——持续落后才校准;瞬时抖动平滑吸收。判据挂批的到达序/游标差(`eventBatchSeq` 既有),不挂墙钟。
3. **校准分两档**:硬吸附(换锚/丢弃)只给「无因果意义」的跳变(teleport 语义;断线重建、过时批),渐变/加速给「有因果但有误差」的——与 #596 零兜底红线注记口径互证,是生命周期语义不是容错。
4. **硬重置归零语义已有现成同构**:`resetEventFace`/`dropStalledBatch`(重连边界);③ = 同一语义推广到非重连落后,不新增第二套游标。
5. **治理顺位**:产出端节拍(ADR-0028)→ 播放侧 bound(③);阈值与所有演出常量进 `sc` 登记(`test/e2e-time-scale.test.ts` 恒等快照组)。
