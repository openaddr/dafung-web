# 游戏时机框架(Timing Framework)

> 一句话:**技能/珍宝/地块/全局规则 = 纯数据声明(何时触发)+ 效果函数(做什么)**,统一挂到引擎的时机总线上,不再在 `authority.ts` 各处手写散派。

## 1. 组成

| 文件                                                   | 职责                                                                                                                                                               |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`src/core/timing.ts`](../../src/core/timing.ts)       | 时机定义:`GameMoment` 类型(七类;数量以 `MOMENTS` 注册表为准)+ `MomentCtx` + `MOMENTS` 集中注册表(单一事实源)                                                       |
| [`src/core/effects.ts`](../../src/core/effects.ts)     | 效果注册表:`EFFECTS: Record<EffectId, EffectFn>` + `EffectCtx`                                                                                                     |
| [`src/core/skills.ts`](../../src/core/skills.ts)       | 技能数据表(ADR-0036 技能升一等公民):`SKILLS`(被动+主动同表,技 id 全局唯一)/`TriggerSkill`/`ActiveSkillDef` 类型与池序读口同文件;新增技只改此文件(纯数据)           |
| [`src/core/heroes.ts`](../../src/core/heroes.ts)       | 名将数据表:新增名将只改此文件(纯数据);`HeroDef` 只声明技能池 `skillPool`(按池声明序引用技 id,可跨将共享);招募授技掷子集(单源 `roster.ts` `rollGrantedSkills`,#787) |
| [`src/core/authority.ts`](../../src/core/authority.ts) | 派发器 `GameEngine.dispatchMoment` + 部分时机挂点(其余挂点随结算逻辑住在机制域模块,见 ADR-0019)                                                                    |

术语对齐(用户定义):**回合(turn)**= 一个人行动一次(`engine.turnNumber`);**轮(round)**= 所有人各行动一次(`engine.round`,由 `roundAnchor` 锚定)。

## 2. 时机分类目录

**这是设计技能/事件/地块/全局规则时的灵感目录**:按七类分组,每条给出触发点位、主体(subject)、ctx 字段与技能灵感示例。所有挂点唯一派发、无散派——一律经 `GameEngine.dispatchMoment` 总线(挂点分布在引擎壳与机制域模块的各结算点,划分见 ADR-0019);同一事件链内的先后顺序见各条「顺序」说明。

> **scope 与 ctx 的分工**:`scope` 只按「属主 vs 时机主体(subject)」过滤(self/others/any/actor);
> 「与属主相关的更细条件」(如"*你的*城被落"、"*你*被途经")在效果函数内读 `ctx.ownerSeat/passedSeat/buyerSeat…` 与 `ctx.owner` 比对,不匹配返回 false 静默跳过。

## 3. 三要素

### 时机(GameMoment,`timing.ts`)

时机全量见上文目录;类型上就是字符串联合 + `MOMENTS` 集中注册表(派发器与文档据此校验完备性)。新增时机三步见 §5。

### 派发上下文(MomentCtx / EffectCtx)

```ts
// timing.ts:dispatchMoment 入参,原样透传给效果
interface MomentCtx {
  subject: number; // 时机主体座位(必填)
  die?: number; // 骰面(DieRolled)
  amount?: number; // 金额(CashLost/CashGained/TreasureSold/TradeSettled/BankruptcySettle)
  passedSeat?: number; // 被途经者座位(PassedPlayer)
  ownerSeat?: number; // 城主座位(LandedOnProperty/MarchPassedCity)
  buyerSeat?: number; // 买家座位(TradeSettled)
  sellerSeat?: number; // 卖家座位(TradeSettled)
  creditorSeat?: number | null; // 破产债主座位(PlayerBankrupt;null=无债主归银行/销毁,#384)
  tileIndex?: number; // 涉事格(CapitalHalt/LandedOnProperty/PassedPlayer/WarrantGained/PropertyDemolished/PropertyLost/MarchPassedCity)
  propertyId?: string; // 涉事城(PropertyBought/PropertyGained/PropertyUpgraded/PropertyDemolished/PropertyLost/LandedOnProperty)
  treasureId?: string; // 涉事珍宝(TreasureGained/TreasureSold/TreasureLost)
  heroId?: string; // 涉事名将(HeroRecruited)
  cardId?: string; // 锦囊牌 id(JinnangAnnounced)
  targetSeats?: number[]; // 目标座位集(JinnangAnnounced:全体域=受影响全员,自身域=[使用者])
  reason?: "jinnang" | "exhaustion"; // 跳回合缘由(TurnSkipImposed):缓兵之计/体力耗竭善后
  count?: number; // 实际入手张数(JinnangGained;牌库空落空不派,恒 ≥1)
  targetSeat?: number; // 单一目标座位(PeekApplied 被窥者)
  delta?: number; // 变更量(带符号,夹紧后实际值;StaminaChanged/ReputationChanged)
  cities?: string[]; // 被收走的城 id 列表(AssetsSeized:破产终局资产转移)
  treasureCount?: number; // 被收走的珍宝件数(AssetsSeized;名将是释放非转移,不计数)
}
// effects.ts:EffectCtx = MomentCtx + { moment, owner }
```

### 技能(TriggerSkill,`skills.ts`)——技能即数据

```ts
export interface TriggerSkill {
  id: string; // 唯一 id(技名拼音,如 "jixing"),同时是冷却键
  name: string; // 技名(如 "疾行";纯展示,不参与判定,#358)
  when: GameMoment; // 触发时机
  effect: string; // EffectId,查 effects.ts 注册表
  params?: Record<string, number>; // 效果参数(纯数据,可序列化)
  cooldown?: number; // 冷却(单位:轮;键=skill.id,记于麾下槽位 lastFired——各槽各账,#785)
  scope?: "self" | "actor" | "others" | "any"; // 属主与主体/行动者的关系,缺省 "self"
}
```

**scope 语义(定案)**——属主(owner)= 技能持有者座位,主体(subject)= 时机相关玩家座位:

- `"self"`:属主是时机主体(`owner === subject`,我的骰/我的失财/我的回合…)。
- `"others"`:主体不是属主(`owner !== subject`,别人失财/别人掷骰…)。
- `"any"`:主体不限(任何人,含属主自己)。
- `"actor"`:时机主体恰为当前行动玩家(`subject === activeIndex`,属主不限)。
- 主体并非当前行动玩家的时机已存在(如 `PlayerBankrupt` 的破产者、`AssetsSeized` 的债主、`TurnSkipImposed` 的被跳者),这些时机上 `actor` 与 `any` 分化;「与属主相关的细分」(如"*你的*城被落")在效果内读 ctx 比对,scope 不背这个职责。

### 效果(EffectFn,`effects.ts`)

```ts
export type EffectFn = (
  engine: GameEngine,
  ctx: EffectCtx,
  params: Record<string, number>,
) => boolean;
```

- 返回 `true` = 生效(派发器记战报 + 冷却);返回 `false` = 条件不满足,**静默跳过**(不记战报/冷却,如 `gainIfFace` 骰面不匹配)。
- 效果只能通过引擎方法改状态(现有效果通道:`addMarchBonus`/`takeMarchBonus`/`grantSkillCash`),浮字经 `grantSkillCash` 自动入队;战报(skill 击发行)由派发器统一记录。
- **零兜底**:EffectId 查不到 → 派发器抛错;必填 params 缺项(`req`)→ 抛错。都是数据 bug,直接崩。

## 4. 派发器(`GameEngine.dispatchMoment`)

```
dispatchMoment(moment, ctx: MomentCtx)
  ├─ 派发深度 +1;> 2 层 → 抛错(不变量校验,防递归)
  ├─ 按座位序遍历所有未破产玩家 × 麾下槽位序 × 槽内已授技序(=池声明序,#785):
  │    when 匹配 → scope 过滤 → cooldown 检查(槽内账)→ 查 EFFECTS(未知→抛错)
  │    → 执行效果;返回 true 才记 slot.lastFired[skill.id] = round + logEvent("skill", …)
  └─ 派发深度 -1(finally)
```

**确定性**:同层派发顺序 = 座位序 × 麾下槽位序 × 槽内已授技序,与行动顺序/随机数无关;固定 seed 的对局触发序列完全可复现(`test/timing.test.ts` 稳定性断言)。

**禁递归**:效果内同步再派发时机最多嵌套一层(顶层 + 1);第 3 层直接抛错。这是不变量校验而非兜底——效果链递归是框架 bug,必须崩出来。另见 §2.6 的 **CashGained 防连锁**(经济结算点单侧派发,效果层不递归)。

**零新增序列化状态**:全部派发点为派生调用,不落新增快照字段;麾下=槽位(`roster.ts` `{heroId, skillIds, lastFired}`),槽位全量随快照走(技定义单源 `skills.ts`,展示字段按 heroId 回查 `heroes.ts`);冷却内嵌槽位(`lastFired`,键=`skill.id`)。`snapshot-contract` 契约测试自动覆盖一致性。

## 5. 扩展指南

### 加一个效果(一步,`effects.ts`)

```ts
// 1. 在 EFFECTS 注册表加一项(必填参数用 req 读,缺项自动抛错)
export const EFFECTS: Record<string, EffectFn> = {
  // …
  /** 回血:params { amount } */
  heal: (engine, ctx, params) => {
    engine.grantSkillCash(ctx.owner, req(params, "amount")); // 复用引擎效果通道
    return true;
  },
};
```

### 加一个技能(`skills.ts` 技表 + `heroes.ts` 池声明)

```ts
// 1. skills.ts 的 SKILLS 表加一条纯数据(技 id 用技名拼音、全局唯一,被动+主动同表):
```
