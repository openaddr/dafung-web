# 联机架构

联机把裁决集中在一台服务器，玩家设备按权威结果更新画面。每局各有独立的房间编排和状态。对战操作见[联机指南](../how-to/联机对战.md)。

## 2. 拓扑

```
   Android Tauri APK（自带界面，大厅可填联机地址）
     │ HTTPS / WSS
   公网入口（运维者通过 1Panel 管理）
     │ HTTP / WS
   联机服务（Bun，systemd 守护）
     ├─ HTTP 大厅
     ├─ WebSocket 对局
     └─ 房间快照和对局日志落盘
```

联机 API 的跨源响应和预检由[服务端入口](../../apps/server/src/server.ts)处理。

## 5. 同步模型(事件流口径,折叠切换⑥ #388 落地)

同步模型按 [ADR-0020](../adr/0020-event-stream-sync-model.md) 切换,链路:**命令直达权威服 → 引擎产出事件批 → 服务端广播(唯一状态通路)→ 客户端折叠 + 校准锚**。

- **事件批是唯一对局状态通路**:每次编排转移(人类命令/bot 步/开局驱动)引擎产出类型化事件批(词汇表 `packages/core/src/engine/game-events.ts`);服务端按 flush 节奏合并(本 tick `setTimeout(0)` 统一排空,快速托管局数百步 bot 连锁合并为一批),以 `{type:"events"}` 消息逐座位下发。逐座位下行装配(#431)只经一个口:`packages/core/src/room/seat-projection.ts` 的 `assembleDownlinkShot`——事件批与整房摘要一次配齐,**redaction 是装配必经步而非调用纪律**:签名带 `viewerSeat`,传座位即裁剪流(联机必裁;将来回放类消费面复用本口,传座位默认拿裁剪流),传 `null` 即显式 god-view 退化(单机内存直连唯一合法取值)。同一 flush 内**先发事件批、后发快照**(因果在前、状态在后),WS 有序保证客户端折叠时读到转移后状态。
- **落格决策事实(#1497)**:`marchArrived` 只宣告位置与路径;城池固定事件落账后,权威通过 `landingResolved` 下发最终相位、`pendingLand`、`treasureVisitor`、`lastLandOutcome` 及固定事件续接标记。折叠器直接采用该事实,不按到达时的现金/归属预测后续决策。招贤闭窗转购地、扩军或交涉也走此事件,清除已完成的候选与续接载荷;自动结束回合走既有回合事件,不以落格事实覆盖新回合。该事件全桌公开、无独立表现、非校准触发源;招贤候选仍由既有入窗校准提供。
- **摸牌、体力与研读**。起手、实际回合及己城摸牌均走 `jinnangDrawn`。普通座位读取张数，持有者还收到牌面。体力变更与耗竭公开，待决技能以公开的选择事件呈现，续接由权威端保存。求书按珍宝入册事件同步，研读的 `skillLearned` 同时更新名将技能和消耗的书。重连时由座位投影快照恢复这些结果。
- **正常对局零逐步快照**,全量下行只剩三类(#381 起按接收座位投影):
  1. **整房摘要**——WS 建连(首连/重连)时该座位的 per-seat 投影一份(`clientView` 带座位);
  2. **关键节点校准**——flush 时按引擎公开结算态判定(零启发式):Setup 三段式全程 + finishSetup 批、实际破产批(`playerBankrupt`)、决策窗(出牌阶段/招贤/破产清算)进入及停留。退出闭沿仅在空批或含 `CALIBRATION_BACKED_KINDS` 时附摘要;普通非空事件批自行完成状态转移。校准承载事件尚未表达的上下文(`offeredHeroes`/`pendingJinnang` 等私有载荷),快照水合覆盖折叠后的字段。触发登记(#431 类型化归口 `packages/core/src/room/seat-projection.ts`):`CALIBRATION_WINDOWS: ReadonlySet<TurnPhase>` / `CALIBRATION_EVENT_KINDS: ReadonlySet<EventKind>`——phase/kind 改名 = 编译红;与折叠端不折清单的覆盖对账单源 `CALIBRATION_COVERAGE`(档位表 `core/event-tiers.ts` 的 calibration-only kind 逐个点名覆盖触发,漏点名 = 编译红);
     清偿成功另有 `bankruptcySettled` 完成事实:携带付款人与债主的结算后现钱并清空债务,在交割及相关技能时机后、结束回合前产生。只卖城偿还银行债也能仅凭事件批完整收口,不依赖闭沿额外快照;既有交易付款事件不会使收付款重复计算。
  3. **房间元数据**——lobby 形状(座位在线/房主/托管),指纹变化才发;对局中掉线/托管开关不再搭快照车(元数据全桌公开,无 per-seat 面)。
- **客户端**:事件批折叠进本地只读引擎副本(`apps/client/src/app/net/event-fold.ts` 纯函数投影,折叠投影全覆盖见 #387),动效照读因果(`apps/client/src/app/fx/event-extract.ts`);一次事件批一次重渲,命令在途锁由事件批帧(或空批转移时的决策窗校准快照)解锁。
- **对局诊断**使用已入座的连接接收权威日志。校准摘要中有该座位可见的全部日志，普通拍由 `gameLog` 交付的尾段独立写入本机归档。解散通知前送出剩余行，重连后从新摘要接续。游戏状态仍由既有事件批和校准推进。见 [对局日志](../reference/对局日志.md)。
- **客户端自校准(表现落后治理,#610,[ADR-0029](../adr/0029-presentation-self-consistency-invariants.md) 不变量③)**:校准触发源共两道(ADR-0020 决策 3 修订)——服务端结算节点(上条「关键节点校准」)+ 客户端按积压自追帧/自吸附。表现消费出队点(`apps/client/src/app/net/snapshot-effects.ts`)以混合尺判落后度:主尺 = 未消费批数、辅尺 = 最早未播批等待时长(阈值表 `apps/client/src/app/fx/timings.ts` `LAG`;判据走到达序,机器时间,负载免疫),分类非布尔:单次超线升**追帧**(演出编排时长经 `scStage()` 除法压缩——积压越深倍率越高、播得越快;界面/节拍类时长只吃 e2e 键不进追帧),连续 `LAG.consecutiveForSnap` 批超线才升**吸附**(过时演出整块作废、棋子直切终态)。观感全静默,诊断计数挂 `__dafung.fxCatchup` 调试桥(`E2E_DEBUG_BRIDGE_KEY` 门禁)。交互锁同链解绑(#611):`canAct` 只等本座位演出落定,全局队列积压不进门——轮到你时决策卷轴照弹,他人棋子照飞。过滤批对折叠器零感知——事件到了就是「我能看的」(`consumeCard` 对暗牌数组恒空的口径、闭窗算术对询问集数量的依赖,均已按投影形态对齐)。
- **重连 = 整房摘要 + 清批**:断线期间事件不补发(无 seq/ack);底层连接打开先把事件面整体归零(netStore 暂存批/到达计数/表现消费游标成对清),状态唯一来源 = 紧随其后的整房摘要。连接打开仍处于 `calibrating`,当前摘要水合完成后 `OnlineController.sessionReady` 才成立并恢复操作;未开局大厅以当前连接的未开局 lobby 摘要完成校准,对局中的 started 元数据不能代替局面摘要。服务器重启后旧批不重发(恢复房间时登记事件批基线,见 server.ts `seenBatches`)。
- **断线即丢**:无排队、无补发、无可靠性机制,可靠性全靠重连全量;漂移纯信任(不做哈希对账、不做版本仲裁),由权威摘要与校准点纠偏。客户端保留断线时的只读局面,不重放已失效的演出。
- **保密口径(#381,ADR-0020 决策 2 后补兑现)**:三类秘密不出网——①他人锦囊手牌内容(快照 players[].jinnangHand 恒空,数量走引擎态 `jinnangHandCount`);②锦囊牌库序(快照 `jinnangDeck` 恒空,剩余数走 `jinnangDeckCount`);③反应窗询问集(快照 `reaction`、`pendingReaction.view` 与 `reactionOpened.view` 共用 `queriedBySeat` 裁剪口径——jinnang 窗**身份匿名、数量保留**:自己座位保留,他人一律置换 -1 占位;数量必须保留,否则折叠器「应答数 ≥ 询问数」的闭窗算术在首条应答即全员误闭窗,#461;march 窗全公开原样)。其余公开事件全桌原样透传(逐 kind 审计表见 `packages/core/src/room/seat-projection.ts` `redactEvents` 头注;`jinnangDrawn` 本就是 count-only 设计;`treasureStolen` 的牌名是明置信息——珍宝列表全员可见、战报公开记名)。未知事件 kind 过滤时当场炸:新增事件必须先在 `redactEvents` 登记隐私档位(与 ADR-0016「新增载荷登记」同纪律)。单机通路(`room.ts` `connectSeat`/`flushTransport`,本机单真人)无跨设备泄密面,保持 god-view 不在保密范围内——#431 起该退化收口为装配签名上的显式 `viewerSeat: null`,「忘了裁」不再是可能形态,双模式行为由 `test/online/downlink-assembly.test.ts` 锁定。
- **反应窗公告（#1511）**：事件直接下发权威窗号和公告视图。快照在闭窗后仍保留最后分配的编号，对局恢复时继续编号。事件批与重连摘要为被询问座位附上当前窗号及剩余时间，时长取自房间看门狗共用的截止时刻。反应窗展示和选份从公告读取影响对象。火烧连营的对象用城格编号，出牌指示线继续用受击城主的席位号。最后一条应答携带实际消耗的反应锦囊，副本在这一步统一扣账。
- **wire 协议编解码单源(#429)**:上行消息 union(`cmd`/`pickCapital`/`autoPilot` 三族)、解析分发(`dispatchInbound`——**错误回报是返回值的一部分**,分 `badJson`/`unknownShape`/`rejected` 三类,任何失败都不抛出传输层之外)与下行构造(`eventsMsg`/`errorMsg`/`dismissedMsg` + `encodeDownlink` 封装单口)全部收口 `packages/core/src/protocol/wire.ts`;cmd 座位校验(#454)前置在编排层(`room.ts` `applyCommandFromSeat`):WS 连接只能以本连接绑定的座位提交命令——`respondReaction` 须为本窗**被询问座位**且未应答(`cmd.seat` 必须=提交者座位,替他人应答即越权),其余命令须为**决策归属座位**(`decisionSeatOf`:Setup=当前选都位,Playing=`decisionOwner`,含珍宝交涉城主与清算抉择者),不归属一律 403 经 error 消息回执;内部通路(bot-driver/watchdogs 直调 `applyCommand`、单机 `local.ts`)不经此口。两个传输面(adapter)只负责把失败送到各自通道——**WS = error 消息下行**(联机,含 #428 的非法命令回报),**内存 = pushHint**(单机;结构性失败在内存面结构上不可能,真出现 = 自身 bug 照炸,零兜底)。lobby/snapshot 两类下行的载荷产出仍单源 `packages/core/src/room/seat-projection.ts`(redaction 归属见「保密口径」),编解码只管类型与封装;客户端(`online.ts`/`local.ts`)与服务器从此 import 同一份类型与 dispatch 本体,「逐字同契约」双写与注释互指退役,新增消息类型漏任一侧 = 编译红(穷尽 switch 收 never)。形状与错误分类由 `test/online/wire.test.ts` 锁定。

## 6. 掉线座位保留窗口与重连令牌

- `seatToken` 标识房间内的座位归属，与房间存续同寿命。`RETENTION_WINDOW_MS` 到期时，看门狗可以开启托管，原玩家仍可凭令牌归座。`DECISION_TIMEOUT_MS` 用于处理停摆决策，以自身定时器计时。配置入口见[配置与数据](../how-to/部署服务器.md#配置与数据)。
- 断线后，`OnlineController.reconnect` 复用当前房间、座位和令牌建立新连接，并等权威摘要完成 `sessionReady`。退出时统一由 `returnHome` 销毁传输、重连链与房间状态，旧实例的回调失效。玩家按钮见[应对断线](../how-to/联机对战.md#应对断线)。
- 保留窗口由入局后断线触发。开局前断线及服务器重启前已有的断线座位仍按令牌归座和决策停摆规则处理。房间持久化与恢复见[恢复测试](../../test/online/room-recovery.test.ts)，托管操作见[回合与行军](../reference/rules/03-回合与行军.md#托管与代打)。

相关决策见 [ADR-0005](../adr/0005-seat-ownership-by-token.md) 与 [ADR-0028](../adr/0028-takeover-is-autopilot.md)。

## 7. 运行模型

单个 Bun 进程维护多个房间。房间记录由文件适配器持久化，重启时复原。开发网页由 Vite 托管，生产服务独立为 APK 提供联机接口。监听、目录、安装与回滚查[部署服务器](../how-to/部署服务器.md)。

## 9. 单机形态:「服务器住在本进程」(单机统一 #379,#397..#400)

单机不再是与联机平行的锁步实现——**同一份房间编排**(`packages/core/src/room/room.ts`,零 WS/零 node 依赖,双运行时同构)只差传输介质:

- **拓扑**:浏览器进程内起 `RoomRegistry`(内存持久化,无跨进程恢复语义),`LocalController`(`apps/client/src/app/controllers/local.ts`)经 **MemorySocket**(`apps/client/src/app/net/transport.ts` 内存双工)与其互连。命令上行经 wire 协议编解码单源(`packages/core/src/protocol/wire.ts` #429,与联机 WS 同一份 parse/dispatch 本体,见 §5);下行同走「事件批先行、校准摘要随后」的单拍 flush(编排传输面 `transportBroadcast`)。
- **同一通路**:命令路由(applyCommand/pickCapital/setAutoPilot)、bot 链(driveBots)、看门狗(#118 停摆/#188 自动起摇/#281 反应窗)、事件产出与演出消费(SnapshotEffects → extractBatchEvents,ADR-0020 事件直译)全部与联机同一份代码;单机与联机从此只差「传输在不在网上」。
- **状态 = 协议水合副本**([ADR-0066](../adr/0066-local-protocol-hydration.md)):控制器持独立副本,构造时先开局、再入座,首连整房摘要同步水合;此后事件批先折叠再经 `syncFromEngine` 写入 store,校准摘要无条件覆盖。决策归属与交互读取副本,行军位置锚在折叠/水合前捕获。权威引擎只留在房间编排侧。
- **校准与房间字段**:自动下行复用服务器的 `CALIBRATION_WINDOWS`、`CALIBRATION_EVENT_KINDS` 与 `CALIBRATION_BACKED_KINDS` 口径,普通事件拍不随发全量快照;房间元数据指纹变化时发送 `lobby` 消息。托管从下行座位表回读,单机不写 `netStore` 的联机房间字段。Worker 挂死的异常终局立即完整下行;换局销毁仍解散房间并清理看门狗、时钟与传输残表,不提供跨进程重连。
- **Worker 时钟**(#399):回合节拍唯一定义在 `packages/core/src/engine/timings.ts`(AUTO_ROLL_DELAY_MS / AUTOPILOT_STEP_MS,单机联机同表;e2e 时间倍率只缩放演出编排,不进权威节奏)。编排定时经 `RoomClock` 注入——服务器 = 宿主全局定时器;单机 = `apps/client/src/app/net/worker-clock.ts` 的 Web Worker 时钟,减少 WebView 主线程的定时影响;回前台演出队列按落后校准追平——浅积压追帧加速、持续落后吸附作废,不重放(事件通路既有语义 + [ADR-0029](../adr/0029-presentation-self-consistency-invariants.md) 不变量③);交互解锁只等本座位演出落定,不锁等全队列排空(#611)。
- **单机配套**:对局日志仍走 ADR-0014 浏览器侧 IndexedDB 归档(挂权威编排的 persist 通道);托管与联机使用同一协议消息,不建立绕过下行的权威读写口。
