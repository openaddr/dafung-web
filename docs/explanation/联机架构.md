# 联机架构

联机把裁决集中在一台服务器，玩家设备按权威结果更新画面。每局各有独立的房间编排和状态。对战操作见[联机指南](../how-to/联机对战.md)。

## 2. 拓扑

```
   Android Tauri APK（自带界面，大厅可填联机地址）
     │ HTTPS / WSS
   公网入口（运维者通过 1Panel 管理）
     │ HTTP / WS
   联机服务（Bun，systemd 守护）
     ├─ HTTP 大厅
     ├─ WebSocket 对局
     └─ 房间快照和对局日志落盘
```

联机 API 的跨源响应和预检由[服务端入口](../../apps/server/src/server.ts)处理。

## 4. 宿主与协议

服务端通过 HTTP 提供大厅，通过 WebSocket 传输对局命令和状态。客户端控制器经只读副本驱动界面。文件职责见[代码地图](../reference/代码地图.md)，包边界和独立构建见 [ADR-0072](../adr/0072-workspace-packages-and-server-artifact.md)。

安卓与无界面玩家共用房间 HTTP 接口建房、入座、选图和开局，房主权限由服务端校验。认证连接先接房间状态，开局后用同一条连接读取座位摘要。主动离开关闭本机连接，离线房主按规则移交。现任房主解散时，服务端向各在线席发送 `dismissed` 再关闭连接。

建房、选图、原座恢复、房主移交和解散都由[真实房间的玩家入口](../../test/online/headless-lobby.test.ts)验证。暗牌和多人反应窗见[真 WebSocket 双端用例](../../test/online/online-dual-run.test.ts)。

## 5. 同步模型(事件流口径,折叠切换⑥ #388 落地)

同步模型按 [ADR-0020](../adr/0020-event-stream-sync-model.md) 切换,链路:**命令直达权威服 → 引擎产出事件批 → 服务端广播(唯一状态通路)→ 客户端折叠 + 校准锚**。

- **事件批是唯一对局状态通路**:每次编排转移(人类命令/bot 步/开局驱动)引擎产出类型化事件批(词汇表 `packages/core/src/engine/game-events.ts`);服务端按 flush 节奏合并(本 tick `setTimeout(0)` 统一排空,快速托管局数百步 bot 连锁合并为一批),以 `{type:"events"}` 消息逐座位下发。单机内存连接和联机 WebSocket 都经过 `assembleDownlinkShot`，按已入座的座位裁剪事件和摘要。同一 flush 内**先发事件批、后发快照**(因果在前、状态在后),WS 有序保证客户端折叠时读到转移后状态。
- **落格决策事实(#1497)**:`marchArrived` 只宣告位置与路径;城池固定事件落账后,权威通过 `landingResolved` 下发最终相位、`pendingLand`、`treasureVisitor`、`lastLandOutcome` 及固定事件续接标记。折叠器直接采用该事实,不按到达时的现金/归属预测后续决策。招贤闭窗转购地、扩军或交涉也走此事件,清除已完成的候选与续接载荷;自动结束回合走既有回合事件,不以落格事实覆盖新回合。该事件全桌公开、无独立表现、非校准触发源;招贤候选仍由既有入窗校准提供。
- **摸牌、体力与研读**。起手、实际回合及己城摸牌均走 `jinnangDrawn`。普通座位读取张数，持有者还收到牌面。体力变更与耗竭公开，待决技能以公开的选择事件呈现，续接由权威端保存。求书按珍宝入册事件同步，研读的 `skillLearned` 同时更新名将技能和消耗的书。重连时由座位投影快照恢复这些结果。
- **正常对局零逐步快照**,全量下行只剩三类(#381 起按接收座位投影):
  1. **整房摘要**——WS 建连(首连/重连)时该座位的 per-seat 投影一份(`clientView` 带座位);
  2. **关键节点校准**——flush 时按引擎公开结算态判定(零启发式):Setup 三段式全程 + finishSetup 批、实际破产批(`playerBankrupt`)、决策窗(出牌阶段/招贤/破产清算)进入及停留。同一出牌窗只有私有目标步骤推进时，发相应的事件批。退出闭沿仅在空批或含 `CALIBRATION_BACKED_KINDS` 时附摘要;普通非空事件批自行完成状态转移。校准承载事件尚未表达的上下文(`offeredHeroes`/`pendingJinnang` 等私有载荷),快照水合覆盖折叠后的字段。触发登记(#431 类型化归口 `packages/core/src/room/seat-projection.ts`):`CALIBRATION_WINDOWS: ReadonlySet<TurnPhase>` / `CALIBRATION_EVENT_KINDS: ReadonlySet<EventKind>`——phase/kind 改名 = 编译红;与折叠端不折清单的覆盖对账单源 `CALIBRATION_COVERAGE`(档位表 `core/event-tiers.ts` 的 calibration-only kind 逐个点名覆盖触发,漏点名 = 编译红);
     清偿成功另有 `bankruptcySettled` 完成事实:携带付款人与债主的结算后现钱并清空债务,在交割及相关技能时机后、结束回合前产生。只卖城偿还银行债也能仅凭事件批完整收口,不依赖闭沿额外快照;既有交易付款事件不会使收付款重复计算。
  3. **房间元数据**——lobby 形状(座位在线/房主/托管),指纹变化才发;对局中掉线/托管开关不再搭快照车(元数据全桌公开,无 per-seat 面)。
- **客户端**:事件批折叠进本地只读引擎副本(`packages/core/src/protocol/event-fold.ts` 纯函数投影,折叠投影全覆盖见 #387),动效照读因果(`apps/client/src/app/fx/event-extract.ts`);控制器按事件批或校准摘要更新局面。选都、连环计和反应应答的操作锁跟随回执与决策点一并更新。
- **战报与诊断**都消费已入座连接交付的公开日志。首连和校准摘要提供公开前缀，普通更新由 `gameLog` 交付公开尾段。安卓和无界面玩家按同一套公开行号接续，安卓同时写入本机归档。解散通知前送出剩余行，重连从新摘要接续。玩法状态继续由既有事件批和校准推进。见[对局日志](../reference/对局日志.md)。
- **沙盘与城池详情**在安卓和无界面端共用座位查询。查询把当前地图与已投影的座位局面关联起来，提供公开棋子位置、城池归属、等级、防御及经济信息。实际走过的格序随 `marchArrived` 或 `capitalHalt` 事件交付，首连和重连摘要提供当前棋盘状态。
- **客户端自校准(表现落后治理,#610,[ADR-0029](../adr/0029-presentation-self-consistency-invariants.md) 不变量③)**:校准触发源共两道(ADR-0020 决策 3 修订)——服务端结算节点(上条「关键节点校准」)+ 客户端按积压自追帧/自吸附。表现消费出队点(`apps/client/src/app/net/snapshot-effects.ts`)以混合尺判落后度:主尺 = 未消费批数、辅尺 = 最早未播批等待时长(阈值表 `apps/client/src/app/fx/timings.ts` `LAG`;判据走到达序,机器时间,负载免疫),分类非布尔:单次超线升**追帧**(演出编排时长经 `scStage()` 除法压缩——积压越深倍率越高、播得越快;界面/节拍类时长只吃 e2e 键不进追帧),连续 `LAG.consecutiveForSnap` 批超线才升**吸附**(过时演出整块作废、棋子直切终态)。观感全静默,诊断计数挂 `__dafung.fxCatchup` 调试桥(`E2E_DEBUG_BRIDGE_KEY` 门禁)。交互锁同链解绑(#611):`canAct` 只等本座位演出落定,全局队列积压不进门——轮到你时决策卷轴照弹,他人棋子照飞。过滤批对折叠器零感知——事件到了就是「我能看的」(`consumeCard` 对暗牌数组恒空的口径、闭窗算术对询问集数量的依赖,均已按投影形态对齐)。
- **重连 = 整房摘要 + 清批**:断线期间事件不补发(无 seq/ack);底层连接打开先把事件面整体归零(netStore 暂存批/到达计数/表现消费游标成对清),状态唯一来源 = 紧随其后的整房摘要。连接打开仍处于 `calibrating`,当前摘要水合完成后 `OnlineController.sessionReady` 才成立并恢复操作;未开局大厅以当前连接的未开局 lobby 摘要完成校准,对局中的 started 元数据不能代替局面摘要。服务器重启后旧批不重发(恢复房间时登记事件批基线,见 server.ts `seenBatches`)。
- **断线即丢**:无排队、无补发、无可靠性机制,可靠性全靠重连全量;漂移纯信任(不做哈希对账、不做版本仲裁),由权威摘要与校准点纠偏。客户端保留断线时的只读局面,不重放已失效的演出。
- 每个座位能看见自己的手牌，以及其他座位的手牌张数。房间把可选锦囊和已确认的私有目标发给抉择者，军情密探的牌面只随当次生效事件发给窥探者。摘要省去随机游标、反应结算载荷和历史事件批。锦囊窗的询问名单保留席数和本人身份，其余身份匿名。
- **反应窗公告**。权威在 `reactionOpened` 中公布窗号、作用对象、是否需要选份及合法候选。开窗事件和重连摘要携带同一公告，逐座位投影按上述口径匿名化锦囊窗的询问座位。客户端按公告显示可选城格或席位，bot 在同一候选范围内估损。选份应答携带对象种类和编号，由权威按公告校验。种类或编号有误、遗漏必选份时，权威拒绝命令，座位仍可应答。客户端收到与本次应答编号相符的拒绝回执后，恢复该次应答的交互。被询问座位收到当前窗号和剩余时间，时长取自房间看门狗记录的共用截止时刻。快照在闭窗后仍保留最后分配的编号，对局恢复时继续编号。最后一条应答携带实际消耗的反应锦囊，副本据此统一扣账。具体选份见[反应窗规则](../reference/rules/06-锦囊.md#反应窗)。
- **锦囊演出事实**。`jinnangAnnounced` 携带出牌者和指示线指向的座位。火烧连营按宣布时指向的城主去重，「处变不惊」使用同一组宣布座位。`jinnangVoided` 携带生效识破者、被拆的锦囊及结果对象。客户端按批内事件顺序定位线端、生成判词，重连后收到的新事件沿用同一通路。见 [ADR-0075](../adr/0075-reaction-selection-and-presentation.md)。
- **wire 协议编解码**使用同一个 `dispatchInbound` 解析和分发 `submit`、`cmd`、`autoPilot`。失败分类为 `badJson`、`unknownShape` 或 `rejected`。联机命令在房间编排层校验连接所属的座位。反应应答要求提交者是本窗尚未回答的被询问座位，其余命令要求提交者是决策方。单机内存双工和联机 WebSocket 都使用同一个下行编码，内存上行的结构性失败直接抛错。[协议定义](../../packages/core/src/protocol/wire.ts) · [协议测试](../../test/online/wire.test.ts)
- 选都、基础出牌、落格地产抉择和反应应答经 `submit` 上行。房间、认证座位、决策点和提交编号共同标识这笔操作。权威端校验资格、对象和资源，把处理结果与局面一起保存，向原席回送 `submissionResult`。断线后原席先接收新的座位摘要，再原样重发仍未取得回执的指令，同一编号只结算一次。
- 选都期间，全席看见当前选都者和棋盘候选。只有当前有权选都的座位收到 `decisionPoint` 与 `decisionOptions`。`pickCapital` 选项附城格、地产编号、建城费、可用性和不可用原因，该席从同一局面读余额。按本步候选提交 `pickCapital` 后，所有座位从 `capitalSelected` 应用扣费、都城、落位和城池初始归属与城防。随后按开局校准同步候选与首动席。拒绝回执以 `reasonCode` 区分越席、过期、非法城格、建城费不足和提交编号冲突。[选都规则](../reference/rules/02-开局.md#选都) · [选都验收](../../test/online/capital-submission.test.ts)
- 出牌阶段的选择由房间交给当前有权出牌的座位。无目标锦囊按选中牌位确认，结束出牌也经当前决策点提交。进入起摇后，房间自动推进，逐席交付骰点、实际路线、途经补给和到达。服务器恢复到待起摇时由房间继续调度。
- 购城与免费扩军按权威最终落格开放选项。落格座位读取城池引用、费用和可用选项，选择购买、扩军或放弃后取得回执。城池归属、银两、城防和换席从玩法事件推进。银两不足或己城满级时，房间按现行默认行为推进。
- 招贤只向当前抉择席交付可选名将、预先抽定的技能、求书和跳过选项，招贤结束后按原落格结果续行。珍宝交涉只向城主交付候选与各交易报价，访客可观察交易和交割结果。进入清算后，权威把欠款、现金、可变卖资产和价格一并交给欠款席。该席确认一次资产清单或主动认破产，其他席位从公开结算事件观察结果。
- 名将「你可」由技能属主读取当前询问、既定目标或候选座位，并选择发动或暂不发。权威处理后继续原技能时机，其他席位观察发动及受影响的公开结果。
- 出牌阶段按本席交付主动技的可用性、剩余冷却和候选目标，也交付持有的技能书与可学习者。玩家按名将与技能确认发动，或按书册与名将确认学习。符合遣散条件的行动席读取本次可操作的名将及原因，确认后从事件取得名册和折书结果。
- 安卓和无界面客户端都通过 `SeatInteraction` 草选和确认都城、选择具体手牌、暂选目标、返回或取消。客户端可以读取自己的草选。已确认的步骤由房间恢复。字段和验收场景见 [ADR-0076](../adr/0076-player-interaction-protocol.md)。
- 连环计进入目标步骤、确认第一位、返回或取消时，房间将已确认的牌位和当前选项通过 `jinnangTargetStepChanged` 发给出牌者。其他席位只在出牌公开后收到牌名和目标，私有步骤在公开日志和调试尾段中均不产生记录。按份应答的对象在实时事件和重连摘要中均只发给应答者。
- 反应应答在房间处理指令时按权威截止时间校验。受问席在窗内收回托管时，房间只向该席更新原决策点和剩余时间。已答席位在等待其他席位期间关闭该窗的应答入口。回执未能交付时，原座重连后按同一编号重发。测试房可注入房间时钟，交互指令统一经普通座位连接提交。
- 反应选项给出本席可用的具体手牌和合法份。同窗同份按座次结算，实际打出时扣除应答时选择的那张。应答所选的份和手牌位置只供持牌席回读。「本回合不再询问」由共享座位交互通过普通「不出」应答后续窗，换回合恢复询问。
- 开托管和收回使用本席独立的控制授权，所以在其他席行动时也能切换。控制进度、托管状态和提交回执一并保存，其他席从房间座位表观察托管状态。重连后本席按最新控制授权操作，已经保存的原提交可取回原回执。
- **命令结果取证**使用 `requestId` 配对发出和回执。普通命令明确拒绝走带号的 `error`，处理完成、告警或未处理走 `commandResult`。选都、连环计和反应应答可用同一请求号关联 `submissionResult`。告警回执带公开说明与对局日志序位。回执和座位日志使用权威检查记录的公开分类，例如阶段不符时列出所需与当前回合相位。其余告警给出通用说明，原文留在服务器日志。回执供客户端诊断使用，客户端副本的状态更新由事件批和校准摘要提供。[对局诊断](../reference/对局日志.md#单局诊断文件)

## 6. 掉线座位保留窗口与重连令牌

- `seatToken` 标识房间内的座位归属，与房间存续同寿命。`RETENTION_WINDOW_MS` 到期时，看门狗可以开启托管，原玩家仍可凭令牌归座。`DECISION_TIMEOUT_MS` 用于处理停摆决策，以自身定时器计时。配置入口见[配置与数据](../how-to/部署服务器.md#配置与数据)。
- 断线后，安卓与无界面玩家都用原房间、座位和令牌授权新连接，当前局面和托管状态来自本席摘要。安卓在摘要到达后完成 `sessionReady`，退出时由 `returnHome` 销毁本机传输、重连链与房间状态。玩家按钮见[应对断线](../how-to/联机对战.md#应对断线)。
- 保留窗口由入局后断线触发。开局前断线及服务器重启前已有的断线座位仍按令牌归座和决策停摆规则处理。房间持久化与恢复见[恢复测试](../../test/online/room-recovery.test.ts)，托管操作见[回合与行军](../reference/rules/03-回合与行军.md#托管与代打)。
- 活跃反应窗的窗号和权威截止时刻与局面一起保存。服务器重启后按原时刻计算剩余时间，到期时以普通「不出」为未答席推进。原回执仍可重发取回。见[真实服务器重启验收](../../test/online/reaction-deadline-recovery.test.ts)。

相关决策见 [ADR-0005](../adr/0005-seat-ownership-by-token.md) 与 [ADR-0028](../adr/0028-takeover-is-autopilot.md)。

## 7. 运行模型

单个 Bun 进程维护多个房间。房间记录由文件适配器持久化，重启时复原。开发网页由 Vite 托管，生产服务独立为 APK 提供联机接口。监听、目录、安装与回滚查[部署服务器](../how-to/部署服务器.md)。

## 9. 单机形态:「服务器住在本进程」(单机统一 #379,#397..#400)

单机不再是与联机平行的锁步实现——**同一份房间编排**(`packages/core/src/room/room.ts`,零 WS/零 node 依赖,双运行时同构)只差传输介质:

- **拓扑**:浏览器进程内起 `RoomRegistry`(内存持久化,无跨进程恢复语义),`LocalController`(`apps/client/src/app/controllers/local.ts`)经 **MemorySocket**(`apps/client/src/app/net/transport.ts` 内存双工)与其互连。命令上行经 wire 协议编解码单源(`packages/core/src/protocol/wire.ts` #429,与联机 WS 同一份 parse/dispatch 本体,见 §5);下行同走「事件批先行、校准摘要随后」的单拍 flush(编排传输面 `transportBroadcast`)。
- **同一通路**。玩家提交与普通命令分别通过 `submitFromSeat` 和 `applyCommandFromSeat`，托管由 `setAutoPilot` 处理。bot 链、看门狗、事件产出和演出消费均与联机共用。
- **状态 = 协议水合副本**([ADR-0066](../adr/0066-local-protocol-hydration.md)):控制器持独立副本,构造时先开局、再入座,首连整房摘要同步水合;此后事件批先折叠再由控制器一次发布座位视图,校准摘要无条件覆盖。决策归属与交互读取副本,行军位置锚在折叠/水合前捕获。权威引擎只留在房间编排侧。
- **校准与房间字段**:自动下行复用服务器的 `CALIBRATION_WINDOWS`、`CALIBRATION_EVENT_KINDS` 与 `CALIBRATION_BACKED_KINDS` 口径,普通事件拍不随发全量快照;房间元数据指纹变化时发送 `lobby` 消息。托管从下行座位表回读,单机不写 `netStore` 的联机房间字段。Worker 挂死的异常终局立即完整下行;换局销毁仍解散房间并清理看门狗、时钟与传输残表,不提供跨进程重连。
- **Worker 时钟**(#399):回合节拍唯一定义在 `packages/core/src/engine/timings.ts`(AUTO_ROLL_DELAY_MS / AUTOPILOT_STEP_MS,单机联机同表;e2e 时间倍率只缩放演出编排,不进权威节奏)。编排定时经 `RoomClock` 注入——服务器 = 宿主全局定时器;单机 = `apps/client/src/app/net/worker-clock.ts` 的 Web Worker 时钟,减少 WebView 主线程的定时影响;回前台演出队列按落后校准追平——浅积压追帧加速、持续落后吸附作废,不重放(事件通路既有语义 + [ADR-0029](../adr/0029-presentation-self-consistency-invariants.md) 不变量③);交互解锁只等本座位演出落定,不锁等全队列排空(#611)。
- **单机配套**。对局日志经座位摘要和公开尾段存入 IndexedDB，沿用 ADR-0014。托管与联机共用房间接口。
