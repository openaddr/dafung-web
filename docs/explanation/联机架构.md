# 联机对局设计与部署

> 状态:**已联机可玩**——第 1 步(权威服务器骨架)与第 2 步(多房间 WS + 浏览器联机客户端)均已完成,仅剩第 3 步(CLI 改 fetch server)。本文是设计与部署依据。

## 1. 目标

从本地热座(单设备轮流)演进为**每人一设备、经中心云服务器同步**。引擎权威不变,客户端变瘦(只发 GameCommand、收事件批与快照渲染,同步模型见 §5)。

## 5. 同步模型(事件流口径,折叠切换⑥ #388 落地)

同步模型按 [ADR-0020](../adr/0020-event-stream-sync-model.md) 切换,链路:**命令直达权威服 → 引擎产出事件批 → 服务端广播(唯一状态通路)→ 客户端折叠 + 校准锚**。

- **事件批是唯一对局状态通路**:每次编排转移(人类命令/bot 步/开局驱动)引擎产出类型化事件批(词汇表 `src/core/game-events.ts`);服务端按 flush 节奏合并(本 tick `setTimeout(0)` 统一排空,快速托管局数百步 bot 连锁合并为一批),以单条 `{type:"events"}` 消息明传全体在线座位(god-view,不做逐座裁剪)。同一 flush 内**先发事件批、后发快照**(因果在前、状态在后),WS 有序保证客户端折叠时读到转移后状态。
- **正常对局零逐步快照**,全量下行只剩三类:
  1. **整房摘要**——WS 建连(首连/重连)时 god-view 全量一份(`clientView` seat 缺省);
  2. **关键节点校准**——flush 时按引擎公开结算态判定(零启发式):Setup 三段式全程 + finishSetup 批、破产清算批(`playerBankrupt`)、决策窗五相位(军师幕/招贤/机遇/耗竭/破产清算)的进入/停留/退出。折叠器不可推导的上下文(`offeredHeroes`/`pendingJinnang` 等私有载荷与「窗口进出无专属事件」)由此兜住;校准快照水合**无条件覆盖**折叠后的全部字段,与折叠构成冗余双保险;
  3. **房间元数据**——lobby 形状(座位在线/房主/托管/接管),指纹变化才发;对局中掉线/托管开关不再搭快照车。
- **客户端**:事件批折叠进本地只读引擎副本(`src/app/net/event-fold.ts` 纯函数投影,折叠投影全覆盖见 #387),动效照读因果(`src/app/fx/event-extract.ts`);一次事件批一次重渲,命令在途锁由事件批帧(或空批转移时的决策窗校准快照)解锁。
- **重连 = 整房摘要 + 清批**:断线期间事件不补发(无 seq/ack);重连成功先把事件面整体归零(netStore 暂存批/到达计数/表现消费游标成对清),状态唯一来源 = 紧随其后的整房摘要。服务器重启后旧批不重发(恢复房间时登记事件批基线,见 server.ts `seenBatches`)。
- **断线即丢**:无排队、无补发、无可靠性机制,可靠性全靠重连全量;漂移纯信任(不做哈希对账、不做版本仲裁),失步靠玩家刷新。
- **保密后置**:god-view 明传,他人手牌内容、牌库顺序、反应窗询问集三类信息全网可见(朋友圈信任模型,知情接受);后补时在发送总口做单点过滤,ADR-0016 per-seat 投影冻结保留为落点(#381)。

## 6. 运行模型(目标态)

- 一个 Node 进程:`Map<roomId, GameEngine>` 内存挂多局;每次命令 `saveEngineAt(data/rooms/<roomId>.json, ...)` 落盘;同一进程静态托管 `dist/`。
- 环境变量:`PORT`(默认 3000)、`HOST`(默认 0.0.0.0,走反代设 127.0.0.1)、`ROOMS_DIR`(rooms 目录);全表见[部署服务器](../how-to/部署服务器.md)。
- ⚠️ `.env` 里的 `server_ip` / `server_pwd` 是 **SSH 运维凭据,应用不读**——应用 env 是另一份,别混(见 §6)。
