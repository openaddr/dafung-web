# 联机对局设计与部署

> 状态:**已联机可玩**——第 1 步(权威服务器骨架)与第 2 步(多房间 WS + 浏览器联机客户端)均已完成,仅剩第 3 步(CLI 改 fetch server)。本文是设计与部署依据。

## 1. 目标

从本地热座(单设备轮流)演进为**每人一设备、经中心云服务器同步**。引擎权威不变,客户端变瘦(只发 GameCommand、收事件批与快照渲染,同步模型见 §5)。

## 5. 同步模型(事件流口径,折叠切换⑥ #388 落地)

同步模型按 [ADR-0020](../adr/0020-event-stream-sync-model.md) 切换,链路:**命令直达权威服 → 引擎产出事件批 → 服务端广播(唯一状态通路)→ 客户端折叠 + 校准锚**。

- **事件批是唯一对局状态通路**:每次编排转移(人类命令/bot 步/开局驱动)引擎产出类型化事件批(词汇表 `src/core/game-events.ts`);服务端按 flush 节奏合并(本 tick `setTimeout(0)` 统一排空,快速托管局数百步 bot 连锁合并为一批),以 `{type:"events"}` 消息逐座位下发。逐座位下行装配(#431)只经一个口:`scripts/seat-projection.ts` 的 `assembleDownlinkShot`——事件批与整房摘要一次配齐,**redaction 是装配必经步而非调用纪律**:签名带 `viewerSeat`,传座位即裁剪流(联机必裁;将来观战/回放类消费面复用本口,传座位默认拿裁剪流),传 `null` 即显式 god-view 退化(单机内存直连唯一合法取值)。同一 flush 内**先发事件批、后发快照**(因果在前、状态在后),WS 有序保证客户端折叠时读到转移后状态。
- **正常对局零逐步快照**,全量下行只剩三类(#381 起按接收座位投影):
  1. **整房摘要**——WS 建连(首连/重连)时该座位的 per-seat 投影一份(`clientView` 带座位);
  2. **关键节点校准**——flush 时按引擎公开结算态判定(零启发式):Setup 三段式全程 + finishSetup 批、破产清算批(`playerBankrupt`)、决策窗五相位(军师幕/招贤/机遇/耗竭/破产清算)的进入/停留/退出。折叠器不可推导的上下文(`offeredHeroes`/`pendingJinnang` 等私有载荷与「窗口进出无专属事件」)由此兜住;校准快照水合**无条件覆盖**折叠后的全部字段,与折叠构成冗余双保险。触发登记(#431 类型化归口 `scripts/seat-projection.ts`):`CALIBRATION_WINDOWS: ReadonlySet<TurnPhase>` / `CALIBRATION_EVENT_KINDS: ReadonlySet<EventKind>`——phase/kind 改名 = 编译红;与折叠端不折清单的覆盖对账单源 `CALIBRATION_COVERAGE`(档位表 `core/event-tiers.ts` 的 calibration-only kind 逐个点名覆盖触发,漏点名 = 编译红);
  3. **房间元数据**——lobby 形状(座位在线/房主/托管/接管),指纹变化才发;对局中掉线/托管开关不再搭快照车(元数据全桌公开,无 per-seat 面)。
- **客户端**:事件批折叠进本地只读引擎副本(`src/app/net/event-fold.ts` 纯函数投影,折叠投影全覆盖见 #387),动效照读因果(`src/app/fx/event-extract.ts`);一次事件批一次重渲,命令在途锁由事件批帧(或空批转移时的决策窗校准快照)解锁。过滤批对折叠器零感知——事件到了就是「我能看的」(`consumeCard` 对暗牌数组恒空的口径、闭窗算术对询问集数量的依赖,均已按投影形态对齐)。
- **重连 = 整房摘要 + 清批**:断线期间事件不补发(无 seq/ack);重连成功先把事件面整体归零(netStore 暂存批/到达计数/表现消费游标成对清),状态唯一来源 = 紧随其后的整房摘要。服务器重启后旧批不重发(恢复房间时登记事件批基线,见 server.ts `seenBatches`)。
- **断线即丢**:无排队、无补发、无可靠性机制,可靠性全靠重连全量;漂移纯信任(不做哈希对账、不做版本仲裁),失步靠玩家刷新。
- **保密口径(#381,ADR-0020 决策 2 后补兑现)**:三类秘密不出网——①他人锦囊手牌内容(快照 players[].jinnangHand 恒空,数量走引擎态 `jinnangHandCount`);②锦囊牌库序(快照 `jinnangDeck` 恒空,剩余数走 `jinnangDeckCount`);③反应窗询问集(快照 `reaction/pendingReaction` 按座位只投影「我是否被询问」;事件批 `reactionOpened` 的 jinnang 窗 `queriedSeats` 身份匿名——非自己座位一律置换 -1 占位、**数量保留**,march 窗全公开原样)。其余 37 种事件全桌公开原样透传(逐 kind 审计表见 `scripts/seat-projection.ts` `redactEvents` 头注;`jinnangDrawn` 本就是 count-only 设计;`treasureStolen` 的牌名是明置信息——珍宝列表全员可见、战报公开记名)。未知事件 kind 过滤时当场炸:新增事件必须先在 `redactEvents` 登记隐私档位(与 ADR-0016「新增载荷登记」同纪律)。单机通路(`room.ts` `connectSeat`/`flushTransport`,本机单真人)无跨设备泄密面,保持 god-view 不在保密范围内——#431 起该退化收口为装配签名上的显式 `viewerSeat: null`,「忘了裁」不再是可能形态,双模式行为由 `test/downlink-assembly.test.ts` 锁定。
- **wire 协议编解码单源(#429)**:上行消息 union(`cmd`/`pickCapital`/`autoPilot` 三族)、解析分发(`dispatchInbound`——**错误回报是返回值的一部分**,分 `badJson`/`unknownShape`/`rejected` 三类,任何失败都不抛出传输层之外)与下行构造(`eventsMsg`/`errorMsg`/`dismissedMsg` + `encodeDownlink` 封装单口)全部收口 `scripts/wire.ts`;两个传输面(adapter)只负责把失败送到各自通道——**WS = error 消息下行**(联机,含 #428 的非法命令回报),**内存 = pushHint**(单机;结构性失败在内存面结构上不可能,真出现 = 自身 bug 照炸,零兜底)。lobby/snapshot 两类下行的载荷产出仍单源 `scripts/seat-projection.ts`(redaction 归属见「保密口径」),编解码只管类型与封装;客户端(`online.ts`/`local.ts`)与服务器从此 import 同一份类型与 dispatch 本体,「逐字同契约」双写与注释互指退役,新增消息类型漏任一侧 = 编译红(穷尽 switch 收 never)。形状与错误分类由 `test/wire.test.ts` 锁定。

## 6. 掉线座位保留窗口与重连令牌(#380,ADR-0002/0005)

掉线语义从「纯冻结 + 房主手动出口」补齐为「保留窗口 + 到期自动回收」:

- **保留窗口**:对局中 WS 断开的座位保留 `RETENTION_WINDOW_MS`(env 可调,默认 600000=10 分钟,0=关)。窗口内持 seatToken 重连**无缝夺回**(attachSeat 即撤窗);到期无人归来 → **bot 自动接管**,语义等价房主 takeover(ADR-0002 出口):写 takeover 集合、广播 `takeover(auto)` 观测行、对局日志记接管行,随后 driveBots 解冻续推。
- **窗口期内维持冻结停摆**:保留窗只决定「何时转 bot」,不改窗口内语义——该座位回合到来照样冻结等待(ADR-0002 默认冻结),他人照常行棋;若另配 #118 决策停摆看门狗(默认 120s),它按自身窗口独立兜底,与保留窗互不代替。
- **令牌口径(ADR-0005)**:seatToken 是座位归属唯一凭证,**有效期 = 房间生命周期**(解散/记录移除即失效);保留窗口是「bot 何时接管」的运维参数,**不使 token 失效**——窗口到期自动接管后,原玩家持 token 重连仍可夺回(与房主手动接管后重连夺回同口径)。
- **覆盖范围**:窗口由「对局中断线」事件武装;开局前断线(大厅占座不自动释放)与服务器重启前已断线的座位不在窗口内——仍可凭 token 重连夺回,或由房主手动接管 / #118 看门狗兜底。
- **崩溃恢复实测收口**:恢复通路(落盘 → 新 registry `restoreAll` → 继续推进)落编排级单测(`test/room-recovery.test.ts`),覆盖三形态——进行中对局(双路续跑,终态一致)/ 已终局(快照原样保留)/ 损坏文件跳过(坏 JSON 走 persistence 层「跳过+console.warn」通道且文件保留;结构损坏走 room 层 hydrate 抛错→跳过并移除);并钉住 #388 恢复播种(`seenBatches`/`settledTurnPhase`)与恢复路径的咬合——恢复批按引用去重,重启后旧批不重发,新转移只追加新批。

## 7. 运行模型(目标态)

- 一个 Node 进程:`Map<roomId, GameEngine>` 内存挂多局;每次命令 `saveEngineAt(data/rooms/<roomId>.json, ...)` 落盘;同一进程静态托管 `dist/`。

- ⚠️ `.env` 里的 `server_ip` / `server_pwd` 是 **SSH 运维凭据,应用不读**——应用 env 是另一份,别混(见 §7)。

## 9. 单机形态:「服务器住在本进程」(单机统一 #379,#397..#400)

单机不再是与联机平行的锁步实现——**同一份房间编排**(`scripts/room.ts`,零 WS/零 node 依赖,双运行时同构)只差传输介质:

- **拓扑**:浏览器进程内起 `RoomRegistry`(内存持久化,无跨进程恢复语义),`LocalController`(`src/app/controllers/local.ts`)经 **MemorySocket**(`src/app/net/transport.ts` 内存双工)与其互连。命令上行经 wire 协议编解码单源(`scripts/wire.ts` #429,与联机 WS 同一份 parse/dispatch 本体,见 §5);下行同走「事件批先行、整房摘要随后」的单拍 flush(编排传输面 `transportBroadcast`)。
- **同一通路**:命令路由(applyCommand/pickCapital/setAutoPilot)、bot 链(driveBots)、看门狗(#118 停摆/#188 自动起摇/#281 反应窗)、事件产出与演出消费(SnapshotEffects → extractBatchEvents,ADR-0020 事件直译)全部与联机同一份代码;单机与联机从此只差「传输在不在网上」。
- **状态 = 内存直连**:权威引擎就住同进程,store 直读引擎(不 hydrate 副本)。ADR-0020 的快照水合/校准/重连语义在单机的对应物 = **内存直连天然同步,无网络级重连**;换局销毁即解散(dismissRoom 清看门狗与传输残表),下一局全新房间。
- **节拍单源 + Worker 时钟**(#399):回合节拍唯一定义在 `src/core/timings.ts`(AUTO_ROLL_DELAY_MS / AUTOPILOT_SLOW_MS,单机联机同表;e2e 时间倍率只缩放演出编排,不进权威节奏)。编排定时经 `RoomClock` 注入——服务器 = 宿主全局定时器;单机 = `src/app/net/worker-clock.ts` 的 Web Worker 时钟,**后台标签页节流免疫,失焦照跑**;回前台演出队列追平(不重放,事件通路既有语义)。
- **单机既有配套不变**:对局日志仍走 ADR-0014 浏览器侧 IndexedDB 归档(挂编排 persist 通道);`window.__dafung` 调试桥读写的仍是权威引擎(内存直连,e2e force 通路不变);托管(autoPilot)与联机同协议消息。
