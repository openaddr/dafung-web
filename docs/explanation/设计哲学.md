# 设计哲学

这篇讲「为什么这么做」;规约讲「是什么」——行为红线在 [AGENTS.md](../../AGENTS.md),规则与数值在 [规则手册](../reference/rules/README.md)(以 `src/core/` 代码为权威)。写法上学 Unciv 的《Intentional departures from Civ V》:凡与常规做法分道扬镳之处,把偏离摆上台面、给出理由,让后来者不必考古。

## 1. 零兜底:让问题在出生地死掉

常规工程实践是防御性编程:catch 吞错、默认值回退、极端场景静默降级。本作把这一整套全部禁了(见 [AGENTS.md 零兜底原则](../../AGENTS.md)),在 2026 年的 Web 项目里这几乎是个反潮流的决定,理由如下。

静默兜底的真正代价不是那几行代码,而是它把「bug 在哪里」这个问题变贵了。错误在 A 处被吞掉,症状在 C 处才浮现,中间隔着几层误传;排查者要做的第一件事不是修 bug,而是破译兜底代码对事实的篡改。更糟的是复利效应:每个兜底都在向系统注入「允许不正确」的先例,下一层代码就会站在这个不正确上继续生长——屎山不是写出来的,是兜出来的。

反过来,零兜底让崩溃发生在 bug 的出生地:地图清单空了就抛错(`getDefaultMapId()` 绝不回退到某个写死的地图),珍宝等级查表缺项就抛错,「理论上到不了」的分支真到了就崩。崩溃即发现,发现即修复,修复即消失。个人项目没有兼容包袱、没有不可控的用户群,恰是执行这条红线的最好土壤——我们不为「万一」买单,只为「现在」负责。

两条例外常被误读成兜底,其实不是。显式向用户报错的 catch(UI setError/pushHint 展示失败原因)什么都没吞:失败原因原样走到了玩家眼前,只是换了个出口;纯 UI 的空态(「暂无可用地图」)是正常业务态,不是对错误的伪装。判据只有一条:**错误是否仍然可见**。看得见的失败是信息,看不见的失败才是兜底。

## 2. 无租金经济:压力来自现金流,不来自过路费

大富翁的原型里,租金是核心引擎:落进别人的地,付钱,对方滚雪球。本作把过路费和升级费整个砍掉了([规则手册·地产经济](../reference/rules/04-地产经济.md))。因为我们看清了一件事:租金是一次**无决策的转移**——访客因骰子被罚,城主因骰子得利,转账双方在过程中都没有做任何决定,游戏却因此分出了贫富,还顺手拖长了劣势方的煎熬时间。

于是压力换了来源。**身价 = 仅现金**([networth.ts](../../src/core/networth.ts)):珍宝和城池的账面一概不计,买地直接降身价——每次购地都是掏空自己去下注;现金不够付款就触发破产清算,逼你变卖资产求生。现金流管理从「被收租的被动挨打」变成「何时下注的主动抉择」,这才是我们想要的张力。

升级激励同样改了方向:升级不花一分钱,但**只有公道买卖成交,城池才 +1 级**([economy.ts 头注释](../../src/core/economy.ts))。城主有宝、访客落城,便构成一次双方都有事可决定的交涉:城主在公道买卖、坐地起价、不交易之间权衡,升级是成交的奖励而非白送。落他人城由「纳税事件」变成了「交易机会」。

同样的红线思维也用在了全游戏唯一一处隐藏信息上:锦囊。常规卡牌设计默认「牌越多越爽」,我们只保留一种暗牌,并立下同样的规矩——拿到即用、无需思考的牌不配当锦囊,每张牌必须在「用不用 / 对谁用 / 这回合用哪张」至少一问上有真实权衡([锦囊设计 §1](./锦囊设计.md#1-定位与设计红线))。偏离常规从来不是目的,**每个偏离处都必须让玩家多出一个决策点**,才是。

## 3. 为何是 React + SVG,而不是游戏引擎

做游戏却不用游戏引擎,看起来像自缚手脚。但回合制格子游戏与引擎的强项根本不重合:引擎擅长每秒六十帧的连续模拟,而本作一整局只是「静态棋面 → 动画演出 → 静态棋面」的循环——它本质是**带动画的状态机 UI**([README 技术栈](../../README.md#技术栈))。为状态机引入游戏循环、场景图与独立资源管线,是用一套更贴身的抽象去换一套更重的。

决定性的理由在测试。声明式渲染让 UI 成为引擎快照的纯函数,AI(或人)可以用 `data-testid`、`data-tile` 与 `window.__dafung.snapshot()` 对「这个按钮此刻可不可点、这格现在是谁的城」做**精确断言**;换成 Canvas,剩下的只有像素,测试只能靠截图猜测。本项目的立项目标就是「可被 AI 全自动测试与迭代」:改代码 → build → Playwright 驱动对局 → 读快照断言 → 再改。这个闭环实打实抓出过「人类回合行军按钮卡 disabled」这类靠截图几乎无法定位的状态 bug——工具为可测性让路,是这个仓库技术选型的第一原则。

边界也是刻意的:引擎([`src/core/`](../../src/core))零 DOM 依赖,React 只是快照的一个投影。这不是洁癖——引擎要上服务器跑联机([联机架构](./联机架构.md)),今天沾上的每一个 DOM,都是明天联机化的路障。

## 4. 文档观:代码是唯一事实,文档是人话镜像

多数项目的文档死法相同:文档与代码各说各话,半年后没人敢信文档。根因不在人不勤快,而在结构——**同一事实写了两份,漂移只是时间问题**。所以本仓库把它定成制度:代码是唯一事实源,文档只做人话镜像,职责是解释与指路,从不复制事实本身([AGENTS.md 文档风格规约](../../AGENTS.md))。

最典型的落点是数值表:[规则手册·关键数值总表](../reference/rules/10-关键数值总表.md) 的每个数值标注代码出处,规约要求带符号名锚点、禁写行号——行号必漂移,符号名不会。表是索引,不是第二事实源;要改数值就改代码,锚点跟着符号走,不存在第二处要同步的地方。

受众排序同样明确:**玩家优先,贡献者次之,agent 没有专属章节**。agent 直接读代码——代码是事实,玩家文档是理解事实的入口,理解力缺口用代码注释补,而不是为 agent 另写一套平行文档。维护上,镜像靠完成定义焊住:改动玩家可见机制,同一 PR 内必须回填对应规则页([AGENTS.md](../../AGENTS.md)),文档更新不是欠账而是改动本身的一部分。发版同理:历史的事实由 git tag 与 GitHub Releases 承载,不另建 CHANGELOG 再抄一遍。

> 一句话总结:代码负责正确,兜底负责掩盖,我们只要前者;租金负责惩罚,交涉负责创造决策,我们只要后者;引擎负责像素,快照负责事实,我们只要后者;第二份文档负责漂移,锚点负责指路,我们只要后者。
