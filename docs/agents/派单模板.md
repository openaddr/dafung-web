# 派单模板与主线 QC 检查单

> 来源:锦囊一期耗时回顾(2026-09-25,PR #241)。原则条文在 [AGENTS.md「子代理派单纪律」](../../AGENTS.md),本文件是可直接复制的模板——派单前复制填写,收口时按检查单走。纪律的目标数据:实现轮 229.9min 里 79% 是子代理墙钟、19% 是主线等 e2e;限额与分层就是冲这两块去的。

## 一、派单模板(复制填写)

```markdown
你在 <仓库>(分支 <分支>)实现「<工单号与标题>」。

## 必读(按序,≤6 项)
1. <规格文件+章节>
2. <视觉基线/原型,标注「已验收,原样移植不许自由发挥」>
3. <数据单源文件>
4. <红线文件:AGENTS.md 架构红线/零兜底、BRIEF §0>

## 交付物(只许新增/修改以下文件)
1. <文件+签名级接口说明>
2. ...

## 要做什么(逐条,交互口径写死不留开放题)
1. ...

## 文件所有权(并行纪律)
**只许写**:<清单>
**禁碰**:<清单,含共享文件归属说明>
**并行构建纪律**:`flock tmp/build.lock bun run build`;e2e 专属端口与 rooms 目录;疑似对方在途改动→记录现象继续,不修对方文件。

## 验证限额(超出即停,写进汇报)
- `bun run typecheck` / `bun test` 各一次收口
- e2e 只跑本工单 spec:`E2E_STATIC_PORT=<专属> E2E_GAME_PORT=<专属> E2E_ROOMS_DIR=./tmp/e2e-rooms-<代号> E2E_WORKERS=1 npx playwright test <本工单 spec>`
- 截图证据 ≤4 张关键态,统一走 `scripts/shot.mjs`(勿手写起服脚手架)
- 疑似非本票失败:对照实验(repeat-each / stash)一次定性即停、上报,不多轮取证

## 汇报格式
文件清单 / 验证逐项 / 截图路径 / 与拍板口径的偏差及理由 / 未决问题
```

## 一·五、动手前自答(写码前每问一句答案;答不出=派单没写清,回报主线)

## 二、主线 QC 检查单(每道缝)

- [ ] 门槛四项:typecheck / bun test / 本工单 e2e / build(`flock` 锁内)
- [ ] 截图亲审(验收标准=商业观感 + 原型一致;文字重叠/截断/对比度肉眼过一遍)
- [ ] 代码抽查红线:零兜底(catch{} / 写死默认)/ testid 契约 / 动效 token / 新文案禁 font-deco / core 零改动
- [ ] 按票性质跑双轴评审(Standards 对红线 + smell 基线;Spec 对票面);必修项主线自修
- [ ] 集成点:全量 e2e **每分支一次**,PR 前收口(分层口径见 AGENTS.md「本地 e2e 跑法」)

## 三、已验证的反模式(勿再犯)

- 派单留开放题(「自行决定 X」)→ 代理自证循环多轮;交互口径逐条写死,实现层微调项单列
- 让实现代理顺手修既有 flake → T3 花 10min 做 stash 对照,结论还只能上报;诊断权归主线
- 临时起停 vite 跑多轮截图 → 一次会话拍全关键态;脚手架复用 scripts/shot.mjs
- 全量 e2e 当常规验证 → 每跑一次 ~6min;本屏 40s,全量留 PR 前
