# 子代理派单与主线收口

派单前按本页填写；项目红线见 AGENTS.md，命令与验证范围单源为[开发与测试](../how-to/开发与测试.md)，测试取舍见 [ADR-0065](../adr/0065-test-economics-browser-retirement.md)。

## 派单纪律

1. **文件所有权互斥**：逐文件列出只许写与禁碰范围；共享文件指定唯一属主。任何写盘先建 jj workspace，主树只读。
2. **验证成本写明**：迭代只跑本票单文件/单族；最终 typecheck/build/完整 Bun 默认池各一次，不为每次修补重跑整池。慢例仅对应能力改动时定向执行。
3. **按反馈收敛**：先说明守住的行为与预期成本；已有覆盖直接沿用，普通展示不补测试，删除不要求等价迁移。不可靠例按 AGENTS 默认删除。
4. **诊断和质检归主线**：代理报告失败现场，不自行扩域修其他票；主线抽查代码、处理接缝与诊断，收口做 Standards/Spec 双轴评审。
5. **一票一代理**：AC>10 或预估超过 60 分钟拆棒；每棒收口就汇报。失联时从原 workspace 的 jj 快照盘点续作，保留已完成内容。

## 浏览器边界

常驻浏览器回归已退役，不派浏览器用例、不建 fixture、不安排快慢池，也不要求截图自证。只有用户明确提出页面观察、截图对比或浏览器复现时，才派本次具体辅助；不得把它固化为测试或门槛。视觉与设备交互由用户在 APK 中验收。

## 派单前检查

- [ ] 读当前票与阻塞关系，刷新 freshness，确认基于集成尖端。
- [ ] 文件范围不与其他代理重叠，落盘路径为本票 workspace 绝对路径。
- [ ] 验收条件有无浏览器单测/集成证据或人工验收归属；不为纯视觉制造自动化要求。
- [ ] 写明定向检查和何时结束；禁止扩大到全慢池。
- [ ] 显式写明禁止 push、禁止 pr-merge，除非主线已授权。

## 派单模板

```text
任务：<票号、标题、父规格与相关代码/决策指针>
基线：<集成书签和不可变 commit>
工作区：<绝对路径；jj workspace，开工先 freshness>
只许写：<逐文件>
禁碰：<其他票/共享文件>
验收：<每条行为与验证方式>
迭代验证：<单文件/单族命令，预计成本>
收口：<本票需要的检查；全默认池与 build 留主线最终一次>
禁止：<push/pr-merge/扩域修复/常驻浏览器测试>
汇报：<jj 快照、文件清单、实际验证与退出码、未决问题>
```

规格票调用 implement-spec；本项目适配为 jj workspace 串行实施，merger、接缝修复和诊断由主线承担。每票从最新集成尖端开始，交付先 describe，再由主线检查文件集后并入；不能靠上一波惯性跳过技能流程。

## 主线 QC

- [ ] 核对文件集；已描述的 change 上继续编辑先 jj new 分层。
- [ ] 检查零兜底、公共引擎命令、序列化、core 零 DOM、testid 单源及适用的 DoD。
- [ ] 真实 bug 回归先在未修代码上跑红；基建/环境问题可用实际失败与修后真火记录。
- [ ] 删除纯展示/重复断言及失效助手，检查新增测试没有镜像实现。
- [ ] 最终代码执行本地静态检查、构建、完整 Bun 默认池一次；追加门槛按 AGENTS，慢例按受影响能力。
- [ ] Standards/Spec 评审问题闭环，PR 说明实际检查及人工待验项，不把历史失败改写成通过。
- [ ] push 前再次 freshness 和 diff 文件集对账；交付 describe、书签、push 和 PR。
- [ ] 收尾仅清理自己建立的 workspace 与进程；先验名、保存证据、jj workspace forget，再按安全路径清理目录。他人滞留 workspace 只报告不处理。

jj 建仓、合入与收账命令统一查[开发与测试](../how-to/开发与测试.md)「版本协作」；不在派单中复制第二套配方。
