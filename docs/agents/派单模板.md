# 派单纪律与模板:主线 QC 检查单

> 来源:锦囊一期耗时回顾(2026-09-25,PR #241)。**派单前复制模板填写,收口按检查单走**——拆票→派单→收口全生命周期用这一份。纪律的目标数据:实现轮 229.9min 里 79% 是子代理墙钟、19% 是主线等 e2e;限额与分层就是冲这两块去的。

## 五条纪律(原则层,下文各节是操作层)

1. **文件所有权互斥清单先行**:派单时逐文件写明「只许写/禁碰」;共享文件(testids、helpers、共享 css)预指派唯一属主或由主线预改;并行一律分隔离工作区 + 专属端口与目录(Git Bash 无 flock,隔离即构建锁,2026-10-13 实测)——隔离工作区通道:`jj workspace add ../dafung-web-ws-<用途或代号>` 建仓 ~2s(#537 试点通过,正式口径),运行条件实测见[开发与测试](../how-to/开发与测试.md)「版本协作」节;git worktree = 逃生舱通道。
2. **验证限额写进派单**:`typecheck`/`build` 各一次收口;e2e 只跑本工单 spec(`bun run test:e2e:one e2e/<相关>.spec.ts`,分层口径见[开发与测试](../how-to/开发与测试.md));截图证据 ≤4 张关键态(一律 844×390 移动横屏标准档;动画中间帧/对比度实测随该一轮做完,不反复起停 vite)。
3. **诊断权归主线**:代理遇「疑似非本票引入的失败」,做一次对照实验(stash/repeat-each)定性后即停、上报,不做多轮取证——主线有跨票上下文,一次定性全局复用。机械上限:同一 spec 全程至多 2 遍(定位 1 + 修复验证 1,**含设计迭代轮**——设计前提被推翻(如「目标态不可观测」)即停手回报换口径,不是原地重设计),第 3 遍起停手上报。
4. **主线质检职责不变**:每道缝验门槛+亲审截图+抽查代码;评审(Standards/Spec 双轴)在收口前跑,发现必修项由主线修,不回派。
5. **派单形状:一票一代理,超时拆棒**:默认一张票一个子代理,批多票须写明理由;**拆棒硬线(2026-10-29 #751 retro 实锤:16 条 AC 一票跑成 111 分钟关键路径,整波墙钟被它钉死):单票 AC>10 条或预估 >60min 必拆;共享域文件是 b 档试验票/分棒接力的信号,不是并票理由**;预估超 1 小时的票拆棒接力——每棒收口(交付物过一轮验证)即回报,主线续派下一棒,不搞一棒跑到黑;长派单走后台(run_in_background),主线边等边做别的。取消/断网只损当前一棒。**代理阵亡接力(#712-#725 波两度实锤,零损失)**:API 断连致代理死亡时,现场完好在 workspace @(jj 自动快照)——原代理句柄不可续(SendMessage 报无活动任务)即新派接力代理,派单词写明「先盘点 @ 的 `jj diff` 对照票面(已完成/半成品/未动)再续作,不推翻重做;禁碰文件被前棒碰过不回滚只上报」;前置 freshness 重跑(中断期 master 可能被推前)。**内容安全网连误即停**:同一工单被执行环境内容安全网连续误伤≥2 次,即停派改由主线按接力纪律亲做(前棒现场在 @,盘点续作)——2026-10-29 #765 三连误伤实锤。

## 〇、拆票检查单(派单之前,票怎么切决定省多少)

一期实测:接缝与粒度问题吃掉 ~40min。切票时逐条过:

- [ ] **并行票体量对称**:两票并行时墙钟由慢者决定——T2(28min)∥T3(63min)的并行收益全被 T3 吃掉。估各票工时,悬殊就拆慢票或并快票,让两条链长度接近。
- [ ] **实现与验证分离**:「动效代码+音效接线+视觉走查+跨 spec 回归」混一张票(T4 型)= 验证密度爆炸(74min 单点)。打磨/审计类工作从实现票剥出,单独成票或交主线。
- [ ] **AC 逐条标注验证通路**:e2e/单测/机制论证三选一,写不出通路的 AC 改口径或删——防收口证据缺口类 finding(2026-10-20 #650 实锤:触屏手势 AC 靠机制论证放行、珍宝城入列 AC 被 e2e 漏盖)。
- [ ] **小而独立的活儿先行**:布局迁移、共享文件预改这类 10 分钟级改动,主线开工前顺手做掉,不给任何代理票添「顺带任务」。
- [ ] **文件所有权互斥**(硬条件,不满足就不能并行):逐文件写「只许写/禁碰」;共享文件(testids/helpers/共享 css)预指派唯一属主或主线预改。
- [ ] **文件全覆盖核对**:各票「只许写」清单的并集要对表本波应改文件全集——每文件恰一属主,无主文件要么入票要么显式留主线(react-online 4 处硬等待因切票漏主拖成尾票)。**spec/tests 改写同在覆盖面**:产品改动波及的既有测试文件(spec/单测)要列入某票的改写归属,漏主 = 全量 e2e 假挂(#697-#725 七波 retro 实锤:产品文件列全而 react-jinnang-rack/react-layout 改写无归属,全量四例 spec 漂移挂,收口多三轮 A/B 定性)。
- [ ] **删除类工单清单先 sweep(#626)**:删除符号/退役文案的工单,清单交用户确认**前**先做全仓无过滤 sweep(含 docs/tutorials、how-to 与代码注释),清单按 sweep 结果写全——留到施工时补漏 = 用户批的是残缺清单,补上的文件成范围外变更(#614 实锤:清单漏教程与联机对战两文件)。
- [ ] **依赖图最小化**:能并行才并行;串行链上每道缝 ≈3-7min 主线 QC 成本,票数本身也是成本——两票能干净合并就别拆三票。
- [ ] **b 档触发器(#538 裁决)**:出现「两票必须共享同一文件的拆票需求」或「互斥分区导致串行等待链」时,开一张 b 档试验票(允许文件重叠 + `jj rebase -d`,冲突定点裁决),通过后写入本模板;未触发前维持互斥分区。
- [ ] **底盘预期**:接缝 QC + 集成全量 + 主线模型时间 ≈35min 不可压(单人单线程 QC 的物理下限),拆票方案按「底盘 + 关键路径」估总账,别把底盘当优化对象。

```markdown
## 验证限额(超出即停,写进汇报)

- `check:freshness` 收口一次(基线指纹进汇报;并行会话可能已把 master 推前,收口基线≠开工基线,#645 收口代理漏跑实锤)
- `bun run typecheck` / `bun test` 各一次收口
- `bun run check:fmt` 收口一次(跑过全仓 fmt 的票必查——master 漂移会被 fmt 卷入成范围外变更,红=先 `jj restore --from @- <漂移文件>` 抢救文件集再上报)
- e2e 只跑本工单 spec,一律走脚本入口(自带 build,防陈旧 dist 错配世界):`E2E_STATIC_PORT=<专属> E2E_GAME_PORT=<专属> E2E_ROOMS_DIR=./tmp/e2e-rooms-<代号> E2E_WORKERS=1 bun run test:e2e:one e2e/<本工单 spec>`;裸 `npx playwright test` 仅限主线 flake 取证(`--repeat-each`),且改 src 后必须先 build
- 截图证据 ≤4 张关键态,统一走 `scripts/shot.mjs`(默认视口 844×390 移动横屏标准档,勿手写起服脚手架)
- 疑似非本票失败:对照实验(repeat-each / stash)一次定性即停、上报,不多轮取证

## 完成交付

- 全部改动就位于书签分支并 `jj describe -m "<type>(<scope>): 中文描述(#票号)"` = 交付(「jj 配方」速查第 1 条;**裸 @ 无描述无书签 = jj 版「工作区留 M」**,实现代理默认不交付,实测两票中招)。git worktree 逃生舱通道的等价交付 = 显式 `git commit`(message 同款)

## 汇报格式

基线指纹(HEAD SHA)/ 文件清单 / 验证逐项(含每条 spec 执行次数)/ 截图路径 / 与拍板口径的偏差及理由 / 未决问题
```

## 三、已验证的反模式(勿再犯)

- 派单留开放题(「自行决定 X」)→ 代理自证循环多轮;交互口径逐条写死,实现层微调项单列
- 让实现代理顺手修既有 flake → T3 花 10min 做 stash 对照,结论还只能上报;诊断权归主线
- 临时起停 vite 跑多轮截图 → 一次会话拍全关键态;脚手架复用 scripts/shot.mjs
- 全量 e2e 当常规验证 → 每跑一次 ~6min;本屏 40s,全量留 PR 前
- 实现代理默认不 commit → 干完活验证完工作区留 M,主线代提交兜底混责;派单明写提交要求(#452/#453 实测)
- 审计/取证在落后基线上跑 → file:line 与结论全部失真(#446 两「高置信 bug」被证伪);开工 check:freshness,基线指纹进汇报
- 票面引用封闭词表(对局日志 category/事件 kind/地图格型/标签族)先 grep 词表再落笔 → 凭记忆造类目,代理可能将错就错写进代码(2026-10-18 实锤:票面「归 jinnang 类」,日志 category 封闭联合无此类,代理自查落 system 才没造出脏数据)

## 四、jj 配方(colocated)

操作配方、命令速查与摩擦清单已归口 [开发与测试](../how-to/开发与测试.md)「版本协作」节(单一事实源)。

### git worktree 通道三律(逃生舱)

- **逃生舱即 git**:worktree 目录内用 git 命令(无 .jj,跑不了 jj),不强行 jj 化;**删除 worktree 前必查脏**(`git -C <路径> status --short` 非空即停,force 删除物理销毁未提交内容,wt529 事故);正式通道 = workspace + jj(见速查)。
- **大批次集成分支**:主线建 jj 书签推远端,代理 `git worktree add <路径> -b <分支> <集成分支>` 从本地书签切——网络断可全本地流转,最后统一推。
- **jj 命令只在主树跑**:git worktree 目录无 .jj,报「no jj repo」先想这个;合入后主树对账见上方 QC 检查单。

### 代理 jj 速查(正式口径)

0.45 五摩擦与命令全文在[开发与测试](../how-to/开发与测试.md)「版本协作」节,不重复;代理视角记四条:

1. **describe 即交付**:工作副本即提交,改完 `jj describe -m "<type>(<scope>): 中文描述(#票号)"` + 书签就位 = 交付——git「显式 commit」的 jj 等价物(单票整交也可 `jj commit`);不裸奔,裸 @ 无描述无书签 = jj 版「工作区留 M」。
2. **书签命名 `<票号或用途>-<slug>`**(如 `535-vocab`),push 新书签显式 `--bookmark`。
3. **恢复命令段**(慌乱时先读这):`jj op log`(操作日志,仓库级共享)/ `jj undo` / `jj restore` / `jj abandon`——**并行期裸 `jj undo` 的「上一笔」常是别人的操作,会波及他人;undo/restore 一律按 change id 定点(`jj restore --from <change>`,可带路径),不裸 undo**(#536 裁决)。定点恢复的常见陷阱:`--from @-` 恢复的是**父提交**版本——@ 里已 describe 的正确编辑会被连同冲掉(工作副本本身就是提交,不是 git 的「未提交改动」);要撤 @ 内最后一击,先 `jj new` 分层再 `jj restore --from <持好版本的 change>`(#537 试点实测)。
4. **主树 @ 是停靠位,永不留活**(2026-10-18 S2 收窄,取代 #536「@ 即提交」主树直改口径;AGENTS 第一章为准):**任何写盘改动不分体量,开工前一律先 `jj workspace add ../dafung-web-ws-<代号>`**,在 workspace 内干活与交付。进场 `jj log -r @` 发现主树 @ 有非自己生产的内容 = 有别的会话在用:**不动、不 abandon、不 `jj new` 盖上——让出主树走自己的 workspace**;用户手改主树是一等公民,不判「疑似」直接绕行。**交付边界=describe/push 前的 diff 自查**(`jj st`+diff):含非本工单 hunk 用 `jj split` 拆成独立 change(拆比争论便宜),拆不动(已在 PR 里)则正文逐条披露;**永不静默混入**。收账(`jj new master`)会连 @ 一起运走,动手前必看 @ 归属——人手只准在自己 workspace 跑;唯一例外 = `pr-merge.ts` 尾步自动前移主树**空 @**(有活不动,见开发与测试收账条)。

git 肌肉记忆对照(主线 QC 与日常同款,写进同一份速查不另开文档):`git status`→`jj st`、`git diff`→`jj diff`、`git log`→`jj log`、`git commit`→`jj describe`+书签(或 `jj commit`)。
