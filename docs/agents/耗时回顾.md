# 耗时回顾方法论(ZCode 记录挖掘)

> 目的:下次回顾/估算时零探索成本。数据全部来自本机 ZCode 落盘记录,不含估算。
> 首次实践:锦囊一期回顾(2026-09-25),结论驱动了 AGENTS.md 派单纪律与 e2e 分层。

## 数据源(四件,各答一个问题)

| 文件                                                 | 粒度                                        | 关键字段                                                                                                                                                                                                                                       |
| ---------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `~/.zcode/cli/log/zcode-YYYY-MM-DD.jsonl`            | 事件流(会话全历史,跨压缩)                   | `turn.started/completed`(turnId,**同轮触发 3 条须按 turnId 去重**)、`model.request.completed` 的 `durationMs` + `context.querySource`(main_turn/subagent 分流)、`tool.call.completed` 的 `durationMs` + `context.toolName`;按 `sessionId` 过滤 |

## 方法要点

1. **口径先行**:只计「轮内时间」(turn.started→completed),用户离席(轮与轮之间的大 gap)剔除——那是节奏问题不是耗时问题。
2. **归因三分**:轮内 = 子代理墙钟 + 主线模型时间 + 等待(gap 里对得上 e2e/build 的)。主线模型时间从 rollout `durationMs` 求和;等待从长 Bash(`tool.call.completed` 且 `toolName=Bash`、`durationMs≥60s`)逐条认领。
3. **并行要遮盖算**:T2∥T3 时 wall 只算 max(T2,T3);并行省下的 = 被遮盖代理的墙钟。
4. **排行榜按 wall 占比排**,每个大户追问一层「它的内部时间去哪了」(代理墙钟 175min 里模型仅 65min,56% 是内部 bash——build/e2e/截图)——对策才打得准。
5. **master 对照实验**:怀疑 diff 引入的 flake,在 master 跑一次同负载全量定性(一次 6min,买断「是不是我搞坏的」的全部争论)。

## 一期结论(存档)

三天轮内 10.55h;实现轮 229.9min = 子代理墙钟 79% + 主线等 e2e 19% + 主线模型 8%(有遮盖)。大户:T4 代理 74min / T3 代理 62.6min / 全量 e2e×7 ≈ 44min。对策五条(分层验证/flake 还债/验证限额/诊断权归主线/并行拓扑复用),落地见 [派单模板](./派单模板.md)(四条纪律)与[开发与测试](../how-to/开发与测试.md)(e2e 分层)。
