## 待拍板建议

1. **主线收敛（新提案）**：常规整合、等待、发布降低推理档位；疑难诊断和评审保留高强度。主线验收与派工，不重复推演实现者的细节。降档收益需要复测。
2. **统一发布（扩展既有 release.ts）**：接入本次已验证的 Windows 驱动、进程 PATH、按提交校验、签名与资产核对；保留独立构建缓存，最终只构建合并代码。不另造平行发布框架。
3. **缩短接棒（执行既有派单纪律）**：固定提交、路径验收后启动下一就绪票，文案和台账并行；修复提交返回即发定向复核。首棒定型最终接口，减少过渡接口重写。
4. **前移状态闭环（执行既有TDD/协议约束）**：首个tracer复用真实命令→JSON事件批→副本对账，观察现金、债务和下一相位；变更相位先盘点旧调用与断言。保留已补回归，不新增整局大矩阵。
5. **实施边界压缩（执行现有上下文纪律）**：票面定稿后只保留基线、契约、归属、回执和未决项；读取使用已有有界入口。先减主线生成和历史负担，不再向AGENTS堆同义规则。

建议收益互有重叠，不逐项相加。保持当前代理速度和质量门槛，下轮同规模先以80—90分钟为验证目标，不当作已证实的提速。现有validate/pr-merge强闸确实挡住旧断言，当前不优先再建CI大矩阵或继续削减测试。
