# Dogfood 走查报告(2026-09-28)

基准:b079e06(#285),Windows 侧 serve 127.0.0.1:4180(手工起,bun scripts/server.ts),视口 932×430(Android 横屏目标)。

## Issue 列表

### ISSUE-001 环境·高:3000 端口被 WSL relay 占用,旧世界 dist 仍在服务

- 现象:`http://localhost:3000/maps/index.json` 返回旧清单(无环游图,首项=棋盘天下);仓库 dist 已是新物。
- 取证:`netstat -ano` 显示 3000 监听者 PID 13532 = `wslrelay.exe`(WSL 端口转发),真 serve 在 WSL 内,Windows 侧 build 对它不可见。
- 影响:用户「F5 快照线」实际玩的是 WSL 里的旧版本,与「3000=最新快照」心智冲突;浏览器无任何提示(版本角标 v2026.09.28.xxxx 只在页面底部小字)。
- 复现:Windows 侧 `bun run build` 后 curl 3000/maps/index.json 仍旧。
- 备注:dogfood 换用 4180(Windows 侧)继续;3000 归属待用户决定(杀 WSL 服务 or 迁端口)。

### ISSUE-002 体验·中:首页 932×430 需滚动才能见全四入口

- 现象:横屏首屏只露「单机模式」一张卡,联机/选择地图/编辑地图三卡在折叠线以下(截图 01-home.png 右缘滚动条可见)。
- 影响:Android 横屏首启多一次滚动;四入口不齐一眼。
- 待复验:是否本就设计为滚动长页(若设计如此,降级/关闭)。

### ISSUE-003 体验·低:单机设置屏「当前地图:棋盘天下」与首页「环游图」不一致

- 现象:首页按钮显示「当前地图: 环游图」;点「单机模式」进设置屏后显示「当前地图: 棋盘天下」(快照 2026-09-28)。
- 疑点:两屏读的地图单源不同步(设置屏可能读了自己的旧偏好 localStorage 键,首页读 index.json 首项)——以哪边为准需对表代码,黑盒先记录。
- 复现:首页 → 单机模式,对比两屏地图名。

### ISSUE-004 疑似·中:单机设置屏 DOM 里找不到「起兵」按钮(start-game)

- 现象:快照(AI 树)能看到「起兵」按钮文本,但页面 DOM `querySelector('[data-testid="start-game"]')` = null;testid 定位 3s 超时。
- 疑点:可能按钮在 shadow DOM/portal(快照可穿透)或条件渲染分支未挂;玩家视角按钮可见(快照在),但自动化与读屏 DOM 口径不一致。
- 复现:设置屏 → 页面控制台 `document.querySelector('[data-testid="start-game"]')`。

### ISSUE-005 功能·高(阻断):设置屏渲染与路由脱钩——「单机模式」点进去画面不动

- 现象:首页点「单机模式」→ body[data-screen] 变 "setup",但 DOM/画面仍是 home-screen(5 张首页卡);「起兵」永远点不到。reload 后仍复现(data-screen=setup + home-screen 挂载)。开局流程被完全阻断。
- 取证:02-setup-broken.png(画面=首页)+ 两次独立 evaluate 采样(screen=setup,tid=home-screen,startBtn=false)。
- 对照:首轮进入时快照曾显示完整设置项(AI 树),说明设置屏组件曾有渲染能力;坏帧发生于换屏时机,疑 React 换屏渲染中断或 screen 状态双源错位。
- 复现:首页 → 单机模式 → 观察 URL 下方画面不变;刷新亦不恢复(路由态保留 setup)。
- 附:此前 ISSUE-003「设置屏显示棋盘天下」其实是快照缓存残影,真实矛盾以本条为准(合并观察)。

### ISSUE-005 修订(触发条件收窄)

- 全新加载 http://127.0.0.1:4180/ (无 query) → 点单机模式 = 完全正常(screen=solo-setup,startBtn=true)。
- 带 `?seed=777` 首载 → 首页点单机模式 = 渲染脱钩(ISSUE-005 原文)。
- 触发条件锁定:**首页带 ?seed= query 直载**。疑似 seed 被当作「跳过设置直接开局」的旧入口语义残留,与现路由冲突。

### ISSUE-006 体验·高:选都三选一无可点候选(玩家视角「死横幅」)

- 现象:横幅「「魏」三选一:于候选城中择一定都」常驻,棋盘上无高亮可选城(03/04 截图同态);`.bv-tile.bv-selectable` 计数=0,确认钮不存在。等待多秒无变化,对局推进停滞。
- 玩家影响:不知道点哪/能不能点,只能干等或乱点棋盘。
- 对照:e2e 有「选都候选金圈呼吸」用例且 CI(旧)长期绿——怀疑横幅该带候选高亮而实际未渲染,或需要先点横幅展开。黑盒记为候选高亮缺失/不可发现。
- 复现:开局(默认图 4 诸侯)→ 选都横幅出现 → 观察棋盘无交互提示,点击无效。

### ISSUE-006 撤回(误报修正)

- 复检 `.bv-tile.bv-selectable`=3(三候选金圈在)。先前 count=0 系采样时机早于玩家选都窗开启。非产品问题,撤回;选都交互正常(点击候选→确认钮出现→定都)。

### ISSUE-007 功能·高:对局中途整屏跳回首页(渲染与路由再次脱钩)

- 时序:正常开局 → 选都定都 → 军师幕点「不出」→ bot 衮之回合开始 → 约 30s 观察窗内 → 画面静默回到首页视觉(data-screen="setup" + tid=home-screen,URL 仍是 /),无任何用户操作。
- 取证:06-stall.png(首页画面)+ 采样(screen=setup/tid=home-screen/url=4180)。
- 与 ISSUE-005 同根:路由态(screen 值)与渲染内容脱钩,这次发生在对局中段自动跳变——比 005 更严重(玩着玩着回首页)。
- 疑点:两个 issue 共同指向「screen 状态机与实际渲染不同步」:一种可能=react 外部路由 store 写了 screen 但组件树 memo/error boundary 吞了重渲;控制台 0 错误(观察窗内 errs=[])。
- 复现:开局 → 定都 → 出军师幕点不出 → 等待 bot 回合 → 画面回首页(约 30s 窗口内)。

### ISSUE-008 功能·高:对局中刷新落在坏帧(与 005/007 同根三现)

- 时序:开局进对局屏(screen=game,dash 在)→ F5 → 落在 screen="setup" + tid="home-screen" 坏帧(既非首页正常态也非设置屏)。
- 结论:005/007/008 三现同根——**screen 路由状态与渲染内容脱钩**,触发点含「带 seed 首载」「对局中自动跳变」「对局中刷新」。恢复手段=再点一次入口按钮(临时绕过)。
- 严重度:高(玩家丢局+卡死);但绕过简单。

### ISSUE-009 视觉·中:编辑器画布重影错位

- 现象:编辑器打开即见地图画布「双层」——左上半区正常渲染,中下方叠着一层半透明错位地图(07-editor.png 清晰可见双重格线)。
- 玩家影响:编辑时拖池/点城会看得眼花,不知哪层是真的;疑似 SVG 画布与预览层叠放错位或缩放不同步。
- 复现:首页 → 编辑地图,打开即见。
- 附:editorUi 探测(class*=editor)=false,编辑器根容器无 editor class(可访问性小疵,不另立)。

### 编辑器走查小结(无新 issue)

### ISSUE-010 文案·中:联机大厅选图面板遮挡后「确认选择」未点时开局钮仍可点但无效果

- 现象:host 点「选择地图」→ 面板列出 4 图;点「环游图」卡片 → 面板仍在(需再点「确认选择」——黑盒合理);但第一次点「开局」时面板开着,开局无响应也无提示(采到 screen 仍 lobby)。玩家可能误以为开局坏了。
- 佐证:选图面板打开态下开局钮仍可点击(r3=true 而面板未关),点击后无 toast 指引「请先确认地图选择」。

### ISSUE-011 文案·中:联机席位「离线/东魏」占位表述不可读

- 现象:guest 入座前大厅席位显示「离线魏诸侯 2人·离线 开局将改为『东魏』诸侯 3虚」——「虚」「人·离线」「开局将改为『东魏』」三种表述混排,不玩过的人读不懂哪句是结论(截图未及,大厅文本采样为证)。

- 影响:大厅信息可读性;不阻断。

### ISSUE-012 功能·高:联机 guest 刷新后回不了对局(落坏帧,且无重连路径)

- 时序:联机对局中 guest 页 reload → 落在 screen="setup" + 首页按钮组(与 ISSUE-005/007/008 同款坏帧);页面无「重新加入/返回房间」任何入口;房间码也未自动携带(guest 需记住 RRMH 手动重进)。
- 玩家影响:断线=丢座位视野;重连成本高(首页→联机→输码),且刷新直接撞坏帧。
- 对照:ADR-0002 断线冻结+重连夺回语义在传输层存在(e2e 有),但产品入口被 005 坏帧挡死。
- 本质:005 家族第四现,联机场景下代价最大。

### ISSUE-005 复现实验记录(2026-09-28 修复会话)

- 实验 A:?seed 直载→点单机 = **正常**(solo-setup 真挂载)——与 dogfood 首轮矛盾;
- 实验 B:开局后挂 35s = 不坏;
- 实验 C:点不出后观察到 60s = 画面在 game 屏,但顶栏冻结在「牌库 0 弃牌 0」第 1 轮魏之回合,15s 不动(对照组开局后顶栏是「牌库 14」)。
- 新线索:**冻结局的开局路径 = 我在 setup 坏帧页签上 evaluate 点的 start-game**(坏帧下 React 树是旧的,start.click 触发的 handleStart 挂在了被卸载/失联的树上);顶栏「牌库 0」+ 引擎不推进 = **引擎在跑(或没跑)而 UI 订阅断开**。
- 收敛假设:坏帧的本质不是「screen 双源」,而是 **React 渲染树与 zustand store 失联**(订阅断开):store.screen 已更新(所以 data-screen 变),但组件树不重渲——两次坏帧都是「同页签内经历过多屏切换」后发生。候选根因:screen-transition keyed 外壳 + Suspense/异常边界吞了重渲,或 zustand 选择器返回 NaN 引用抖动。待代码层排查 React 版本已知 bug 与 App.tsx 的 content===null 分支(content null 时 return null 会卸掉整树,若 store 瞬态 null 则 DOM 全灭——与「tid=home-screen 但 screen=setup」矛盾,排除)。

### ISSUE-005 二次修订(修复会话实验终局,2026-09-28 深夜)

决定性证据链(冻结局解剖):

- 坏帧时序重放:开局后引擎在 Setup 逐座位 bot 选都,**bot 步间 delay 累计可达 40s+**(4 诸侯×3 bot);期间画面只有淡淡的候选金圈(.bv-candidate),无横幅、无指引、顶栏仍写「魏之回合+牌库 0」(误导:像对局已开始)。
- selectable 轮到玩家前 `.bv-selectable`=0,轮到后=3;点击定都后一切恢复(牌库 14、手牌 1)。
- **结论:005/007/008/012 的「脱钩坏帧」取证误判**——data-screen 与 DOM 的采样矛盾源于 IAB 快照缓存残影(dogfood 工具层假象),真实产品问题只有两个:
  - **A(体验·高)Setup 期无指引**:bot 选都的长等待窗内,画面无「等待各诸侯定都」横幅,顶栏「魏之回合+牌库 0」是错误语义(对局未开始);玩家面对三枚淡金圈不知何物、不知是否轮到自己。ISSUE-006 首查「死横幅」其实碰到的是同一件事的另一半(横幅文案错误而非候选缺失)。
  - **B(体感·中)bot 步 delay 累计过长**:3 bot 选都可等 40s+ 无任何进度感(无第 2/3 位定都提示)。
- ISSUE-007(对局中跳回首页)与 ISSUE-008(刷新落坏帧)在修复会话的受控复现中**均未复现**(35s/60s 观察、reload 后重开均正常);ISSUE-012(guest 刷新丢局)的「坏帧」部分同判,但「无重连入口」仍是真的(ADR-0002 语义在传输层,产品入口缺失)——保留降级重开。

### ISSUE-005 终局结论(第三次修订,以最后一次受控观察为准)

- 前两次「坏帧/脱钩」判断作废:后续受控复现(A/B/C 实验)中 ?seed 首载、35s 挂机、60s 观察、对局中 reload 全部正常;dogfood 首轮的「screen 与 DOM 矛盾」为 IAB domSnapshot 缓存残影(工具假象)。
- **最终确认的真实缺陷只有一个:选都等待体验**——
  - bot 逐座位选都,步间 delay 叠加(3 bot 40s+),期间棋盘只有三枚低透明金圈(.bv-candidate),无「谁在定都/等待多久」的进度信息;顶栏此间显示「X之回合 + 牌库 0」(Playing 化的误导文案;选都属 Setup,活跃方语义未分化)。
  - 玩家侧唯一可行动信号是金圈升格脉冲(.bv-selectable),不够醒目;dogfood 首轮与修复会话首查都把它看漏 ⇒ 可发现性不及格。
  - 定都后一切正常(牌库 14、回合推进、军师幕出牌、浮字、防连点)。
- ISSUE-006 撤回理由维持(候选存在,可点);ISSUE-007/008 未复现,关闭(不计 issue);ISSUE-012 的坏帧部分同判关闭,**「刷新后无重连入口」保留为独立真实问题**。
- 修复面收敛为:①Setup 期顶栏/横幅语义(「等待各诸侯定都」进度文案+轮到你时强提示);②bot 选都步进提速或加进度;③联机刷新重连入口。
