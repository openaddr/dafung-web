# 记录问题(record-issue)

当用户报告一个问题,且意图是**留到以后再改**(不是现在改),就把这条问题追加到项目根目录的 `TODO.md`。

## 如何区分"记录"与"修复"

用户想**记录**(本 skill)——消息像一个待办条目:他在留意某个现象,但没要求行动。信号:

- 说了"记录" / "记一下" / "先记下来" / "以后再改" / "待会儿改" / "先放着"
- 描述了一个问题,但没有提问、没有"为什么"、没有要求修复
- 明确提到 TODO 文件("todo 里加一条")

用户想**修复**(不是本 skill)——

- 问"为什么" / "怎么会" / "帮我看看" / "排查一下"
- 说了"改" / "修" / "fix" / "处理" / "解决"
- 想讨论原因或修复方案

拿不准时,简短问一句:"记下来,还是现在改?"——一个问题就能定。

## 要做什么

1. 读项目根目录的 `TODO.md`。
2. 在 `## 已知问题` 节下追加一行,格式:
   ```
   - [ ] **简短标题**:描述——在哪、什么现象、(可选)之前应该怎样。加日期前缀更清晰。
   ```
3. 标题保持简短(几个字),细节放在冒号后。
4. **描述尽量沿用用户原话、保留原意**:只做最小必要的通顺化——改明显的错别字/语音转写错误、删口播废话,让语句通顺即可。不要重写、不要润色扩写、不要替用户补因果结论(如擅自加"疑似""导致……")。语义以用户原话为准。
5. 不要修复、不要排查、不要翻代码。只记录。
6. 一句话确认记了什么(把标题复述回来),不要多说。
