# 耗时回顾(time-review)

方法、数据源与口径的完整说明在 [`docs/agents/耗时回顾.md`](../../docs/agents/耗时回顾.md)——先读它再动手,那里有四类数据文件的路径与字段、归因三分法(子代理墙钟/主线模型/等待)、并行遮盖算法和 master 对照实验范式。本页只写流程骨架。

## 流程

1. **定窗**:按 git 提交时刻 + `git log --date=format-local` 或轮次时间线,圈出要回顾的时间窗;剔除轮间离席(那是日历不是工时)。
2. **取数**:按方法论文档的四表取数——CLI 日志(turn/model/tool 事件,sessionId 过滤,turnId 去重)、rollout(主线程模型调用流)、`~/.zcode/cli/agents/<sessId>/agent_*/metadata.json`(子代理墙钟/tokens)、git log。
3. **归因排行**:轮内 = 子代理墙钟(并行算遮盖)+ 主线模型时间 + 长等待(≥60s Bash 逐条认领:e2e/build/截图)。按可见墙钟占比排大户,每个大户追问一层内部结构(模型 vs bash vs 等待)。
4. **对照基线账**:方法论文档末尾有基线账表——本次数据入一行,与上一行对比:对策有没有兑现(如 e2e 等待是否从 46min 降到个位数)?
5. **对策**:只提数据支撑的对策;标注哪些已有条款覆盖(AGENTS.md 派单纪律/分层验证)、哪些需要新条款。**分析完停手,落地等用户拍板**——除非用户明说"修"。

## 口径红线

- 只计轮内时间,离席剔除但单独报(影响日历感知)。
- 主线程模型时间以 rollout `durationMs` 求和为准;CLI 日志的 turn.durationMs 只做交叉印证(计数口径不同会差几个点)。
- 子代理内部时间必须拆(模型/bash/等待)——「代理慢」大多数时候是「代理在反复跑验证」,对策完全不同。
