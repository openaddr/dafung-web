# 耗时分析

以用户指定任务或当前会话为范围。先用提交与会话记录确定起止；无法唯一确定时再询问。轮间超过 10 分钟的离席单列，不计入轮内耗时。

## 证据

- **Codex**：先确定会话 ID，在宿主的 `.codex/sessions/` 定位该会话和子代理 rollout JSONL；Windows 桌面经 WSL 运行时查 Windows 用户目录，而非 WSL 的家目录。按 `task_started`/`task_complete` 定窗，按 `root_turn_id` 关联代理。`token_usage_record` 按 `response_id` 去重后汇总 `usage`，区分缓存输入和输出；推理 token 已包含在输出中。
- **ZCode**：使用 `~/.zcode/cli/log/` 的轮次、工具和模型事件，`rollout/` 的主线调用与 `agents/` 的代理 metadata。rollout 压缩后可能只覆盖最近一段。
- **Git 与回执**：用提交时间、验证日志和发布报告交叉核对阶段与命令结果。

只读取目标会话，先在工具内聚合字段再输出摘要；不要把整轮历史或图片编码作为文本返回。累计输入包含重复的缓存上下文，不等同独立上下文或账单。缺少请求级计时就标明未知，不推算模型耗时。

## 归因与交付

按时间窗列出关键阶段及可见等待；代理并行时间取区间并集，另报被覆盖的累计时间，不把等待代理等同浪费。对每项可优化行为给出次数、耗时或 token 证据，区分真实缺陷修复、用户追加范围与可避免的重复；收益无法从记录确定时说明不确定。

按收益与成本排序提出具体方案，优先执行 [派单模板](../../../docs/agents/派单模板.md) 和 [开发与测试](../../../docs/how-to/开发与测试.md) 已有纪律。用户明确要求留档时，按 [耗时回顾](../../../docs/agents/耗时回顾.md) 规约覆写当前态；方案另经用户决定后实施。
