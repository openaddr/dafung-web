# 死代码体检(dependency-audit)

低频体检,不是日常门禁。台账基线在 `docs/reference/死代码台账.md`(2026-09-26 首跑:导出 33 + 类型 34,文件/依赖 0),本 skill 的职责是**守基线、清已知**,不是追零。

## 何时执行(刻意低频)

1. 用户明说:"查死代码" / "knip" / "依赖体检"
2. 大重构合入后(引擎拆分、屏幕骨架改版)——验证旧接口没留尸体
3. 发版打 tag 前
4. 台账最新一条距今 ≥1 个月,且期间有较大改动 → 可向用户提议跑一次

不在以上情形时不要跑。

## 怎么做

1. `bunx knip`(配置单源 `knip.json`:入口 = index.html + 5 个手工脚本;忽略 = public 静态资源与 shadcn ui/ 底件)。
2. 与台账上一条对照,只看三类:
   - **新增的未用导出/类型**:哪个改动留下的?在途工单的预留面(#234 等)还是尸体?
   - **上次的已删项划账**;没删的问一句还等什么。
   - **死文件/死依赖**:任何新增都是高优先级信号(依赖尤其——多余安装面)。
3. 登记 `docs/reference/死代码台账.md`:新起一节,写日期、基线对照、分类与处置建议(分类口径照首跑那节)。
4. 向用户报告值得行动的发现;真删除走独立小工单,不混进其他票。

## 判读口径

- `src/app/components/ui/**` 的导出**永远忽略**:shadcn CLI 管理的底件,导出即 API 面,清理制造上游 diff 噪声。
- 组件 Props/interface 的未用导出价值低,随桶文件顺手处理,不单独立票。
- `src/core/` 是重点:core 导出收缩不改行为,但逐个确认非在途工单预留面,删除后过 `bun run check:core` + 全量单测。
- scripts/ 共享层(engine-helpers/room/room-persistence)的导出是 CLI/服务器候补接口,倾向真死,顺手工单删。

## 红线

- 不设阈值、不进 CI、不为清零而清零——桶文件动不到就不动
- 只记录与分类;删除走独立工单(用户拍板),不混票
