# 资源消耗复盘

以用户指定范围或当前任务为范围，按问题取证：只查需要的时间、token 或工具数据；仅在相关子代理纳入范围时读取其记录。提交、验证日志和发布报告仅在定位或交叉核对需要时查阅。

## 证据与口径

- **Codex**：按会话 ID 定位宿主 `.codex/sessions/` 中的目标 JSONL；Windows 桌面经 WSL 时查 Windows 用户目录。用 `task_started`/`task_complete` 定窗，按 `root_turn_id` 关联相关代理；`token_usage_record` 的 `usage` 按 `response_id` 去重，区分缓存输入与输出，推理 token 已含在输出中。
- **ZCode**：按需读取 `~/.zcode/cli/log/` 的轮次、工具和模型事件，以及 `rollout/` 与 `agents/`；rollout 压缩后可能只覆盖最近一段。

流式聚合目标记录，尽量每文件一次，只返回所需数值、路径与简短摘要；异常再定向补读。同一任务若还做其他复盘，复用已有证据，仅为新增问题补查。不要输出完整历史、逐条记录或图片编码。标明数据来源、范围和缺失；缺少 ID、记录截断或无法去重时明确说明，不把不完整数据当全量。累计输入含重复的缓存上下文，不等同独立上下文或账单；缺计价数据不估算金额，缺请求级计时不推算模型耗时。

进行中的回合统计到采样时刻并标记未完成；无法判断状态或记录缺失时标未知。轮间间隔与轮内耗时分开，不据间隔推断用户离席。代理并行时间取区间并集，另报被覆盖的累计时间，不把等待代理等同浪费。

## 交付

默认报告所需总量和最多三个最值得处理的问题，每项给次数、耗时或 token 证据及具体建议；用户要求详细或证据需要时展开。区分真实缺陷修复、用户追加范围与可避免的重复，收益不能确定时说明不确定。

用户询问本次分析自身成本时，单列可测的分析轮次 token、工具耗时与输出大小；进行中的轮次只能报告采样前的数据，完整结果须在轮次结束后核对。输出字节数不等同 token。

按收益与成本排序提出方案，优先采用 [派单模板](../../../docs/agents/派单模板.md) 和 [开发与测试](../../../docs/how-to/开发与测试.md) 的已有纪律；用户明确要求留档时按 [耗时回顾](../../../docs/agents/耗时回顾.md) 规约覆写当前态。用户要求分析时只报告，不自动实施方案。
